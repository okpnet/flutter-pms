# 生産管理アプリ 画面デザイン仕様（pms_design.md）

`tools/open-design` の Web プロトタイプ（HTML/CSS/JS）が実装している、画面の項目と振る舞いの現状をまとめたもの。配色・余白などのトークンは `design/theme.md`、Flutter 側は `flutter/app_theme.dart` が正本。
項目名は GraphQL の View 定義（`packages/model_providers/*_model/gql/`）と DB の列コメント（`tools/docker/postgresql/scripts/06_cteate_test.sql`）に合わせている。サンプルの値は実在しない架空のもの。

---

## 1. 全体構成

### 1.1 画面の入口（3 種類の端末）

| ファイル | 端末 | 構成 |
|---|---|---|
| `index.html` | PC | 左サイドバー（幅 248px）+ アプリバー + 本文。幅 820px 以下ではサイドバーがドロワーに変わる |
| `tablet.html` | タブレット | アイコンだけの細いサイドバー（幅 96px）+ アプリバー + 本文 |
| `mobile.html` | スマートフォン | 端末の枠の中に表示。上部アプリバー + 画面タイトル + 本文 + 下部ナビ（2 項目） |

3 つとも同じ `app.js` / `styles.css` / `data.js` を読み込む（`data.extra.js`、`domains.base.js`、`schema.gen.js`、`domains.js` も同様）。`body[data-device]` で端末ごとの表示を切り替える。幅 480px 未満では端末の枠が消え、画面いっぱいに表示する。

### 1.2 アプリバー（画面上部）

- 左から、メニューボタン（ドロワーを開く。PC の広い画面では非表示）、アプリ名「生産管理」、**ユーザーメニュー**。
- アクセント色の背景に白文字。PC・タブレットでは上部に固定する。
- **ユーザーメニュー**: 顔写真 + 名前 + 開閉の矢印のボタン。押すと「設定」「ログアウト」のドロップダウンが開く。
  - 外側のクリック、項目の選択、Esc で閉じる。Esc で閉じたときはボタンにフォーカスを戻す。開いたら先頭の項目にフォーカスする。
  - モバイルでは名前を隠し、写真と矢印だけを表示する。

### 1.3 ナビゲーション

- 並び順: **ダッシュボード → 資源（力量・資格・場所・設備・保全）→ 業務グループ（システム/品目/工程/営業/購買/生産計画/作業実績/品質共通/品質管理文書/品質管理）→ 会社情報**。
- 「設定」「ログアウト」はユーザーメニューへ移した（サイドバーには出さない）。
- 「顧客」「受注」「生産」のトップメニューは廃止した（画面は URL `#/customers` では開けるが、どのメニューからも到達できない）。
- グループは開閉する。表示中の画面があるグループは自動で開く。タブレットのアイコンバーではグループを押すとフライアウトが開く。
- サイドバー/ドロワーの最上部に、顔写真 + 名前 + 所属のユーザーカードを置く。タブレットでは写真だけ。
- 左上のロゴは、会社のシステムを表す六角形の紋章に社屋を重ねたアイコン（`emblem`）。
- **モバイル下部ナビ**: 「ダッシュボード」「その他」の 2 項目（最大 5 項目の規則の範囲）。「その他」には業務メニュー・資源・会社情報・設定・ログアウトを並べる。

### 1.4 画面遷移（ハッシュルーティング）

`#/<画面>` 形式。主なルート:

| 種別 | ルート |
|---|---|
| ダッシュボード | `#/home`、`#/orders`（出荷）、`#/production`（生産計画） |
| 会社 | `#/company`、`#/company/edit`、`#/company/provision/<id|new>`、`#/company/position/<id|new>`、`#/company/position/<pid>/assign/<id|new>` |
| 事業所・部署 | `#/sites`、`#/sites/edit`、`#/sites/<id|new>`、`#/departments`、`#/departments/edit`、`#/departments/<id|new>`、`#/departments/<id>/kind`、`#/departments/<id>/kind/<kid|new>` |
| 職員・承認 | `#/staff`、`#/staff/edit`、`#/staff/<id|new>`、`#/staff/<id>/capability/<cid|new>`、`#/staff/<id>/license/<lid|new>`、`#/approval`、`#/approval/edit`、`#/approval/<pid|new>`、`#/approval/<pid>/scope/<sid|new>` ほか |
| 資源 | `#/resources`、`#/capabilities`、`#/licenses`、`#/locations`、`#/equipment`、`#/maintenance`（いずれも `/edit` と項目の編集ルートあり） |
| 業務グループ | `#/g/<画面>/<タブ>`（閲覧）、`#/g/<画面>/<タブ>/edit`（一覧の編集）、`#/g/e/<実体>/<id|new>`（1 件の編集） |
| 共通 | `#/menu`（業務メニュー）、`#/settings`、`#/logout`、`#/login`、`#/boot`、`#/error` |

起動直後は `#/boot`（起動中）→ `#/login`。ログイン成功で `#/home`。ログアウトは確認 → 完了（5 秒のカウントダウン後にログイン画面へ）。

### 1.5 画面の基本構造（モード）

- **閲覧モード**と**編集モード**を分ける。閲覧画面の見出し右の「編集」リンクで編集モード（`…/edit`）に入る。
- 編集モードの一覧は、行を選ぶと 1 件の編集画面（フォーム）へ移る。「〇〇を追加」ボタンで新規作成画面（`new`）へ。
- 画面上部に「戻る」ボタンを置く（遷移元に戻る。閲覧に戻る/一覧に戻る/メニューに戻る など行き先を文言で示す）。
- 保存・追加・削除のあとは、一覧に戻って**完了メッセージ**（`role="status"`）を 1 回表示する。

## 2. ダッシュボード（`#/home`）

上から順に、次を表示する。

1. **ログインユーザーのカード**: 顔写真（72px）+「ログイン中」+ 名前 + 所属・基準日。
2. **遅延アラート**: 遅延ラインがあるときだけ表示（`role="alert"`、枠と文言で色以外にも示す）。対象ラインと「生産計画・進捗で確認する」リンク。
3. **KPI 4 枚**: 新規受注（件）、出荷準備中（件）、生産進捗の平均（%）、遅延ライン（本）。それぞれ該当画面へのリンク。
4. **受注の進み具合**: 受注・出荷準備・出荷済の件数を積み上げバーと凡例（件数付き）で表示。
5. **拠点別の生産進捗**: 拠点ごとのラインの平均進捗（%）を進捗バーで表示。
6. **出荷予定**（出荷準備中の受注を納期順）と **生産ラインの進捗**（先頭 4 本）の 2 列（モバイル・タブレットは 1 列）。

**タブ**: ダッシュボード上部に「概要」「出荷」「生産計画」を並べ、同じタブバーを 3 画面すべてに表示する（選択中は下線 + `aria-current="page"`）。
- 出荷（`#/orders`）: ステータス「受注」「出荷準備」「出荷済」で絞り込むフィルタチップ（件数付き）+ 一覧。
- 生産計画（`#/production`）: 拠点（全拠点/関東工場/関西工場）で絞り込み、平均進捗・注意・遅延の 3 つのサマリ + ライン一覧。

端末別: KPI は PC で 4 列、タブレット/モバイルで 2 列。

## 3. 共通の振る舞い

### 3.1 一覧テーブル

- 検索（部分一致）、フィルタチップ（該当する画面のみ）、並べ替え（列見出しのボタンでトグル、または「並べ替え」セレクト）、「表示する列」メニュー（更新者・更新日は初期非表示。名称の列は常に表示）。
- 件数表示: 「全 N 件のうち M 件を表示」。検索で絞ると「条件に合う N 件から M 件を表示」。
- **データの読込件数**: 設定の件数（標準 50）までを表示し、超える分は一覧の下の「さらに読み込む（残り N 件）」で追加する。検索語を変えると先頭に戻る。対象は共通の一覧表（業務グループ・承認・力量/資格・保全など）。職員・事業所・顧客の一覧は別実装のため対象外。
- 閲覧モードで子を持つ一覧は、名称を押して選ぶと下に子の一覧（詳細）を表示する（選択中は `aria-pressed`）。
- 空の一覧は「なぜ空か」と次の操作を示す（空状態）。
- モバイルでは表が縦積みになり、各セルが `data-label` の項目名つきで表示される。

### 3.2 ツリー（品目・工程・コンテナ・文書・文書コンテンツ・部署・場所）

- 親子をインデントで表し、開閉ボタン（`aria-expanded`）で展開する。初回の展開時は 350ms の「読み込み中…」を挟む。
- 編集モードでは、ハンドルのドラッグで親を付け替える。ドラッグできない環境向けに「親を変更」ボタン（選択シート）を用意する。最上位へ戻すドロップ領域もある。
- 自分自身と配下は親に選べない。配下のあるノード、使用中のノードは削除できない（理由を文で示す）。

### 3.3 編集フォーム

- すべての入力にラベルを常時表示。必須は「必須」バッジ。入力欄の下に項目ごとのエラーを出し、複数あるときは先頭に要約を置く（`role="alert"`）。
- 検証: 必須、最大文字数、重複（`taken`）、日付の前後（`after`/`min`）。確定（保存）時にまとめて検査し、フォーカスは最初のエラーへ移す。
- 更新者・更新日は読み取り専用の欄で表示する（編集不可）。
- 削除は確認シート（キャンセル/削除する）を経由する。元に戻せない旨を明記する。
- 入力途中で別画面（区分の選択など）へ行く場合は、下書きを保持して戻ったときに復元する（会社・部署・職員の新規作成）。

### 3.4 ID の扱い

画面に ID は表示しない。一覧・参照の表示は、**コード → 名称 → 読み**の順（参照欄の選択肢と代表表示は「コード 名称」）。

### 3.5 アクセシビリティ・レスポンシブ

- タップ領域 44×44px 以上、フォーカスリング常時、色だけに頼らない状態表示（アイコン/文言）、`prefers-reduced-motion` で動きを無効化。
- ブレークポイントは 375 / 768 / 1024 / 1440。モバイルは横スクロールなし。固定バーの分の余白を本文に確保する。
- ダークテーマはライトとは独立に配色している（`prefers-color-scheme` または設定で切り替え）。

## 4. 個別実装の画面（会社・組織・職員・承認・資源）

項目名は DB のコメントに合わせてある。`*` は必須。DB にない項目は「（アプリ独自）」と記す。

### 4.1 会社情報（`#/company`）

- 表示: 会社名、会社名の読み、略称、代表者名（役職つき）、ホームページ、本社所在地、備考。サマリ（従業員数の内訳バー、外部委託業者数、顧客数）、事業所のタイル、部署の構成、提供サービス・製品のタイル。
- 編集（`/edit`）: 会社名*、会社名の読み、略称、代表者名*、代表者の役職*（アプリ独自）、ホームページ、メインサイト（本社）所在地*、備考。その下に「提供の一覧」と「役職の一覧」。
- **提供**（`info_provision`）: 種別*（製品/サービス）、提供コード*、名称*、詳細*。
- **役割（役職）**（`info_position`）: 役割名称*、読み、順位*、備考。画面の下に「この役割を割り当てている人」の一覧と「担当を追加」。
- **割当**: 役割と担当者の組。同じ人を同じ役割に重複して割り当てられない。解除は確認シート。

### 4.2 事業所（`#/sites`）

- 一覧の列: 事業所コード、事業所名称（固定）、読み、種別、所在地、在籍人数、更新者、更新日。検索は コード/名称/読み/所在地。種別（本社/工場/物流/営業所）でフィルタ。
- 編集: 事業所コード*、事業所名称*、読み、種別*、所在地*。在籍人数は読み取り専用。**在籍が 1 名以上いる事業所は削除不可**。

### 4.3 部署（`#/departments`）

- ツリー表示。各行に組織コード、組織名称、部署区分のタグ、配下の件数。閲覧モード/編集モードあり。
- 編集: 組織コード*、組織名称*、読み、事業所、親部署（任意）、部署区分（タグ。「区分を選択・編集」で別画面へ）。配下に部署があると削除不可。
- **部署区分**: 一覧から複数選択（チェック）、区分名*（12 文字以内・重複不可）の追加/変更/削除。削除すると全部署から外れる。

### 4.4 職員（担当者）（`#/staff`）

- 一覧の列: 担当者コード、名前（固定）、読み、所属事業所、区分（社員/パート/派遣）、部署、力量（件数）、資格（件数）、更新者、更新日。検索は 名前/読み/コード。区分と所属事業所でフィルタ。
- 編集: 担当者コード*（新規のみ入力、以降は変更不可）、名前*、読み、性別、電話、緊急電話、所属事業所*、区分*、部署、備考。**役割に割り当てられている人は削除不可**。
- 下に「力量」と「資格」の一覧と追加ボタン。
  - 力量: 力量*、値（習熟度）*（見習い/一人で作業可/他者の指導可）。同じ力量は重複不可。
  - 資格: 資格*、適用開始*、適用終了（任意・開始以降）。同じ資格は重複不可。
- 新規作成中に力量/資格を追加する場合は下書きに保持し、保存時にまとめて登録する。

### 4.5 承認（`#/approval`）

- 3 階層: **承認パターン** → **承認の範囲**（段階・承認する役職・対象の組織・配下の部署を含むか）→ **承認できる人**（担当者・種別（承認者/代理承認者）・有効開始日・有効終了日）。
- パターン: パターン名称*、読み、備考。範囲の段階は 1〜9 で重複不可。
- 承認できる人の一覧には「役職の割当あり/なし」のチップを出す（承認する役職が割り当てられているか）。

### 4.6 資源

資源のトップ（`#/resources`）に 力量・資格・場所・設備・保全 へのリストを置く。

| 画面 | 一覧の列 / 編集項目 |
|---|---|
| 力量 | 力量コード、力量名称（固定）、読み、詳細、基準、最小、最大、刻み、保持者（名）。下に「保持している担当者」（名前・担当者コード・所属事業所・値（習熟度））。編集: コード*、名称*、読み、詳細、基準*、最大、最小、刻み、備考 |
| 資格 | 資格コード、資格名称（固定）、読み、詳細、公的、顧客、内部、保持者。下に保持者（名前・コード・適用開始・適用終了と有効状態）。編集: コード*、名称*、読み、詳細、公的/顧客/内部（はい/いいえ）、備考 |
| 場所 | ツリー。場所コード、場所名称、読み、種別（アプリ独自）、使用停止のチップ、設備数、配下の件数。編集: 場所コード*、管理コード、場所名称*、読み、種別*、親の場所、使用*、備考。配下か設備があると削除不可 |
| 設備 | 上: 設備分類の一覧（分類コード、分類名称、読み、適用開始、適用終了、備考、設備数）。下: 設備の一覧（設備コード、管理コード、表示コード、設備名（品目）、設備分類、場所、設置日、状態）。分類を選ぶと設備を絞り込む。設備編集の下に「設備点検の運用」と「点検実績」 |
| 保全 | タブ: 点検整備区分 / 点検整備項目台帳 / 設備点検整備運用台帳 / 点検予定（下表） |

**保全の階層**:

| テーブル | 主な項目 |
|---|---|
| 点検整備区分 | 区分コード*、区分名称*、読み、周期の目安（アプリ独自）、備考 |
| 点検整備項目 | 点検コード*、点検名称*、読み、点検区分*、標準起算日、標準間隔、外部点検整備、対象部位*（アプリ独自）、判定基準（アプリ独自） |
| 点検整備算式（項目の子） | 算式名*、式*、単位、基準値（算式名・単位・基準値はアプリ独自） |
| 設備点検整備運用 | 運用コード*、運用名称*、設備*、点検整備区分*、周期*（周期はアプリ独自） |
| 運用明細（運用の子） | 点検整備*、順*、起算日、間隔、担当の役職（アプリ独自）。同じ点検整備は 1 運用に 1 回だけ |
| 点検予定 | 管理コード*、予定名称*、点検整備運用*、予定月*、状態*（計画/実施中/完了。予定月・状態はアプリ独自） |
| 予定明細（予定の子） | 点検整備項目*、開始予定日*、終了予定日、担当者* |
| 点検実施（予定明細の子） | 実施日*、実施者*、結果*（合格/不合格/要再点検）、測定値・所見、備考。ファイル（子） |

使用中のものは削除できない（区分は項目/運用で、項目は運用明細/予定で、運用は予定で使用中のとき）。

## 5. 業務グループの画面（共通エンジンで生成）

`domains.base.js`（手書きの構成）に、YAML × SQL から生成した項目定義 `schema.gen.js` を重ねている（再生成は `node tools/gen-schema.js`）。画面の振る舞いは 3 章の共通部品（一覧テーブル・ツリー・編集フォーム）に従う。
`*` は必須、`[種類]` は 文字/複数行/数値/日付/選択/参照。参照は、参照先の「コード 名称」を選択肢に表示する。親子の関係にある子は、親を選ぶと下に表示し、編集画面でも同じ親の文脈で追加する。


### システム

#### 単位（#/g/unit）

- **単位台帳**（単位）: 単位名称*[文字]、読み[文字]、略称[文字]、詳細[複数行]、記号[文字]、備考[複数行]

### 品目

#### 品目区分（#/g/itemkind）

- **品目区分**（品目区分）: 品目コード[文字]、品目区分名称*[文字]、読み[文字]、略称[文字]、備考[複数行]

#### 品目（#/g/item）

- **品目体系**（品目・ツリー）: 品目コード*[文字]、識別コード[文字]、管理コード[文字]、表示コード[文字]、品目名称*[文字]、読み[文字]、略称[文字]、品目種類*[参照→品目区分]、詳細[複数行]、個別単位[参照→単位]、備考[複数行]
  - 子: HSコード: HSコード

## 6. 設定・認証

### 6.1 設定（`#/settings`）

サインインしている本人にだけ反映される設定。2 列のカード（モバイル/タブレット/狭い PC は 1 列）。

| セクション | 項目と振る舞い |
|---|---|
| 自分のイメージ | 現在の画像（72px）+ 名前・所属のプレビュー。ファイル選択（PNG・JPEG・GIF・WebP、2MB まで）。選ぶとアプリバー/ダッシュボード/サイドバーの顔写真がその場で変わる。画像以外・2MB 超・開けないファイルは、欄の下にエラー文を出して無視する。「初期のイメージに戻す」ボタン |
| データの読込件数 | 一覧に一度に読み込む件数。標準 **50**、範囲 10〜500（10 刻み）。範囲外は欄の下にエラーを出し、元の件数のまま。「標準（50 件）に戻す」ボタン。変更すると全一覧が先頭の件数から表示し直す |
| バージョン情報 | アプリケーション名とバージョン（ライブラリではなくアプリの版）、ビルド |
| テーマ | 実行環境に合わせる / ライト / ダーク（即時反映） |
| 使用言語 | ISO 3166 の言語コード。初期値は実行環境。画面文言は日本語のみ |
| 各画面の列 | 業務グループの画面ごとに、表示する列と標準の並べ替えを選ぶ。名称の列は常に表示 |

画像と読込件数はブラウザの `localStorage`（`od.photo` / `od.pageSize`）に保存し、保存できないときはそのセッションだけ有効。

### 6.2 認証画面

- 起動中: 1.5 秒後にログイン画面へ。
- ログイン: ユーザー名*・パスワード*。空は「入力してください」、誤りは「正しくありません」を `role="alert"` で表示。成功で 0.7 秒の送信中表示（ボタン無効 + 進行表示）→ ダッシュボード。プロトタイプのパスワードは `demo-password`。
- ログアウト: 確認（キャンセルでダッシュボードへ）→ 完了表示 → 5 秒のカウントダウン後にログイン画面。「ログイン画面へ」ですぐ移動できる。
- エラー: 原因と戻り先を示す画面。

### 6.3 メンテナンス中（`#/maintenance-mode`）

- **フラグがオンのあいだ**は、どのルートを開いても（サインイン前の起動中・ログインを含む）この画面だけを表示する。アプリバー・サイドバー・ナビは出さない。フラグは `data.extra.js` の `maintenance.enabled`、`localStorage` の `od.maintenance=1`、URL の `?maintenance=1` のいずれか。実運用ではサーバーのフラグに置き換える。
- フラグがオフのときは通常表示されないため、**確認用のメニュー**を用意した（サイドバー/ドロワーの最後の「メンテナンス中」、モバイルは「その他」の一覧）。この場合は通常の画面枠の中に表示し、「確認用の表示です」の注記を付ける。
- 内容: イメージ（`maintenance.svg`、4:3、幅 100%・最大 480px。歯車・レンチ・通行止めバリケード・注意標識。ダークテーマと reduced-motion に追従し、歯車はゆっくり回る）、見出し「ただいまメンテナンス中です」、メッセージ、作業の時間帯（開始〜終了予定）、ご利用いただけない範囲、再読み込みの案内、「再読み込みして確認」ボタン。
- モバイルでは画面幅いっぱいに縮小し、横スクロールしない。

### 6.4 バーコード（`#/barcode`・作業実績グループの先頭）

バーコードリーダー（キーボード入力として届き、末尾の Enter で確定）・スマートフォン・タブレットから symbol を読み込んで作業を進める画面。モバイルでも使えるよう、入力欄と選択ボタンは大きく（56〜64px）、1 列で表示する。

- **リーディングトップ**: 画面の最上部に「バーコードの読込」の入力欄（見出しはこれだけで、サブタイトルは出さない。常にフォーカス。Enter または「問い合わせ」ボタンで確定。モバイルでは入力欄とボタンがカードの幅いっぱいに縦に並ぶ）、その下に種類の選択（作業実績・受入検品・棚移動・設備点検）。種類を選ぶとその種類だけを受け付け、違う種類を読むとエラーを出す。選ばなければ symbol から自動判定する。登録のない symbol はエラー表示 + 履歴に残す。カメラ読み取りは、ブラウザが `BarcodeDetector` に対応しているときだけボタンを出す。
- **コマンド分岐**（symbol の種類）:

| symbol（例） | 種類 | 流れ |
|---|---|---|
| `WO-…` | 製造/委託品の作業指示 | 状態で分岐。未開始 → 開始の選択（はい → 棚出庫処理 → 作業開始 → トップ、いいえ → トップ）／開始中 → 数量入力 → 評価（合格 → 棚移動リーディング → 入庫処理 → トップ、不合格 → 不合格処理（理由）→ 棚移動リーディング → 入庫処理 → トップ）／指示数量完了 → トップ |
| `SH-…` | 棚 | 製品/購入品リーディング → 数量入力 → 入庫処理 → トップ |
| `PO-…` | 購入品 | 受入検品: 受入数量 → 評価 → 合格/不合格処理 → 棚移動リーディング → 入庫処理 → トップ |
| `EQ-…`（設備コード） | 設備 | 設備点検: 点検整備項目ごとに 合格/不合格/要再点検 を選んで記録 → トップ |

- 数量は 1 以上の整数。作業は指示数量の残り、受入は発注数量の残りまで。超えるとエラー。
- 入庫処理で作業指示の完了数・状態（開始中/完了）、購入品の受入済数を更新する。画面の右（モバイルは下）に「処理の履歴」を新しい順で残す（要確認は文言で示す）。
- 開始の選択で「いいえ」を選んだ場合の行き先は、仕様の図に行き先がないため、トップへ戻す扱いにしている。
- 状態はこの画面の中だけで更新する（プロトタイプ）。確認用に「試すためのバーコード」（サンプルの symbol）を折りたたみで置いている。

| `maintenance.svg` | メンテナンス中のイメージ（`node tools/gen-maintenance-svg.js` で生成） |
| `schema.gen.js` | YAML × SQL から生成した項目定義と行（`tools/gen-schema.js` で再生成） |
| `domains.js` | `domains.base.js` に `schema.gen.js` を重ねる |
| `schema.gen.log.md` / `schema.bespoke.log.md` | 置換した画面、不明な箇所、DB にない項目のログ |
| `tools/gen-bespoke.js` | 個別実装の画面について、YAML ページごとの DB 列を一覧にする |

- 生成の規則: ID 列・更新者・削除フラグ・件数ビュー・バーコード用の記号は表示しない。コード → 名称 → 読み → 略称 → その他の順に並べる。外部キーは、参照先の画面があれば参照欄にする。
- 画面側で `app.js` が扱う実体の識別子（`id`）は画面に出さない。

## 9. 未対応・既知の制限

- **DB にない項目**（アプリ独自のまま残している）: 会社の代表者の役職、事業所の種別・在籍人数、職員の所属事業所・区分、承認範囲の段階/役職/対象組織、点検整備の対象部位・判定基準・算式名・単位・基準値、設備の設置日・状態、場所の種別。詳細は `schema.bespoke.log.md`。
- 会社・事業所・部署の**住所**は `info_address` の複数列（住所1・住所2・建物・電話・FAX）だが、1 つの欄で扱っている。
- **割当**（`info_assign`）の有効・優先順位・事業所・部署は未対応。
- 力量の「値」は数値、停止の有無も DB にあるが、画面は 3 段階の習熟度のまま。資格の停止/取り消しも未対応。
- **読込件数の制限**は共通の一覧表のみ。職員・事業所・顧客の一覧は対象外。
- 読み（フリガナ）のサンプルは一部の名称のみ。未入力は「―」。
- 顧客・サプライヤーの担当者、取込用の子画面（`*imp` 系）は YAML との対応づけがなく、既存の項目のまま。
- 画像アップロードのサイズ検証は 2MB 固定。サーバー保存はなく、ブラウザ内の保存のみ。
- 実機（Flutter）の画面とは、このプロトタイプの項目・振る舞いを移植して合わせる。

## 購入品と品目仕入先（購買）

- **品目の「購入品」**: 品目の編集画面にチェックボックスを置く（`domains.js` で追加）。仕入先が登録されている品目は、チェックを外せない（理由を欄の下に表示）。
- **購買 › 品目仕入先**（`#/g/itemsupplier`）: 購入品にチェックの入った品目の表。各行の先頭の矢印で、その品目のサプライヤーの表（表の中の表）を開閉する。初期状態はすべて開く。
  - サプライヤーの表: サプライヤー、デリバリータイム（日）、最小発注ロット、単価（円）、言い値区分。言い値のときは、単価に「言い値（都度確認）」と表示する。
  - 編集モード（`…/main/edit`）: 各品目の「サプライヤーを追加」と、サプライヤーの行の編集。入力はサプライヤー（選択式。同じ品目に二重登録不可）、デリバリータイム（0以上）、最小発注ロット（0より大きい）、単価、言い値区分（トグル）。トグルをオンにすると単価は入力不要（無効）になり、オフのときは単価が必須。
- 項目名は DB の `mstr_item_supplier`（デリバリータイム・最小発注ロット・単価・言い値区分）に合わせた。
