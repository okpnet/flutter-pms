# trans_visiter_owner の @omit(create / update / delete)が付いていない

## 指示元
`flutter-pms/issue/202611.md`(元の 20261111_0002.md を統合) の 0-2(model_providers・features の先構築の前提確認)。実施: 2026-11-11、テスト環境の PostgreSQL `192.168.1.101`(DB `test_avocado`)を直接確認。

## 確認した結果
1. 0-1: 05〜15 が最後まで流れている。13 の関数(`visiter_owner_refresh`・`visiter_owner_rebuild`)、`visiter_move`・`mrp_run`・`mrp_execute` は存在する。
1. 0-3: `trans_visiter_owner` の権限は、`pms_user` が `SELECT` だけ、`pms_admin` が `REFERENCES, SELECT, TRIGGER`(書き込みなし)。13 の `REVOKE` は効いている。
1. 0-5: 新しいテーブル・ビューは DB に揃っている(`trans_plan_change`・`trans_supply*`・`trans_return*`・`trans_order_detail_settlement`・`trans_visiter_owner`・`trans_complaint_supply`・`mstr_change_reason`・`mstr_return_kind`・`mstr_settlement_kind`・`v_order_detail_balance`・`v_purchase_detail_balance`・`v_plan_change_unreflected`・`v_supply_detail_balance`・`v_external_property`)。
1. **0-2: 未対応**。`trans_visiter_owner` のコメントは `支給所有権` だけで、`@omit` が無い。PostGraphile は create / update / delete の mutation を生成する(権限が無いので呼べば権限エラーになるが、「書き込む操作がモデルに無い」の基準に反する)。

## 依頼(DB 側)
`13_visiter_owner.sql` に、次を足す(既存のコメントの文言は残す)。

```sql
COMMENT ON TABLE tests.trans_visiter_owner IS E'支給所有権\n@omit create,update,delete';
```

反映後、PostGraphile を再起動(またはスキーマの再読み込み)して、`createTransVisiterOwner` などが消えることを確認する。

## 反映までの扱い(アプリ側)
`trans_visiter_owner` のモデルは読み取りだけ(`kind: read`)にし、生成された mutation は使わない(YAML に書かない)。
