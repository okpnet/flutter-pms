## 2. マスタ・Info・trans: ミューテーションで行う(マスタごとの関数は作らない)
- **登録**: 呼称・文章・ラベルを持つ列は、共通関数で作り、返った ID を、本体の create の `names`(呼称)・`details`(文章)などの列に渡す。そのあと、本体を create(平らな列だけ)。
- **更新**: 本体の update(patch)は、渡した列だけが変わる(渡さない列は今のまま。null を渡すと消える)。呼称・文章の値を変えるときだけ、共通関数(`p_appellation_id` に本体の `names`)を呼ぶ。実サーバーで確認済み。
- **同じ値の更新**: 履歴のトリガーが「変更なし」で更新を握りつぶすため、応答の行が null になる(エラーではない)。画面は、更新後に読み直す。
- **削除**: `remove = true` の更新(論理削除)。使用中かの判定は、登録簿(`EntityCatalog`)が行う。
- **コードの重複**: 索引(0 の 3)が `23505`(`duplicate key value violates unique constraint "<表>_ix_code_active"`)で止める。クライアントは、索引の名前(`_ix_code_active`)で、検証エラー(`EntityFieldError.duplicate`)に変換する。
- **2 回の呼び出し**: 共通関数と本体は別のトランザクション。本体の登録が失敗すると、呼称・文章が、どの本体からも参照されない行(孤児)として残る。マスタ・Info は、同時に変更される可能性が低く影響が限定的なため許容する(あとから、参照されない呼称を一括で整理できる)。
- **体系(ツリー)**: 体系の表(`mstr_location_tree`・`info_department_tree`・`mstr_document_tree` など)への create・update(親の ID。null で最上位。トリガーが閉包 `hrchy_*` を更新する。確認済み)。循環(自分自身・子孫を親にする)は DB に検査が無く、できてしまう(確認済み)。クライアント(取得元の `reparentHandler`・保存)で検査する。
- **平らな定義**: 既存の `~PageEdit`(マスタ)は、呼称を入れ子で更新し、言語の値を全部入れ替える(`deleteOthers`)形で、新方針に合わない。新しく、スカラーの列と `names`・`details` の ID だけを持つ `kind: create` / `kind: edit` の定義を足す(`OrderPageEdit` と同じ形。名前の付け方は、生成器の規則を確認して決める)。

## 3. 取得元(取り込み)の手順(関数ごとではなく、実体ごと)
1.  `melos run gql:schema` → モデルの YAML に、共通関数の `kind: function`(`SharedAppellationSavePageCall` など。使う機能のモデルごとに。`JSON` のスカラー `fromJsonJson`・`toJsonJson` を `build.yaml` に足す)と、平らな `kind: create` / `kind: edit` の定義を足す → `melos run gql`。
1.  取得元の実体を書き込める定義にする(`viewOnly` を外す)。DB が採番する列(`symbol`)と、取得元がまだ GraphQL 版でない実体への参照は、読み取り専用にする。`save` は、(1)呼称・文章を共通関数で作る・変える(更新は、読み込んだ値から変わったときだけ)(2)本体を create・update(更新は、変わった列だけ)(3)読み直して返す。`remove` は `remove = true`。
1.  DB のエラーを、検証エラーに変換する(`23505` の索引名 `_ix_code_active` → `duplicate`、必須 → `required`)。体系の循環は、クライアントで検査する。
1.  通信テスト: 登録 → 名称だけ更新(ほかが残る)→ 空にした項目が消える → 必須・重複の検証エラー → 論理削除、を一般ユーザーで行い、後始末で論理削除する。
1.  取得元の印・feature の CLAUDE.md・`issue/202611.md` を更新する。

## 4. 現状の取り込み状況(2026-11-15)と、既知の制限
- 暫定: `system`(単位)・`shared_master`(利害関係者)の取得元は、適用済みの `unit_save`・`stakeholder_save`(取り下げる関数)で書き込んでいる(コミット前)。共通関数・索引・平らな定義が揃ったら、2・3 の方式に入れ替える。
- 詳細(文章)は、読み込みが先頭の文(`lead_text`)だけを返す。保存は、詳細が変わったときだけ送る(変えないと全文が先頭の文で上書きされる)。画面で全文を見て直せるようにするには、共有の部品(`FixTextReadFields`)に `text_value` を足す(全モデルの再生成が要る)。
