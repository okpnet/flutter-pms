# 20261103_0003 PostGraphile が JWT を検証していない(アプリの JWT が効かない)

`packages/model_providers/issue/20261103_0005.md` の「アプリの GraphQL 接続と JWT」の調査(`packages/model_providers/doc/log/20261103_0006.md`)の結果。

## 現状(2026-11-03、PostGraphile `http://192.168.1.100:5000/graphql`)
1. `tools/docker/postgraphile/docker-compose.yml` の起動オプションに `--jwt-secret` が無い。**不正な JWT を付けて問い合わせても 200 で通る**(検証していない)。つまり、アプリが `Authorization: Bearer <JWT>` を送っても無視され、`jwt.claims.*` は設定されない。
1. DB の関数(`07_visiter_functions.sql`・`08_mrp.sql`)は `jwt.claims.staff_id` を読むが、いまは常に空になる。担当者を引数で渡したときだけ動く。
1. PocketBase が発行する JWT の `role` は `app_user` / `app_admin`(`PB_GRAPHQL_JWT_DB_ROLE`・`_ADMIN_DB_ROLE`)。DB のスクリプトにこのロールは無い(あるのは `stores_user`・`stores_admin`・`tester`・`tester_admin`)。

## 必要な対応(案)
1. PostGraphile の起動オプションに `--jwt-secret`(PocketBase の `PB_GRAPHQL_JWT_SECRET` と同じ値)、`--jwt-verify-audience postgraphile` を足す。
1. `role` クレームを PostgreSQL のロールとして使う(PostGraphile は `SET LOCAL ROLE` する)ので、`app_user` / `app_admin` を作り、スキーマ・テーブル・関数の権限を与える。使わない場合は、`--default-role` を接続ユーザーにし、`role` クレームを使わない設定にする(PocketBase 側の `PB_GRAPHQL_JWT_DB_ROLE` を既存のロール名にする方法もある)。
1. JWT なしの問い合わせ(いまのテスト・開発)を許すか決める。許す場合は `--default-role` を設定する。
1. 確認: 有効な JWT で `jwt.claims.staff_id` が関数に渡ること、不正な JWT が拒否されること。
