# 20261103_0002 アクセスパスの登録を DB の関数にまとめる(調査と案)

`packages/model_providers/issue/20261103_0005.md` の「登録の途中失敗」の調査結果。**案であり、適用していない。**

## 現状
アクセスパスの登録(`AccessControlClient.createAccessPath`)は、PostGraphile の自動 CRUD の mutation を 1 テーブルずつ順に呼ぶ(辞書×3 → 言語別の値×6 → 呼称 → アクセスパス = 11 回)。途中で失敗すると、辞書・値・呼称だけが残る(孤児)。1 件の登録で通信が 11 往復になる点も負担(CSV の 80 件ほどを登録すると約 900 回)。

## 調査結果
1. **関数にできる**: 棚ビジター(`07_visiter_functions.sql`)と同じ方式で、PostGraphile の mutation として公開できる。1 回の呼び出し = 1 トランザクションなので、途中で失敗しても何も残らない。モデル側は `kind: function`(`~PageCall`)で呼べる(`model_providers/CLAUDE.md`「DB の関数の呼び出し」)。
1. **必要な表**: `shared_dictionary`(`symbol`・`remarks` だけ)、`shared_dictionary_value`(言語・辞書・値)、`shared_appellation`(名前・読み・略称の辞書)、`info_access_path`(`names` が必須)。いずれも外部キーは `DEFERRABLE INITIALLY DEFERRED`。
1. **担当者(監査列)**: 自動 CRUD の mutation は `update_user_id`・`update_user_history_id` を渡していない。`07` の関数は `visiter_staff()` で JWT の `jwt.claims.staff_id` から担当者と履歴 ID を引いて明示している。**自動 CRUD の登録・更新で監査列が埋まるか(トリガーが JWT から埋めるか)は未確認。** 履歴(`history_*`)のトリガーは `trg_02_history_*` で動く。関数にするなら、`visiter_staff()` を使って明示するのがよい。
1. **重複**: `usecase_path` の一意制約は DB に無い(`symbol` だけが一意。空の symbol は 2 件目から衝突するので、関数でも空は避ける)。クライアントが `usecase_path` で調べてから登録している。同時登録の競合を防ぐなら、関数の中で `usecase_path` を検査するか、一意制約(`remove = false` の行に部分一意)を足す。
1. **JWT のクレーム**: 関数が `jwt.claims.staff_id` を読むので、PocketBase の GraphQL 用 JWT に `staff_id` が必要(対応済みとのこと。`20261103_0001.md`)。

## 案: `access_path_create`
```sql
-- アクセスパスを呼称つきで登録する。1回の呼び出し = 1トランザクション。
-- 呼称の読み・略称は空の値で作る(あとから編集で入れる)。
-- 返り値: info_access_path_id
CREATE OR REPLACE FUNCTION tests.access_path_create(
    p_app_id uuid, p_usecase_path varchar, p_name_ja varchar, p_name_en varchar,
    p_symbol varchar DEFAULT '', p_remarks varchar DEFAULT NULL, p_staff_id uuid DEFAULT NULL
) RETURNS uuid AS $$
DECLARE
    v_ja uuid; v_en uuid; v_name uuid; v_pron uuid; v_nick uuid; v_names uuid; v_id uuid;
    v_staff record;
BEGIN
    SELECT * INTO v_staff FROM tests.visiter_staff(p_staff_id);            -- 担当者(省略時は JWT)
    SELECT shared_language_code_id INTO v_ja FROM tests.shared_language_code WHERE code = 'ja' AND remove = false;
    SELECT shared_language_code_id INTO v_en FROM tests.shared_language_code WHERE code = 'en' AND remove = false;
    IF v_ja IS NULL OR v_en IS NULL THEN RAISE EXCEPTION '言語コード(ja・en)がありません' USING ERRCODE = 'ACP01'; END IF;
    IF EXISTS (SELECT 1 FROM tests.info_access_path WHERE usecase_path = p_usecase_path AND remove = false) THEN
        RAISE EXCEPTION 'このパスは登録済みです (%)', p_usecase_path USING ERRCODE = 'ACP02';
    END IF;
    -- 辞書(名前・読み・略称)と言語別の値
    INSERT INTO tests.shared_dictionary DEFAULT VALUES RETURNING shared_dictionary_id INTO v_name;
    INSERT INTO tests.shared_dictionary DEFAULT VALUES RETURNING shared_dictionary_id INTO v_pron;
    INSERT INTO tests.shared_dictionary DEFAULT VALUES RETURNING shared_dictionary_id INTO v_nick;
    INSERT INTO tests.shared_dictionary_value (shared_language_code_id, shared_dictionary_id, dictionary_value) VALUES
        (v_ja, v_name, p_name_ja), (v_en, v_name, p_name_en),
        (v_ja, v_pron, ''), (v_en, v_pron, ''), (v_ja, v_nick, ''), (v_en, v_nick, '');
    INSERT INTO tests.shared_appellation (shared_dictionary_name_id, shared_dictionary_pronunciation_id, shared_dictionary_nickname_id)
        VALUES (v_name, v_pron, v_nick) RETURNING shared_appellations_id INTO v_names;
    INSERT INTO tests.info_access_path (info_app_id, names, usecase_path, symbol, remarks, update_user_id, update_user_history_id)
        VALUES (p_app_id, v_names, p_usecase_path, p_symbol, p_remarks, v_staff.staff_id, v_staff.staff_history_id)
        RETURNING info_access_path_id INTO v_id;
    RETURN v_id;
END
$$ LANGUAGE plpgsql;
```
※ 列名は案のとおりで、実際のスキーマで確認が必要(`shared_dictionary` の `DEFAULT VALUES` が使えるか、`visiter_staff` の OUT 列名)。エラーコード(`ACP01` 言語 / `ACP02` 重複)は案。

## 採否の目安
- 登録が画面からの 1 件ずつ、CSV の一括登録は初回だけなら、現状(クライアントが順に呼ぶ)でも運用できる。
- CSV の一括登録を何度も行う、または孤児が問題になるなら、この関数にする。モデル側は `~PageCall` を足し、`AccessControlClient.createAccessPath` の中身を 1 回の呼び出しに置き換える(公開の型は変えない)。
