# 20261116_0001 MRP の結果のビュー(`v_mrp_suggestion`)を boolean の列で返す

依頼元: `flutter-pms` のルート(`issue/20261116_0002.md` の「MRP の結果の boolean 化」)。

**2026-11-16: 案を作った(`doc/query/20261116_0004_stage1_views.sql` の `v_mrp_suggestion`・`v_mrp_run`)。`mrp_commit` が書き換える範囲(確認してほしいことの 1)は、検査で確認した(`doc/query/20261116_0006_stage1_tests.sql` の T9。反映は採用の提案だけ)。適用の依頼は `20261116_0002.md`。判断の列は、決定の `adopted`・`rejected` に、`undecided`・`is_info`(`decision` の 0 と 9)を足した(ルートの `issue/20261116_0003.md` の D1)。**

## 目的
アプリが、提案の種類(`trans_mrp_suggestion.kind`。文字列 17 種)のコード値を持つと、解釈がアプリごとに変わる。DB のビューが boolean の列で返し、アプリはその列だけを使う(設計の共通ルール「状態・区分をコード値で持たない・判定しない」)。

## 決定したこと
1.  **MRP の定義**: MRP は、個別の変更(キャンセル・追加・変更)の結果を集計して提案を作る。判断は個別ではなく結果に対して行い、判断が済んだものを確定して反映する(`mrp_run` → 判断 → `mrp_commit`。これらの関数は使われている)。
1.  ビューは `kind` を出さず、対象・動きを boolean に分解して返す。ビットスイッチの整数値(boolean をまとめた整数)は持たない(廃案)。
1.  言語別の表示の文字の列は持たない。アプリは、列のコメントを見出しにして、チェック・シグナル・ステップで表示する。
1.  判断を求めるかは既存の `need_user` を使う。採用・却下は `decision`(整数)から導く `adopted`・`rejected` で返し、整数の `decision` はビューの外へ出さない。

## 依頼
1.  ビュー `v_mrp_suggestion`(名前は既存の `v_mrp_pending_suggestion` などと合わせて決めてよい)を作る。`kind` から `CASE` で導く(MRP の関数・既存の行は変えない)。`symbol` 列を含める(設計の共通ルール)。
1.  列の案(種類との対応は、実際の意味に合わせて確定する):
    1.  対象: `is_purchase`・`is_production`・`is_outsource`・`is_plan`・`is_exception`・`is_supply_request`。例外の主題: `subject_equipment`・`subject_stock`・`subject_master`。
    1.  動き: `is_new`・`is_change`・`is_cancel`・`is_keep`・`is_option`。既存の `late`(遅延)はそのまま出す。
    1.  判断: `need_user`(既存)・`adopted`・`rejected`(`decision` から導く。両方 false = 未判断。両方 true は不可)。
1.  種類の分解の案(実際の意味に合わせて確定する):

    | 種類(`kind`) | 対象 | 動き |
    |---|---|---|
    | `PURCHASE_NEW` | 発注 | 新規 |
    | `PURCHASE_RESCHEDULE` | 発注 | 変更(日程) |
    | `PURCHASE_CANCEL` | 発注 | 取消 |
    | `PRODUCTION_NEW` | 生産 | 新規 |
    | `PRODUCTION_RESCHEDULE` | 生産 | 変更(日程) |
    | `PRODUCTION_CANCEL` | 生産 | 取消 |
    | `OUTSOURCE_NEW` | 外注 | 新規 |
    | `OUTSOURCE_CANCEL` | 外注 | 取消 |
    | `OUTSOURCE_OPTION` | 外注 | 切替の選択肢 |
    | `PLAN_NEW` | 生産計画 | 新規 |
    | `PLAN_UPDATE` | 生産計画 | 変更 |
    | `PLAN_KEEP` | 生産計画 | 維持 |
    | `PLAN_CANCEL` | 生産計画 | 取消 |
    | `EXC_OVERLOAD` | 例外(設備) | — |
    | `EXC_EXCESS` | 例外(在庫) | — |
    | `EXC_MASTER` | 例外(マスタ) | — |
    | `SUPPLY_REQUEST` | 支給依頼 | 新規 |
1.  PostGraphile 用: 主キー・外部キーを `COMMENT ON VIEW` の `@primaryKey`・`@foreignKey` で付ける。
1.  DB のテスト: 「対象の列が、全ての行でちょうど 1 つ立つ」ことを検査する(新しい種類が増えても、どの列も立たない行が出ないように)。
