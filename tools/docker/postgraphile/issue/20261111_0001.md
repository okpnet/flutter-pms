# スキーマ全体のイントロスペクションで接続が切れ、再起動する

## 指示元
`flutter-pms/issue/20261111_0002.md` の 0-4(`melos run gql:schema`)。実施: 2026-11-11。接続先 `http://192.168.1.100:5000/graphql`(`postgraphile_server`)。

## 症状
1. `{ __typename }` や型名の一覧(`__schema { types { name } }`)は応答する。
1. `fetch_schema.dart` の標準のイントロスペクション(全型・全フィールド・引数、型参照7段)を送ると、`Connection closed before full header was received` で接続が切れる。
1. その後、約3分間は全ての要求に接続できず(HTTP 000)、その後で応答が戻る(`restart: always` による再起動とみられる)。3回続けて再現した。
1. 2026-11-03 には同じ取得が成功し、`.schema/schema.graphql`(約31MB)ができている。以後、DB の新しいテーブル・ビュー(受注・発注まわりの仕様変更)が増えた。

## 推測(コンテナのログは、この PC から見られないため未確認)
Node のメモリ不足(既定の上限)で、イントロスペクションの結果の生成中にプロセスが落ち、再起動している。`docker logs postgraphile_server` の `JavaScript heap out of memory` などで確認できる。

## 依頼(PostGraphile 側)
1. `docker logs postgraphile_server` で、落ちた理由を確認する。
1. メモリ不足なら、`docker-compose.yml` に `environment: NODE_OPTIONS=--max-old-space-size=4096`(必要なら `mem_limit` も)を足す。Dockerfile の `ENTRYPOINT` は `postgraphile` を直接呼ぶため、`NODE_OPTIONS` が使える。
1. 代わりの取得方法: `--export-schema-graphql /schema.graphql` は、コンテナ内に書くだけでホストから読めない。ホストへ出す(`volumes` に `./schema:/schema` などを足して、出力先を `/schema/schema.graphql` にする)なら、イントロスペクションの送信が不要になる。`fetch_schema.dart` の冒頭にも「直接書き出せる場合は、このツールは不要」とある。
1. 直ったら、`melos run gql:schema` から再開する。

Docker の設定は、指示があるときだけ変更する決まりのため、変更していない。
