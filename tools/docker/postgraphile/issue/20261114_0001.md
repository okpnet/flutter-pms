# GraphQL のエラーに DB の errcode が含まれない(--extended-errors)

指示元: `flutter-pms/issue/20261114_0001.md`(操作の DB 関数をモデルに取り込んだ検証。2026-11-14)。接続先 `http://192.168.1.100:5000/graphql`。

## 症状
DB の関数が `RAISE EXCEPTION ... USING ERRCODE = 'OPR01'`(操作の関数)・`'VIS03'`(棚ビジターの関数)・`'MRP00'`(MRP)で失敗しても、GraphQL のエラーは `message` だけで、`extensions` が空(`null`)。クライアントは errcode で失敗の種類を見分けられず、エラーの文(日本語の RAISE の文)に頼ることになる。
- 例: `orderDetailCancel` に存在しない受注明細を渡すと、`errors[0].message = "受注明細が見つかりません (…)"`、`extensions: null`。
- `barcode_entry_model` の `ScanClient`(`ScanClientException.code`)・`production_plan` の MRP のエラー(`MRP_ERROR` など)は、errcode を読む作りだが、実サーバーでは null になる(代役サーバーのテストでだけ通る)。

## 依頼(Docker の設定。指示があるまで変更しない)
`tools/docker/postgraphile/docker-compose.yml` の `command` に、次を足す。
```
- "--extended-errors"
- "errcode,hint,detail"
```
PostGraphile v4 は、既定では本番向けに、エラーの `extensions` に何も入れない。`--extended-errors errcode` で、`extensions.exception.errcode`(DB の SQLSTATE。関数の `ERRCODE`)が入る。`hint`・`detail` は RAISE の `HINT`・`DETAIL`。
- セキュリティ: 検証用サーバーでは問題ない。本番では、DB の内部情報(`detail` など)がクライアントに出るため、`errcode` だけにするか、`detail` を外すかを判断する。
- 反映後、`flutter-pms` 側のテスト(`model_providers/*/test/operation_call_test.dart`)が errcode(`OPR01` など)も確認する(いまは、errcode があれば一致を確認し、無ければエラーの文だけを確認する作りにしてある)。
