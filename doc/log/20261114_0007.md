# 20261114_0007 画面の取得元を GraphQL 版にする(方針 A: 読み取り専用)

指示: 「Aで進めてください。そのあとBを採択します」(A = 読み取り専用の GraphQL 版を先に作る。B = 画面案を DB に合わせる。B はあとで進める)
対象: `packages/features/{sales,purchasing,production_plan}`、`apps/pms_app`、`tools/entity_gen/gen.js`、`packages/model_providers`

## 実施
1. `sales`(受注・受注明細)・`purchasing`(発注・発注明細)・`production_plan`(資材計画・生産計画)に、GraphQL 版の取得元(`lib/src/graphql/*_repositories.dart`)を作った。
   - DB の列に対応する項目だけを、読み取り専用(`viewOnly`・各項目 `readOnly`)にした。保存・削除は `UnsupportedError`。
   - DB にあって画面案に無い項目を足した: 受注明細・発注明細のキャンセル数量・停止・残・受注残/発注残・全部キャンセル済み・受入済み・精算額・顧客所有(DB のビュー `v_order_detail_balance`・`v_purchase_detail_balance` の列。画面で計算しない)、生産計画の停止・打ち切り。
   - 受注明細・発注明細・生産計画は、親ごとに引く(`findByParent`)。明細の ID だけからの取得(`findById`)は、明細から親を引いてから読む。
   - `pms_app` の `graphql_overrides.dart` に差し込んだ。
1. 生成元 `tools/entity_gen/gen.js` に、`GRAPHQL_EXTRA_LABELS`(DB にあって画面案に無い項目の表示名)を足し、`node tools/entity_gen/gen.js` で言語ファイルを再生成した(生成物は直接編集しない)。再生成は、ビルド日時と空行以外は差分が出ない(冪等)ことを確認し、無関係なパッケージの差分は戻した。
1. 通信テスト(検証用サーバー、一般ユーザー。読み取りだけ)を各機能に追加: 一覧・1件の取得・親ごとの明細・DB のビューの列(残など)・読み取り専用であること。`dart_test.yaml` に `server` タグを宣言した。
1. 各機能の `CLAUDE.md` に、取得元の説明を足した。`issue/202611.md` の 2-1 に進み具合を書いた。

## 見つけたこと
1. **入れ子の読み込みの `pick` は、列を読まない**: モデル生成器の `pick` は、共有定義がある件数ビューの列を絞るものだった。残(`balance`)・登録できるか(`registrable`)を `pick` で書いたため、生成された読み込みには主キーしか入らなかった。`columns` に直した。**`barcode_entry` の停止・終了の判定が、この間は常に false になっていた**(直近のコミットの内容。今回の修正で正しく動く)。
1. 画面案の定義が DB と合っていない: 受注に顧客の項目が無い(DB は必須)、出荷予定・出荷指示は DB に対応する表が無い、発注の金額は別のビュー。このため、書き込みは B(定義を DB に合わせる)のあとにした。
