## 判断したこと・Issue との差

- **前提の差**: `graphql_provider` の実体は `graphql_provider_lib`(`gqlprvlib`)、`gql_yaml2graphql` は存在しなかった(YAML は `source/views`)。機能パッケージはこのライブラリをコードから参照しておらず(コメントのみ)、import の切り替えは不要だった。
- **YAML のアンカーはパッケージをまたぐ**(共通定義、company↔resource↔provision↔sales)。`gql_yaml2graphql` は全パッケージの `gql/*.yaml` を結合して変換し、出力はノードの持ち主のパッケージへ振り分ける。共通定義は `packages/model_providers/gql_shared/gql/`。
- **`*.graphql.dart` は Git に入れない**(合計約 200MB、最大 6.9MB)。画面用 `schema.graphql` と `.graphql` は Git にあるので、本家スキーマ無しで `melos run gql:build` だけで再生成できる。入れる方針に変えるなら `packages/model_providers/.gitignore` を消す。
- **スカラーの型が変わった**: Datetime → `DateTime`、BigInt → `BigInt`(Issue 第6章のとおり)。UUID・Date・Cursor は従来どおり `String`。
- **YAML の不具合を1件修正**: `gql_shared/gql/transaction_common.yaml` の入れ子の編集(`FlexibleLabelEditFields`・`FlexibleTextEditFields`)に、子の作成入力に存在しない親 ID の列(`trans_label_id`・`trans_text_id`)があり、抜き出しツールの検証で 15 ファイルが失敗した(旧ライブラリでは未生成の画面だった)。この2列を外した。
- 旧ライブラリで未生成だった 165 ファイル(quality・work などの画面)が、今回初めて生成・モデル化された。

## 検証

- `gql_schema_pruner` 11 件、`gql_yaml2graphql` 19 件、`pms_graphql` は 68 件成功・2 件失敗(下記の既存の失敗)。
- 全モデルパッケージのテスト(往復変換、RFE⇔Edit、検索条件の対応表、ツリー)が成功。
- `melos run gql:check` が全パッケージで一致、`gql:yaml` が通る。
- `melos run analyze` は `pms_authenticator`(example の `Logger` 未定義)だけ失敗。今回の変更前からのもの。

## 未解決・要判断

1. `pms_graphql` の既存テスト 2 件(`graphql_converter_collection_test`: hasConverter/getConverter が常に例外)は改名前から失敗している。今回は触れていない。ネットワークを使う `client_provider_public_api_test` も環境によって失敗しうる。
2. 旧 `tool/gen_property_list.dart`(連携インターフェイス CSV)・`tool/scaffold_view.dart`(YAML の雛形)は新しい構成へ移植していない。`doc/legacy_graphql_provider_lib/tool/` に残してある。必要なら移植する。
3. 各 `*_model` の `lib/src/contents/*_keyname.dart` は旧ライブラリの手持ち分のみ(生成元の `gen_property_list` は未移植)。
4. 機能パッケージ(`features/*`)はまだモデルパッケージに依存していない。実際のデータ取得を組み込むときに、自分の `*_model` だけに依存し、生成型を機能の外に出さないこと(Baton 経由を含む)。現時点で型を受け渡している箇所は無い。
5. `.schema/schema.graphql` は旧 `source/schema.full.graphql` を複製した(取得日 2026-10-26)。DB 変更後は `melos run gql:schema`。サーバーには接続していない。

## 追記(issue/20261027_0002 の対応)

- 未解決1: 失敗していた2件は`pms_graphql`側の問題(実装で型の検査がコメントアウトされ、テストが旧挙動のまま)。`packages/infra/pms_graphql/issue/20261027_0001.md`に追加した。`client_provider_public_api_test`は現在成功している。
- 未解決2・3: `gen_property_list`・`scaffold_view`を`tools/gql_yaml2graphql/bin/`へ移植した(`--root`・`--schema`対応)。`melos run gql:property-list`で`doc/contents/property_list.csv`(約9MB、Git対象外)を出力する。生成モデルが必要なため`gql:build`の後に実行する。警告21件は、Dartの予約語`class`の列が生成モデルで別名になるため。
- 未解決4: `packages/features/CLAUDE.md`に「GraphQL モデルの利用」を追加した。
- 未解決5: 変更なし(現在のスキーマが最新)。
