# 20261118_0004 06 の確認結果(指摘 4 件)への対応

指摘(`06_cteate_test.sql` を構築して確認した結果)と対応。PERO のデータ・06 の両方に反映した(DB には未適用)。

1.  **`trans_visiter_owner` のコメントの順番**: `@omit create,update,delete` を先頭の行にし、説明「支給所有権」を後ろにした(PostGraphile は先頭の `@` の行からタグとして読むため、順番が逆だと効かなかった)。ほかのテーブル・ビュー・関数のコメントに、同じ誤りが無いことを、06 を走査して確認した(説明が先で、あとに `@` の行がある注釈は、ほかに無い)。
1.  **`mrp_purge` が全部消すか何も消さないか**: 実行ごとに、サブトランザクション(`BEGIN … EXCEPTION WHEN foreign_key_violation`)で削除するようにした。遅延の外部キーは、実行ごとに `SET CONSTRAINTS ALL IMMEDIATE` → `DEFERRED` で検査し、違反した実行だけを残して(`RAISE NOTICE`)、ほかの古い実行は消す。戻り値は、削除できた実行の数。一時表(`_mrp_purge`)は使わなくなった。
1.  **`lot_deliver` の品目の確認**: 精算につなぐ受注明細(`p_order_detail_id`、または既存の精算 `p_order_detail_settlement_id` の受注明細)の品目と、引き渡すロットの品目(`v_visiter_item`)が違うときは、`OPR02`(「ロットの品目と、精算の受注明細の品目が違います」)にする。ロットの品目が分からない(`NULL`)ときは、確認しない(分かるときだけ)。
1.  **NOTICE**(言語コードの索引の `DROP INDEX IF EXISTS`、`mrp_run` の一時表の `DROP TABLE IF EXISTS` の「does not exist, skipping」): 害が無いため、変更していない。
