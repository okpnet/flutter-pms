# 営業(受注・受注明細)の書き込み(GraphQL 版)

## 内容
1. `sales_model/gql/order.yaml` に `OrderPageCreate`・`OrderDetailPageCreate`(`kind: create`)を追加し、`melos run gql` で生成した。
2. `sales_repositories.dart`: 受注・受注明細の定義を書き込める形にした(`_writableDefinition`。キャンセル数量・停止・残・精算額・マスタ不備件数は読み取り専用)。`save`(新規は create、既存は edit)と `remove`(論理削除 `remove = true`)を実装した。
3. 顧客・品目の履歴ID+IDは、PostGraphile の `allHistoryMstrStakeholders`・`allHistoryMstrItems` を `revision` 降順で1件引いて送る。担当者(`update_user_*`)は送らない(DB の列は NULL 可)。
4. 必須・数値・日付の検証は取得元が行い、`EntityValidationException` で返す。

## テスト
`packages/features/sales/test/sales_connection_test.dart`(PostGraphile、一般ユーザー)。受注 → 明細の登録、更新、論理削除を行い、`finally` で後始末した。4 件すべて通過。

## 残り
- `purchasing`・`production_plan` の書き込み(仕入先・資材計画の履歴ID の解決)。
- 担当者(更新者)を送る(JWT の `staff_id` を取得元へ渡す仕組みが要る)。
- 出荷予定・出荷指示の定義(運送業者は利害関係者、梱包サイズは品目から求める)。
