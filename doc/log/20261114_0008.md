# 20261114_0008 方針 B: 画面案を DB に合わせる(受注・発注・生産計画から)

指示: 「1. 梱包サイズは品目を参照すればわかります。運送業者は利害関係者に含まれています。2. 採択します(B を、受注・発注・生産計画から)」
対象: `tools/open-design`(画面案とその生成ツール)、`tools/entity_gen/gen.js`、`packages/features`

## 実施
1. **`tools/open-design/tools/gen-schema.js`(画面案を DB から生成するツール)は、旧い入力元を読んでいて動かなかった**(廃止した `graphql_provider_lib` の views、旧い `scripts/` フォルダ)。新しい入力元に直した: 画面ごとの読み込みは `packages/model_providers/*/gql/*.yaml`(`gql_shared` を含む)、DB は `tools/docker/postgresql/script/06_cteate_test.sql`(PERO の出力。コメントの書式が大文字のため、正規表現を大文字小文字を区別しないものに)。
1. **履歴ID+IDの組の外部キー**(例: `stakeholder_history_id, stakeholder_id → history_mstr_stakeholder`)を、IDの列の参照として読むようにした。これまでは単一の列の外部キーしか読まず、顧客・発注先・品目の項目が画面案から落ちていた(「参照先の画面が無い → 非表示」)。
1. 操作の DB 関数で変える列(`cancel_quantity`・`stop`・`discontinue`)は、編集項目にしない。`tools/entity_gen/gen.js` の `FIELD_ADDITIONS` が、読み取り専用の項目(キャンセル数量・停止・残・受注残/発注残・全部キャンセル済み・精算額・受入済み・打ち切り)として足す。先に足した表示名だけの表(`GRAPHQL_EXTRA_LABELS`)は外した(項目の定義に含まれる)。
1. `gen.js` の改名(`purchase` → `catalog_item`)が、DB から来た同じ項目と重なって `item` の生成が失敗した。改名先がすでにあるときは、画面案の古い項目を外すようにした。
1. 再生成(`gen-schema.js` → `gen.js`)の結果(受注・発注・生産計画):
   - 受注: 顧客(`stakeholder_id`)が入った。受注明細: 品目・価格調整・確定単価・製品顧客所有が入った。
   - 発注: 発注先が入った。発注明細: 品目が入り、資材支給・有償支給が選択(はい/いいえ)になった。
   - 資材計画・生産計画: 親の生産計画・品目・生産数量が入った。
   - ほかの機能の定義も、同じ理由で DB に近づいた(品目の購入品、非計上明細、作業実績の作業担当者など。`tools/open-design/schema.gen.log.md` の差分を参照)。
1. 取得元(GraphQL 版)は、生成された定義をそのまま使う形に直した(値を返す項目だけを読み取り専用で使う)。

## テスト
機能 21 パッケージ・`pms_app`・`entry_app` が全て通過(一般ユーザー)。
