# 20261106_0002 追加: メンテナンス情報サーバーの 403/404 の調査と修正

対象: `tools/docker/maintenance`(192.168.1.101:18480)。Talend API Tester で `/health` は成功、`PUT /info/...` が 403、のちに 404。

## 原因と対応
1. **403**: 認証ファイル `/etc/nginx/htpasswd` がコンテナ内に無かった(`open() "/etc/nginx/htpasswd" failed (2)`)。
   - `10-htpasswd.sh` を `/docker-entrypoint.d/` に置いていたが、nginx の公式イメージは実行権限のあるスクリプトしか実行しない。Windows で作ったため Git では 100644 で、サーバー(Linux)では実行されなかった。
   - `auth_basic` は認証ファイルが開けないと、ID・パスワードに関係なく 403 を返す。`/health` は認証を使わないので成功していた。
   - 対応: `docker-compose.yml` の `entrypoint` で、スクリプトを CRLF を除いて `sh` に直接渡して実行してから nginx を起動する。スクリプトは `/opt/10-htpasswd.sh` に置く。
2. 認証ファイルを nginx のユーザーが読めない(`umask 077`、root 所有)問題と、置き場に `chown` が効かず書けない問題に備え、`10-htpasswd.sh` で `chown`/`chmod` を追加した。
3. **404**: クライアントのメソッドが `POST` だった。`dav_methods` は `PUT DELETE` のみなので、`POST` は読む処理になり、ファイルが無くて 404。`PUT` にすると 201/204。README に追記した。

## 確認
`/health`、`/info/<名前>.json`、`/maintenance.flag` の PUT と GET が動作した(ユーザーが Talend API Tester で確認)。
