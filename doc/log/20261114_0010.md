# 購買・生産計画の書き込み(GraphQL 版)

`20261114_0009.md`(営業)と同じ方式で、購買(発注・発注明細)と生産計画(資材計画・生産計画)に書き込みを足した。

## 内容
1. `purchasing_model/gql/purchase.yaml` に `PurchasePageCreate`・`PurchaseDetailPageCreate`、`production_plan_model/gql/plan.yaml` に `ResourcePlanPageCreate`・`OperationsPlanPageCreate`(`kind: create`)を追加し、`melos run gql` で生成した。
2. 各取得元に `save`(新規は create、既存は edit)と `remove`(論理削除)を実装した。仕入先・品目の履歴ID は、最新(`revision` 最大)を引いて送る。担当者は送らない。
3. 読み取り専用のまま: 発注明細のキャンセル数量・停止・受入済み・残・発注残・全部キャンセル済み、生産計画の停止・打ち切り。

## テスト(PostGraphile、一般ユーザー)
各 `test/*_connection_test.dart` で、親 → 子の登録、更新、論理削除を行い、`finally` で後始末した。購買 4 件・生産計画 3 件すべて通過。

## 残り
- 担当者(更新者)を送る(JWT の `staff_id` を取得元へ渡す仕組みが要る)。
- 出荷予定・出荷指示の定義(運送業者は利害関係者、梱包サイズは品目から求める)。
