# 登録・更新の方式を整理する(共通関数 + ミューテーション)

指示(2026-11-15)を `issue/20261115_0001.md` に記録し、ルートの `CLAUDE.md` の「登録・更新の方式」に統合した。

## 指示
1. 共通のもの(呼称・文章・ラベルなど)は関数にする。
1. マスタ・Info・trans は、極力ミューテーション(自動 CRUD)で対応する。
1. 2 を実行したときに複数の表にまたがり影響が大きいもの(例: MRP、棚移動)は関数にする。
- 理由: Info・マスタは同時に変更される可能性が低く影響が限定的。trans は棚移動が同時に起こる可能性が高く、MRP でも参照・変更され、金銭に直結する。関数が増えすぎると DB の保守性が下がる。

## ずれていたところと対応
- マスタごとの保存関数(`unit_save`・`stakeholder_save`。適用済み)と、作りかけの 13 本(`doc/query/20261115_0001_master_save_functions.sql`。未適用。ファイルは削除)は、方針に合わないため取り下げた。`unit_save`・`stakeholder_save` は、移行後に DB から外す依頼を出す(`tools/docker/postgresql/issue/20261115_0001.md` の 0 の 5)。`ap_*`(`@omit`)は、共通関数の内部で使うので残す。
- 代わりに、共通関数 4 本と索引を作った:
  - `doc/query/20261115_0001_common_functions.sql`: `shared_appellation_save`(呼称)・`shared_text_save`(文章)・`trans_label_save`(trans のラベル)・`trans_text_save`(trans の文章)。戻り値は行。渡した言語の値だけ入れ替え、空文字で空になる。
  - `doc/query/20261115_0002_code_unique_indexes.sql`: コードの部分一意索引(`remove = false` の行だけ。`<表>_ix_code_active`)。マスタごとの関数の検査の代わり。

## 検証
- 検証用 DB で、`0003` → 共通関数 → 索引を、トランザクション内で流して ROLLBACK(46 ケース。想定外 0): 共通関数の新規・更新(渡した言語だけ)・同じ値の更新・空にする・エラー(`APL00`・`APL01`・`APL02`)、ミューテーションと同じ形の INSERT / UPDATE でのマスタ・Info(渡した列だけ更新、null で消える、履歴、論理削除、削除済みコードの再利用、索引による重複 `23505`)と、体系(部署)の親の付け外し(閉包が更新される)。
- 実サーバー(PostGraphile)のミューテーション: 登録、備考だけの更新(ほかが残る)、null で消える、論理削除。**同じ値の更新は、応答の行が null になる**(エラーではない。履歴のトリガーが握りつぶす)。画面は更新後に読み直す。
- 体系の循環(自分自身を親にする)は、DB に検査が無く、できてしまう。クライアントで検査する。

## 継続(Issue)
- `tools/docker/postgresql/issue/20261115_0001.md` を書き直した: DB への依頼の順(0)、共通関数(1)、マスタ・Info・trans ごとのミューテーションの本体の列と注意(2)、取得元の取り込み手順(3)、現状と既知の制限(4)。更新者の列(NULL のまま)を共通のトリガー関数 1 本で埋めるかは、未決として判断を依頼している。
- `system`(単位)・`shared_master`(利害関係者)の取得元は、暫定で `unit_save`・`stakeholder_save` を使っている(未コミット)。DB に共通関数・索引が適用されたら、共通関数 + 平らなミューテーションに入れ替える(コードと CLAUDE.md に【暫定】の印)。
- 既存の `~PageEdit`(マスタ)は、呼称を入れ子で更新し、言語の値を全部入れ替える形のため、使わない。平らな `kind: create` / `kind: edit` の定義を足す(名前の付け方は、生成器の規則を確認して決める)。
