# 20261106_0001 管理者・一般の利用者の初期化バッチ(メイン用とテスト用)

指示: [issue/20261106_0001.md](../../issue/20261106_0001.md)(20261105_0001 への対応)
対象: PocketBase `http://192.168.1.103:8090`、PostGraphile `http://192.168.1.100:5000/graphql`、PostgreSQL `192.168.1.101:5432`(DB `test_avocado`)

## 結論
`tools/init` に、管理者・一般の利用者の初期化バッチを、メイン用とテスト用(`test_` 付き)に分けて作った。`test_init.bat` / `test_init.ps1` は `test_admin_init.bat` に置き換えた(削除)。テスト環境で実行して確認した。

| バッチ | 内容 |
|---|---|
| `admin_init.bat` | メイン。入力式。管理者の追加(いなければ)、`app_user_id` の更新(同じなら無視) |
| `test_admin_init.bat` | テスト。`.env` から読む。同上 |
| `user_init.bat` | メイン。CSV の利用者を担当者に対応させて登録(有効化コードを発行) |
| `test_user_init.bat` | テスト。ダミーの担当者を PocketBase のユーザーに追加 |

本体は `admin_init.ps1`・`user_init.ps1`(テストは `-Test`)、共通部品は `init_common.ps1`。使い方は [tools/init/README.md](../../tools/init/README.md)。

## 追加仕様への対応
1. PostgreSQL の `info_staff` の管理者のID → PocketBase `users.app_user_id`(更新)。PostGraphile から管理者になりすまして(superuser の `impersonate`)担当者を引き、同じなら何もしない。
2. PocketBase の管理者がいなければ追加(`role=admin`、有効、superuser ではない)。
3. 実行時に `username`・パスワード(2回)・`email`(空可)を入力できる(本番)。引数・環境変数でも渡せる。
4. ダミーユーザー: `13_user_dummy.sql` の担当者 `TANAKA`・`SUZUKI`・`SATO` を、PocketBase のユーザーとして追加し、担当者のIDを `app_user_id` に入れる(`test_user_init.bat`)。

## 判断
1. 本番のバッチは `.env` を読まない。接続先は `https`(ローカルのネットワークのみ `http`)。パスワード・資格情報は表示しない。
2. 本番の一般の利用者は、パスワードを決めずに「有効化コード」を発行する(既存の `POST /api/app/admin/users`)。コードは一度だけ画面に出し、ファイルに残さない。
3. 担当者との対応は、コードで行う(大文字小文字を区別しない)。すでに別のユーザーに対応している担当者は飛ばす。管理者のアカウントは、利用者のバッチでは変更しない。
4. 終了コード: `0` 完了 / `1` 失敗 / `2` 一部を処理できなかった。
5. PowerShell の変数名は大文字小文字を区別しない(`$AdminUser` と `$adminUser` が同じ)ため、取得したレコードは `$adminRecord` にした(実行で発見・修正)。

## 確認(テスト環境)
- `test_admin_init`: 管理者 `administrator` が PocketBase にいなかったため追加 → `ADMIN`(`ef491383-…`)と対応 → ログイン OK、JWT `role=pms_admin`・`staff_id` 一致。
- `13_user_dummy.sql`: トランザクション内で実行して ROLLBACK し、3人が作られることを確認した後、実際に投入した(PostgreSQL の担当者は ADMIN を含め4人)。
- `test_user_init`: 1回目に `sato`・`suzuki`・`tanaka` を追加(role=user、有効、`app_user_id` が担当者のID)。2回目は3人とも「対応済み」で変更なし(冪等)。
- `user_init`(本番、CSV): 対応済みの行は何もしない。担当者が無い行・`username` の形式が誤りの行・担当者が別のユーザーと対応済みの行は、飛ばして終了コード 2。
- `user_init`(本番)の登録: 一時的に `suzuki` の `app_user_id` を外して、CSV の `initcheck` を登録 → 有効化コードが発行された。確認後、`initcheck` はID指定で削除し、`suzuki` の `app_user_id` は元に戻した。

## 現在の状態(テスト環境)
- PocketBase: `administrator`(admin、`ADMIN` と対応)、`sato`・`suzuki`・`tanaka`(user、有効、各担当者と対応)。ダミーユーザーの共通のパスワードは、実行時の `-UserPassword` の値(ここには書かない)。
- PostgreSQL `test_avocado`: 担当者 `ADMIN`・`TANAKA`・`SUZUKI`・`SATO`。

## 未対応・注意
1. 本番の接続先(実在の https)での実行は、この環境では行えない(テスト環境のみ確認)。
2. `05_app_admin.pb.js` はコンテナ再起動で反映済み(Issue の記載)。ただし自動作成の `app_user_id` は UUID でないため、バッチ(`admin_init`)で担当者のIDに直す。
3. 本番の `admin_init` の入力(対話)は、非対話の実行でのみ確認した。
