# 呼称の関数(案)のテスト結果への対応

対象: `doc/query/20261114_0002_appellation_functions.sql`(適用していない案。検証用 DB で、トランザクション内で実行して ROLLBACK した。DB は変わっていない)。

## 指摘と対応
| 指摘 | 対応 |
|---|---|
| 更新で、渡さなかった項目が消える(顧客の印が true → false、管理コード・メール・備考が空、コードだけ今のまま) | 全部の関数を「渡した項目だけ更新する」にそろえた(NULL は今のまま)。空にするには、文字は空文字、配送区分は `p_clear_shipping_kind`、真偽は true / false。単位の備考も同じ |
| コードの重複が、同時登録・関数を通さない登録で入る | 部分一意索引 `mstr_stakeholder_ix_code_active`(`remove = false` のみ)を足した(DDL)。関数の検査(`APL03`)は分かりやすいエラーのため残す。削除済みのコードは再利用できる |
| 戻り値が ID だけ | 保存した行(`shared_unit`・`mstr_stakeholder`)を返す。PostGraphile の応答で、名称を含めて保存後の内容を受け取れる |
| 住所の引数が無い | 画面の定義に住所の項目が無く、別の実体のため、関数では扱わない(更新では今の値を残す)。必要になったら引数を足す |
| 登録した言語の名称を消せない | 空文字(または JSON の null)で値が空になる。名称の ja は、新規・更新とも空にできない(`APL02`)。行は削除せず、値を空にする(履歴の外部キーのため) |

## 再テストの結果(検証用 DB。ROLLBACK)
- 名称だけの更新で、顧客・供給者・運送業者の印、管理コード、メール、備考、コードが残る。供給者の印だけ・メールと顧客の印だけの更新で、その項目だけが変わる。履歴とリビジョンが更新ごとに増える。
- 戻り値が行(ID・コード・役割・管理コード・メール)。単位の備考は、渡さなければ残り、空文字で消える。
- 関数を通さない同じコードの登録が `23505` で止まる。削除(`remove = true`)したあとは、同じコードで登録できる。
- 名称(ja)を空にする更新は `APL02`。en を空にすると値が空になる。コードを空にする更新は `APL02`。
- 遅延された外部キーの検査で違反なし。ROLLBACK 後に関数は残っていない。
- 未確認: 配送区分を実際に外す(検証用 DB に配送区分が無い)、住所。

## 影響(適用する場合)
関数は戻り値の型を変えたため、適用済みの古い版があれば `DROP FUNCTION` してから作り直す(SQL の先頭で行う)。索引は、適用前に重複が無いことを確認する。
