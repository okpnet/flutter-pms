# 20261105_0001 イニシャルデータと、管理者の登録バッチ(`tools/init/test_init.bat`)

指示: [issue/20261105_0001.md](../../issue/20261105_0001.md)(依頼: 「アプリからログインできる管理者ユーザーを生成するバッチファイルを生成」)
対象: PocketBase `http://192.168.1.103:8090`、PostGraphile `http://192.168.1.100:5000/graphql`、PostgreSQL `192.168.1.101:5432`(DB `test_avocado`)

## 結論
`tools/init/test_init.bat` を作成した。実行すると、App の管理者ユーザー(superuser ではない、`role=admin`、有効)が PocketBase に用意され、PostgreSQL の担当者と紐付き、アプリのログイン画面から入れる。テスト環境で実行して確認した。

## 実装
- `tools/init/test_init.bat`: PowerShell の `test_init.ps1` を呼ぶだけ(UTF-8、オプションは素通し)。最後に一時停止する(環境変数 `TEST_INIT_NOPAUSE=1` で省く)。終了コード 0=完了、1=失敗、2=ユーザーは用意したが担当者と未紐付け。
- `tools/init/test_init.ps1`(UTF-8 BOM つき。PowerShell 5.1 で日本語が化けないため):
  1. `tools/docker/pocketbase/.env` の `PB_SUPERUSER_*` で PocketBase の superuser にログイン。
  2. `APP_ADMIN_USER`(既定 `admin`)の利用者を、なければ作成(`role=admin`、`disabled=false`、`activated_at` を設定 = コード入力なしでログインできる)。あれば `role`・無効化・有効化だけそろえ、パスワードは `-ResetPassword` のときだけ変える(ログイン中の端末を切らないため)。パスワードは `APP_ADMIN_PWD`、無ければ乱数(作成時だけ、一度だけ表示)。
  3. 管理者になりすまして(superuser の `impersonate`、120秒)GraphQL 用の JWT を取り、PostGraphile から担当者(`info_staff`)を読む。コードがユーザーIDと同じ(大文字小文字を区別しない)、無ければ `ADMIN` の担当者のID(UUID)を `app_user_id` に設定する。パスワードが分からない既存のユーザーでも紐付けられる。
  4. アプリと同じ手順(ログイン → GraphQL 用の JWT → `role=pms_admin` と `staff_id` を確認)で確認する。
- `tools/docker/postgresql/script/12_app_admin_dummy.sql`: 担当者(コード=`:admin_code`、既定 `ADMIN`)を、なければ作る(言語・会社も、なければ)。何度流しても同じ。

## 確認(テスト環境)
- 初回(`.env` の `APP_ADMIN_USER=administrator`・`APP_ADMIN_PWD`): ユーザー `administrator` を作成 → 担当者 `ADMIN`(`ef491383-6645-4228-a39b-5014ca96c83a`)と紐付け → ログイン OK → JWT は `role=pms_admin`・`staff_id` が担当者のID。終了コード 0。
- 2回目: 「登録済み(変更なし)」「紐付け済み」。変更なし(冪等)。
- 別のユーザー(`init.check.user`、`.env` の `APP_ADMIN_PWD` なし): パスワードを乱数で作って一度だけ表示、担当者は `ADMIN` にフォールバックして紐付け。確認後、そのユーザーは ID 指定で削除した。
- `12_app_admin_dummy.sql`: トランザクション内で実行して ROLLBACK し、新しいコード(作成される)と既存のコード(作らない)の両方を確認。DB は変わっていない。
- PocketBase `http://192.168.1.103:8090` は、検証の途中で一時的に接続できなくなった(再起動とみられる。約10秒で復帰)。バッチは「接続できません」で、失敗を明示して終了する。

## 現在の状態(テスト環境)
- PocketBase に、管理者ユーザー `administrator`(`role=admin`、担当者 `ADMIN` と紐付け)が1人いる。パスワードは `.env` の `APP_ADMIN_PWD`。ほかのユーザーはいない。
- アプリ(`--dart-define=POCKETBASE_URL=http://192.168.1.103:8090`)のログイン画面に、このユーザーIDとパスワードを入力して入る。

## 判断・注意
1. **PocketBase のサーバー起動時の自動作成(`05_app_admin.pb.js`)と、バッチを併用できる**。同じ変数(`APP_ADMIN_*`)を使い、バッチは既存のユーザーを作り直さない。ただし、サーバー側の自動作成は `app_user_id` が UUID でない値になる。`.env` に `APP_ADMIN_APP_USER_ID=<担当者のID>` を設定するか、バッチで紐付ける。`.env.example` の説明(既定の値)も、UUID が必要な旨に直すとよい(未変更。`.env.example` は別の変更中のため)。
1. **紐付けは担当者のコード(名前)で行う**。Issue の「同じID(名前)」に合わせ、ユーザーIDと同じコードの担当者を優先した。ユーザーIDが `administrator` でも、担当者が `ADMIN` しかなければ `ADMIN` に紐付く(テスト環境の標準の管理者)。別のコードに紐付けたいときは `-StaffCode`。
1. **superuser の資格情報をバッチが `.env` から読む**(テスト環境専用)。パスワードをファイル・ログに残さない。乱数のパスワードは、作成時の表示だけ。
1. 管理者のユーザーID・パスワードをソースに書かない。
