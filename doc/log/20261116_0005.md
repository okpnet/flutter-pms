# 20261116_0005 ラベルプリンターの調査(棚移動のバーコードラベル)

指示: 棚移動にあたり、コンテナ・モノにバーコードラベルを貼る必要がある。ラベルプリンターをサーバー上で管理し、アプリと連携するための調査。**ログに記録するだけで、Issue には追加しない**。
要望: ラベルプリンターのドライバーを、ハンディターミナルなどの Android に設定できる、または、選択不要で印刷できることが望ましい。

調査の方法: Web 検索(公開資料。メーカー・標準化団体・OSS のページ)。製品の仕様は、機種の選定のときにメーカーの資料で再確認する(検索の要約は、検証していない)。この環境では、プリンター・サーバーとも実機で試していない。

## 1. 結論(提案)
**印刷は、サーバーで行う。アプリ(Android のハンディターミナル・Windows)は、「印刷の依頼」をサーバーへ送るだけにする。** ドライバー・プリンターの選択がアプリに要らず、要望(5.1)を満たす。
1.  アプリ: 対象(コンテナ・ロット・作業指示書などの `symbol` とメニューの種類)・枚数・ラベルの種類を、サーバーへ送る(認証は、これまでと同じ PocketBase の JWT)。印刷するプリンターは、サーバー側の設定(場所・部署・ラベルの種類ごと)で決め、利用者に選ばせない。
1.  サーバー: プリンターの一覧・状態・ラベルの様式(テンプレート)を持ち、ラベルの印刷データを作ってプリンターへ送る。印刷の記録(誰が・いつ・何を・何枚。再印刷を含む)を、追記のみで残す(プロジェクトの規則「記録は追記のみ」に合う)。
1.  バーコードの中身は、これまでの体系(コード + `symbol`。`barcode_entry/CLAUDE.md`)。`symbol` は DB のトリガーが採番するため、**登録のあとに印刷する**(採番前には印刷できない)。

## 2. 調べて分かったこと
### 2-1. Android から「選択不要」で印刷できるか
1.  Android の標準の印刷は、Mopria・IPP Everywhere を使う「ドライバー不要」の方式で、同じネットワークの IPP プリンターを見つける。ただし、**印刷ダイアログでプリンターを選ぶ**。Flutter の `printing` パッケージの Android 版も、この印刷の枠組みを使うため、選択が要る(要望と合わない)。ゲストの Wi-Fi・クライアント分離のネットワークでは、見つからない([IPP Everywhere](https://pwg.org/ipp/everywhere.html)、[ezeep: ドライバー不要の印刷(倉庫)](https://www.ezeep.com/blog/driverless-printing-warehouse-staff))。
1.  選択なしで印刷するには、(a)アプリが、プリンターの言語(ZPL など)を、TCP 9100 の生のソケットで直接送る、(b)メーカーの SDK・アプリで送る、(c)サーバーに依頼する、のどれか。(a)(b)は、プリンターの IP・機種ごとの言語を、各端末のアプリが知る必要があり、**(c)がいちばん管理しやすい**。
### 2-2. プリンターの言語と、サーバーでの管理
1.  Zebra: ZPL を、ネットワークの TCP 9100 に生で送れる(Link-OS)。Android 用の Zebra Print(印刷サービス)・Browser Print もあるが、アプリからの直接の制御には向かない。9100 を使う別のプログラムがあると競合する([Zebra Print のシステム要件](https://docs.zebra.com/us/en/software/zebra-print-ug/introduction/system-requirements.html)、[Link-OS のベストプラクティス](https://techdocs.zebra.com/link-os/2-12/bestpractices/content/index.html))。
1.  サーバーで共有する方法の 1 つは、CUPS(IPP。`ipp://ホスト:631/printers/名前`)。ラベルプリンターは、片側を「raw」のキューにする(両側でフィルターをかけない)([CUPS のプリンター共有](https://www.cups.org/doc/sharing.html)、[Arch Wiki: CUPS](https://wiki.archlinux.org/title/CUPS))。
1.  もう 1 つは、LPrint(OSS)。ラベルプリンターを、IPP Everywhere・AirPrint・Mopria のプリンターとして見せるスプーラー兼サーバーで、Android・Windows などが、ドライバーなしで使える。対応機種は、ZPL・EPL2・TSPL(TSC は試験的)・Brother QL/PT(試験的)で、SATO・東芝テックは載っていない([LPrint](https://www.msweet.org/lprint/)、[GitHub](https://www.github.com/michaelrsweet/lprint))。
1.  Brother(QL・TD)は、Android 用の SDK と Flutter のプラグイン(`brother_native_print` など。画像・PDF の印刷。Wi-Fi・Bluetooth・USB)がある。P-touch Template(テンプレートを印刷機に持たせて、差し込みの値だけ送る)は SDK にあるが、Flutter のプラグインは見つからない([Brother Mobile SDK の対応機種](https://support.brother.com/g/s/es/htmldoc/mobilesdk/overview/supported-printer.html)、[brother_native_print](https://pub.dev/packages/brother_native_print))。
1.  SATO(CT4-LX など): 自社の Android 用の SDK・アプリ(Mobile All-In-One Tool)・SmaPri ドライバー(HTTP で呼べる)がある。IPP・ドライバー不要で印刷できるかは、確認できなかった([SATO CT4-LX 取扱説明書](https://www.manual.sato-global.com/printer/ct4-lx/main/main_GUID-11EC3401-B40C-49FF-A489-36F25A0BB712.html)、[SmaPri](https://www.satoeurope.com/products/smapri.php))。

## 3. 構成の案
| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| A(推奨) | 印刷の依頼を受けるサーバー(小さなサービス)が、プリンターの言語(ZPL・TSPL など)を作り、TCP 9100 で送る。プリンターは、ネットワーク(有線・Wi-Fi)で固定の IP | アプリは依頼だけ。機種の違いはサーバーで吸収。LPrint・CUPS が要らない | 小さなサービスを作る(Docker。`tools/docker` に置く) |
| B | サーバーに CUPS(または LPrint)を置き、IPP のキューへ、PDF・画像を送って印刷する | 既存の仕組み。ドライバーはサーバーだけ | ラベルの寸法・バーコードの精度(解像度)の調整が難しい。機種により raw が要る |
| C | Android・Windows のアプリが、機種の SDK で直接印刷する | サーバー不要 | 端末ごとにプリンターの設定・SDK が要り、選択が要る。要望と合わない |

認証は、PocketBase の JWT(`GET /api/app/graphql-token` と同じ仕組み)を、サービスの入口で検証する。PocketBase の JS フック(`pb.js`)は、生のソケットが使えないため、印刷は別のサービスに分ける。

## 4. 機種を選ぶときの確認(購入の前)
1.  ネットワーク(有線・Wi-Fi)の接続と固定の IP、生の TCP 9100(または IPP)で受けられる。USB だけの機種は、Docker(Windows)のサーバーから使いにくい。
1.  ラベルの言語が、1 つに決まる(ZPL が、いちばん多くの機種で使える。TSPL・SBPL は、メーカー固有)。
1.  ラベルの寸法・紙(感熱か熱転写か。コンテナの保管環境・耐久・追跡に必要な期間)・解像度(Code 128・QR を、ハンディターミナルが読める細さで印刷できる 203dpi 以上)。
1.  ステータスの取得(用紙切れ・ヘッド開放)を、サーバーが読める。
1.  Android のハンディターミナル側の要件は、**無い**(案 A なら、プリンターの設定・ドライバーを入れない)。
