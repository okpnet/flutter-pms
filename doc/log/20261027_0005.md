## 2. 集約のレビュー(`app_core`)

結論: **`flgtable_lib`などの部品は`app_core`へ集約しない**。理由:

1. `app_core`は機能(`features`層)。ここへ集約すると、`ui`層の`entity_screens`・`flgtable_lib`や他の機能が`app_core`に依存することになり、依存の向き(`apps → features → core → ui/model_providers/infra → foundation`)と「機能同士は`xxx_api.dart`の型だけを使う」規則に反する。
2. `flgtable_lib`の`query_builder`連携は、条件を式にする変換だけで、画面の状態は持たない。`ui`層のままで、使う側(`entity_screens`)が受け取る。

集約した方が保守性の上がるもの(置き場の提案):

| 対象 | 現状 | 提案 |
|---|---|---|
| GraphQLクライアントの提供(`GraphQLClient`の`Provider`、接続先の設定) | アプリに無い | `apps/pms_app/lib/services/repositories`(アプリの配線)。環境ごとの接続先(`--dart-define`)はアプリが決める |
| 取得元の組み立て(`GraphqlDataRepository`+`IQueryState`) | 機能ごとに書くことになる | 機能が`xxx_api.dart`で公開する(`staffCountMetricSource(client)`の形)。クライアントはアプリが渡す |
| 集計値の元の差し込み | `metricSourcesProvider`(既定は空) | アプリの`dashboard_overrides.dart`で各機能の元を並べる(件数の元と同じ) |
| `apps/pms_app/lib/contents`・`extensions`・`constants` | 旧mock_upの残り(`nested_map_flattener`は`pms_graphql`に同等の実装がある) | 使われていないものを確認して削除 |

## 3. 次のステップ(全体をまとめたAppへの移行)の評価

評価: **画面の枠は移行できるが、データの接続はまだできていない**。

準備できているもの:
- ワークスペースの解決・解析。`melos run analyze`は`pms_authenticator`(example)以外で通る。
- モデル生成(10パッケージ)・抜き出しの検証(`gql:check`)・`query_builder`→PostGraphile→`FlatFilterConverter`の変換。
- シェル(`app_shell`)・設定の保存・メンテナンス・セッション確認・ダッシュボード(件数はモック)・各機能の台帳/編集(メモリ上のサンプル)。
- `pms_app`のテスト6件が成功。

ブロックしているもの(優先順):
1. **GraphQLクライアントがアプリに無い**(接続先・ヘッダー・タイムアウトの設定とProvider)。機能の取得元はすべてメモリ上のサンプル。サーバーにも接続していないため、実サーバーでの動作は未確認。
2. **認証**: ログイン画面は未実装(`app_core`)。`pms_authenticator`はセッション確認のみ接続済みで、トークンをGraphQLのヘッダーへ渡す配線が無い。
3. **生成物の準備**: `*.graphql.dart`はGit管理外のため、取得直後は`melos run gql:build`が必要(`melos bootstrap`の手順に含める)。
4. **集計値の表示**: 8つの元の実装と、タイルの表示が未実装(要件待ち)。
5. **テストの状態**: `pms_graphql`の既存2件、`pms_authenticator`の`callback_server_test`2件が失敗(今回の変更とは無関係)。`feature_shared`はテストが無く、`melos run test:flutter`の絞り込み(`dirExists: test`)が空のフォルダを対象にして失敗扱いになる。
6. 実機での起動(`flutter run -d windows`)は、この評価では実行していない。

推奨する順序: (1)クライアントのProviderと接続先の設定 → (2)1機能(例: `shared_master`の配送区分)の取得元(メモリ上のサンプル)をGraphQL版にして実サーバーで確認 → (3)認証のトークンをヘッダーへ → (4)集計値の要件確定。

## 検証
`dashboard_container` 11件、`organization` 6件が成功。ワークスペース全体のテスト(`melos run test`)の失敗は上記5のとおり。
