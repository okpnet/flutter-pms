# 20261107_0002 画面実装

指示: [issue/20261107_0002.md](../issue/20261107_0002.md)

サーバーに接続できない環境で、通常のテストを実施した(サーバー接続のテストと、画面のスクリーンショットによる評価は省略。別の環境で行う)。

## GraphQL にアクセスする前の確認
- ページの切り替え: ルーターの `redirect` が、メンテナンスの確認 → 認証を行っていた(適用済み)。ただし、セッション切れの向け先がログインだったため、セッション切れのページ(`LogoutDestination(sessionExpired: true)`。ログインへの遷移を促す)へ向けるよう変更した(`authRedirect` の `expiredPath`)。
- GraphQL の通信の前: 無かったため追加した。`GraphqlAccessGuard`(`services/graphql/graphql_access_guard.dart`)を `graphqlAuthorizationProvider` の先頭で呼ぶ。メンテナンス中は通信せず、ルーターの評価し直しでメンテナンスのページへ。セッション切れは通信せず、セッション切れのページへ。確認は15秒の間は省く。
- `CLAUDE.md`(ルート)に、これらを追加した。`pms_app` は適用済み。**`apps/entry_app` には適用していない**(未確認の課題)。

## メインフレーム
- APP バー・サイドバーは `AppMainFrame`(`app_shell`)で実装済み。
- サイドバーを権限で絞るようにした(`menuAccessProvider`)。管理者(`role=admin`)はすべて、それ以外は担当者の実効アクセスパスに含まれるページだけ。取り出せないときは出さない。ロールは保持せず、ページのアクセスごとに取り出す。
- ロールの取り出しのため、`pbapi` の `AuthSession` に `role`・`isAdmin` を追加した(`packages/infra/pbapi` の issue・ログに記録)。
- 実サーバー(GraphQL の実効アクセスパス)での確認は未実施。

## ダッシュボード
- ログイン後のトップページは `app_core` のダッシュボードで実装済み。
- 配置の保存先を、ユーザーごとにした(`dashboard_container` に指示。issue・ログに記録)。ユーザーが変わるたびに、そのユーザーの配置を読む(保存が無ければ初期の配置)。従来の共通の配置は引き継がない。

## 設定ページ
- `app_core` の設定ページで実装済み(言語・画面・テーマ・ユーザー)。
- 再起動が必要な項目のまとめ:

  | 項目 | 場所 | 反映 |
  |---|---|---|
  | 使用言語・サイドバーをアイコンだけ・テーマ・表示モード・ユーザー | 設定ページ | すぐ |
  | 画像の変更可否 | 裏設定 | すぐ |
  | 接続先(GraphQL・PocketBase・メンテナンス)、ログのレベル | 裏設定 | 再起動 |
  | サイドバーの既定 | 裏設定 | 次の起動 |

  設定ページの項目は、すべて再起動が不要だった。
- 裏設定の接続先・ログのレベルは、起動時に接続・ログを組み立てるため再起動が必要。再起動を不要にする案(接続の作り直し、ログのレベルの実行時の変更)は、影響範囲が広い(全ライブラリの接続・ログ)ため、今回は行わない。必要なら `logger_provider`・`pms_graphql` の issue に起こす。
