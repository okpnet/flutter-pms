# 20261026_0004 ページ用の拡張・メンテナンス・ダッシュボードの組み込み

指示: `packages/features/issue/20261026_0003.md`・`20261026_0004.md`(アプリへの組み込み、ダッシュボードのページ)。

## アプリのページとライブラリのページの対応(置き換え)
| アプリのページ | ライブラリのページ | 結果 |
|---|---|---|
| ダッシュボード(`Dashboard`・`DashboardRouter`、見出しだけの仮) | `app_core` の `DashboardPage`(`/dashboard`) | 置き換えて削除。`DashboardConstant`(パス・名前)だけ `contents/controls/route/dashboard_constant.dart` に残した(サイドバー・認証の遷移が使う) |
| メンテナンスのお知らせ(`Maintenance`・`MaintenanceRouter`、`/notice/maintenance`) | `maintenance` の `MaintenancePage`(`/maintenance`、枠の外) | 置き換えて削除。アプリのモック(`MockMaintenanceProvider`・`MockMaintenanceApi`・アプリの `MaintenanceStatus`)と、`mock_core_service` のメンテナンスの監視も削除。アプリの文字列(`maintenance`)も削除 |

## 実施
- ルーター(`services/router/root_router.dart`): `standaloneFeatureModules`(`MaintenanceModule`)のルートを `ShellRoute` の外へ追加。`redirect` で、ページの切り替え・更新のたびに `pageSessionMediatorProvider.refresh()` を呼び(メンテナンスページでは通信しない)、`maintenanceRedirect` でメンテナンス中はどのページもメンテナンスページへ向ける。
- `refreshListenable`: `maintenanceStatusProvider` の変化で `redirect` を評価し直す(メンテナンスの終了で、メンテナンスページからダッシュボードへ戻る)。
- セッション確認(`services/session`): `MaintenanceAwarePageSession`(メンテナンスを先に確認)+ `AuthenticatorPageSession`(`pms_authenticator`)。メンテナンスの確認先は `--dart-define=MAINTENANCE_URL`(`HttpMaintenanceChecker`)。
- ダッシュボード(`services/dashboard`): 件数の元のモック、初期の配置。`main.dart` で、設定から配置を復元し、保存が無ければ初期の配置にする。
- `go_router_builder` の生成物を再生成した(`build_runner`)。他のファイルの生成物にも、再生成による差分がある(内容は生成コードのみ)。
- コマンドバスのハンドラ登録・遷移先の解決は、枠の外の機能も含める。

## 確認
- `flutter analyze`: エラー・警告なし(既存の `avoid_print` の情報のみ)。`flutter test`: 6件成功(メンテナンス中は全ページがメンテナンスページになり、再確認で終わるとダッシュボードへ戻る、セッション確認、ダッシュボードの配置と件数)。

## 残り
- 件数の元は暫定のモック(GraphQL の `totalCount` を返す取得元へ置き換える)。
- 認証(`pms_authenticator`)の初期化(`AuthController.init`)とログイン画面は未実施。未初期化のあいだは、セッション確認はログアウトとして返し、リダイレクトの対象にしていない(メンテナンスだけを切り替える)。
