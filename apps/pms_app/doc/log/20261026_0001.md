## 1. エラー修正(`flutter analyze`: error 0件)

ワークスペース化で変わった各ライブラリの API にアプリ側を合わせた。

| 内容 | 対応 |
|---|---|
| `theme_lib` の `textStyleMode(sizeMode:, colorMode:)` が `size: (t) => t.xxx` / `color:` に変更 | 呼び出し側(7ファイル)を修正 |
| `TextFormField.toPrimary` は無い(入力欄はテーマ全体に適用済み) | ログインの入力欄 2か所から削除 |
| `AppTheme.customTheme` が無い | `lightThemeProvider` / `darkThemeProvider` / `themeModeProvider` に置換。ロガーを先に作る必要があるため `main()` を非同期にし、`themeLoggerProvider` / `loggerProvider` を差し込む |
| `package:theme_lib/constants/constant.dart` が無い | `imports.dart` に置換 |
| `ExpressionVisitorType.graphQL` → `graphQl`、`IDataRepository.find` の引数名 `predicate` / `orders` | 追従 |

### ルーター定義の不具合(起動時に例外になっていたもの)
GoRouter は同名のルートを許さないため、アプリは起動できなかった。コピー&ペーストの誤りを修正して `build_runner` で再生成した。

- 品目構成(`TreeItemRouter`)の子に、品目閲覧と同じ `EditItemRouter` を重複定義 → 子を削除(編集は品目閲覧の下の定義を使う)
- `EditEquipmentConstant` の name/path が設備分類編集と同一 → `equipment_edit` / `/orgresources/equipment/edit` に変更し、設備分類編集は `EditEquipmentKindConstant` を使う
- `EditSupplierConstant`(`purchase_order`)、`EditCustomerConstant`(`customer`) の name が閲覧ページと同一 → `supplier_edit` / `customer_edit`
- 未登録だが同名の `RecordsMaterialTransfer` / `RecordsPurchaseRecive` の name → `*_records`

## 3. `features` をライブラリとして参照
`pubspec.yaml` に `feature_shared` と `organization` / `item` / `resource` / `sales` / `purchasing` / `production_plan` / `production_process` / `work_record` / `quality` / `quality_common` / `quality_document` / `system` / `shared_master` を追加。

- `lib/services/features/feature_modules.dart`: 組み込む `FeatureModule` の一覧。
- `lib/services/features/feature_command_bus.dart`: `FeatureHost` と同じ配線(ハンドラ登録・`GoRouterDestinationNavigator`・`DefaultCommandBus`)。`main()` で `commandBusProvider` に差し込む。
- `services/router/root_router.dart`: 既存の `$appRoutes` に加えて、`ShellRoute(UnControlContentsFrame)` の中へ各機能のルートを追加。ライブラリの画面は `AppBar` を持たない(`ScreenScaffold`)ため、アプリの枠の中に入れて二重にならない。
- `DrawerMenu`: 各機能の `MenuContributor` の項目をグループごとに追加(選ぶと `TopLevelDestination` で枠内の画面を入れ替える)。
- `test/feature_wiring_test.dart`: 配線とルーター生成が例外にならないこと、遷移先がパスへ解決されることを確認。

ライブラリの画面は `/e/<実体キー>` で開く。既存の定義(`TypedGoRoute`)と同じ書き方はライブラリ側が非公開の画面を持つため使えず、`RouteBase` をそのまま足した。
