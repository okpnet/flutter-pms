## 2. `app_core` を組み込んだ(ライブラリのページを参照)
- `featureModules` の先頭に `AppCoreModule` を追加。設定(`/settings`)・ログアウト(`/logout`)・エラー(`/error`)はライブラリのページを使う。
- アプリ側の重複を削除した: `LogoutRouter`、`AppSettingRouter`、`UserSettingRouter`、`ContentsErrorRouter` と、そのページ(`logout.dart`、`settings/`、`contents_error.dart`)。
- エラーへの遷移は `errorLocationOf(SpecificError)`(`services/features/feature_error.dart`)に集約した。エラーは文言ではなく種類(`<type>:<code>`)で渡し、画面が表示する。ルーターの `errorPageBuilder` は `onException` に変え、存在しないパスは `/error` へ遷移する。
- `localeProvider` を `SystemLocaleNotifier` に差し替え、使用言語を実行環境(OS)に従わせた(設定画面で変更できる)。
- ブート画面(`/boot`)はアプリのスプラッシュを残した。

## 4. 課題への処置
- 取得元(サンプル → GraphQL): **保留継続**。このアプリのテストで実施する。
- ログイン等の文字列を slang へ移す: ログイン、メンテナンス、グリッドの件数表示、会社情報(ラベル)、未実装の表示を `lib/i18n` へ移した。
  - **未対応**: 一覧のグリッド列名 178件(`TrinaColumn` の `title`)。モックのままで、置き換え先のライブラリ画面は列名を DB のコメント(`schema.graphql`)から持つため、画面を置き換える時に不要になる。移す場合は列名の方針を決めてから行う。
  - 会社情報の `XXX会社` などのダミー値は文言ではないため、そのまま。
- 警告: 未使用の変数・フィールド・インポート・関数を削除した(76件 → 0件)。残る 17件は `avoid_print`(info)で、未使用ではないため触っていない。

## 5. 再リストアップ(推論・対応できない項目)
1. 品目構成ツリー、出荷管理、出荷梱包、在庫状態に対応するライブラリの実体が無い。ライブラリ側に追加するか、アプリのモックを残すかの判断が必要。
2. ダッシュボードとログインは `app_core` に無い(認証導入時に追加予定)。
3. `ContentsTitle` などアプリ共通部品の AppBar 重複: ライブラリ画面は `UnControlContentsFrame` の中に入れてある。ログアウト画面の「ログインする(仮)」は `/login` ではなく標準ユーザーに戻す動作で、アプリのログイン画面とは結び付いていない。
4. `app_core` の設定画面が保存する設定(言語・サイドバー・ユーザー)の保存先は未選択(標準はメモリ上)。`settings_keeper` を選ぶ作業が残っている。
5. 工程・工程計画・資材計画の未登録ページ(上記)は、置き換え後に削除してよいか確認が必要。
