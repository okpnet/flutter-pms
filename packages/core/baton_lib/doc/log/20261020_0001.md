# 生成結果 2026-10-20 #0001(issue/20261020_001.md)

ロガーをRiverpod経由で共通化する仕様を実装した。

## 変更
- `lib/src/command_logger_provider.dart` 新規。`commandLoggerProvider`(`Provider<ILoggerProvider>`)。アプリ側が`overrideWithValue`で共通ロガーを差し込む。未差し替えは`StateError`。
- `DefaultCommandBus`: `logger`を`ILoggerProvider`の必須引数に変更(`logger`パッケージ直接利用を廃止)。エラーは`[baton_lib]`接頭辞付きで`error`出力。
- `pubspec.yaml`: `logger`を削除、`flutter_riverpod ^3.4.3`(ワークスペース管理と同一)と`logger_lib`(path)を追加、`publish_to: none`。
- バレルファイルに`command_logger_provider.dart`を追加。
- テスト: `test/fake_logger.dart`、`test/command_logger_provider_test.dart`を追加。既存テストはFakeLoggerProviderへ置換。

## Widgetを使わないことの課題・代替案の検討
- 課題なし。`Provider`と`ProviderContainer`は`Ref`のみで動作しWidget不要。テストでも`ProviderContainer`で検証済み。
- 留意点1: `flutter_riverpod`はFlutter依存だが、本ライブラリは元々Flutterパッケージのため問題なし。純Dartにする場合は`riverpod`への切替が代替案。
- 留意点2: 共通ロガーの`Provider`はアプリ全体で1つが望ましく、本来は`logger_lib`/`logger_provider`側で定義すべき。現状は未定義のため`commandLoggerProvider`を暫定で置いた。そちらが整備されたら、アプリ側で`commandLoggerProvider.overrideWithValue(共通ロガー)`とつなぐか、本Providerを置換する。
- 留意点3: `logger_lib`の`ILoggerProvider`は`{Object ex, StackTrace trace}`が非null型のため、スタックが無い場合は`StackTrace.current`、causeが無い場合は例外自体を渡している。`Object? ex`への修正を推奨。
