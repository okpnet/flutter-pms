# 20261025_0001 設定保存プロジェクト(settings_keeper)の追加

## 入力
`issue/20261025_0001.md`

## 提案したプロジェクト名
`settings_keeper`(`packages/core/settings_keeper`)。「設定を預かる管理者」で、メメントの管理者(Caretaker)の役割を表す。
他の候補: `settings_memento`(パターン名だけで保存手段の差し替えが伝わらない)、`settings_store`(保存手段そのものと紛らわしい)。

## 設計
| パターン | 型 | 役割 |
|---|---|---|
| Memento | `SettingsMemento` | 設定の写し(key・version・savedAt・JSON値)。不変 |
| Memento(Originator) | `SettingsOriginator` | 持ち主。`createMemento`/`restoreFrom` |
| Memento(Caretaker) | `SettingsKeeper` | 保存・復元・削除。失敗はログに残して`false` |
| Strategy | `SettingsStorage` | 保存手段の差し替え口 |
| Strategy | `FileSettingsStorage` | `<key>.json`。一時ファイル→置き換えで書く |
| Strategy | `InMemorySettingsStorage` | 保存しない(既定、テスト用) |
| Riverpod | `settingsStorageProvider`、`settingsKeeperProvider` | アプリが前者を上書きして手段を決める |

## 判断したこと
- 既定の保存手段はメモリ。上書き忘れで設定が消える恐れがあるが、`loggerProvider`の未登録時の既定(Noop)と同じ考え方で、アプリを落とさないことを優先した。ファイルを既定にしない理由は、保存先のフォルダ(アプリのサポートフォルダ等)をこのライブラリが決められないため。
- 追加パッケージは無し(`dart:io`のみ)。保存先のパスを得る`path_provider`はアプリ側で使う。
- 識別子はファイル名になるため、`[a-z0-9][a-z0-9_.-]*`以外と`..`を拒否する。
