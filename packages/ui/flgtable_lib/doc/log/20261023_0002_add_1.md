# 20261023_0002_add_1 ツリーのドラッグで親を変えて取り消すと、移動先に行が残る不具合

## 原因
1. **example のデータが戻っていなかった(報告の症状の原因)**: データの実体はアプリ側が持つため、親の付け替えを取り消した/やり直したときは、`onUndone`/`onRedone`(`parent` に適用後の親が入る)でアプリがデータの親を戻す必要がある。example のツリーは通知をログに出すだけで、`Org.parent` を戻していなかった。そのため、取り消した後に移動先を展開すると、データ上の親が移動先のままの行が子として読み込まれ、移動先に1行増えて見えた
2. **ライブラリの不具合(あわせて修正)**: 子を読み込んでいない親へ移動した行を取り消すと、その親の子の数(`childCount`)が +1 のまま残った。行は親の子として入っていない(子の数だけ更新する仕様)ため、取り消しで外す処理が早期に抜けていた。子のない行(▷)へ移動して取り消すと、移動先が▶のままになる

3. **取り消しが古いノードを動かしていた(再発の原因。「移動 → 移動先を展開 → 取り消し」)**: 子を読み込んでいない親へ移動した行は、親の子の数だけ更新し、行(ノード)は親の子に入れない。その後、移動先を展開して読み込むと、同じ行の別のノードが作られて登録し直される。取り消しは移動時に掴んだ古いノードを元の親へ戻すだけで、読み込みで作られた移動先のノードが残った(元の親には戻るが、移動先の子として残る)。やり直しも同様

## 修正
- `lib/tree/tree_table.dart` の `_detach`: 子を読み込んでいない親から外すときは、子の数だけを減らす
- `_reparent`: 取り消し/やり直しは、その時点のノード(キーで`_nodes`から引く)を動かす
- example(`tree_cases.dart`): `onUndone`/`onRedone` で、親の変更(`TableOperation.parentChange`)のとき `item.parent = e.parent?.id` としてデータにも反映する

## テスト
- 本体: 移動先が未展開/展開済みのそれぞれで、取り消し・やり直しの後に移動先の行が増減しないこと、子のない行へ移動して取り消すと▷に戻ること(修正前は失敗することを確認)
- 本体: 移動 → 移動先を展開(読み込み) → 取り消し → やり直し で、移動先と元の親のどちらにも行が重複・残存しないこと(修正前は失敗することを確認)
- example: 同じ操作(本社 第5部 を 支社A 第1部 へ移動 → 展開 → 取り消し/やり直し)
- example: 取り消し後に移動先(支社A)を展開しても、移動した行が現れないこと。やり直しでは移動先(読み込み済みなので開く)に1行見えること
