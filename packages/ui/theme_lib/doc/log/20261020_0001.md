## 2. 新しい構成

```
lib/
  theme_lib.dart            バレル(これだけ import すればよい)
  model/                    ThemeDefinition / ThemePalette / ThemeMetrics(JSON入出力・検証)、ThemeState、例外
  build/                    ThemeBuilder(定義→ThemeData)、組み込みテーマ
  manager/                  ThemeManager(Notifier)と各 Provider、ロガー Provider
  tokens/                   SpaceField / BorderField(ThemeExtension)
  extensions/               ボタン等のバリアント変換、検索窓、余白、文字
```

- 細分化は5機能のため CLAUDE.md の規則どおり1階層(`lib/xxx`)。
- 依存追加: `flutter_riverpod`(バージョンはルートの melos 設定どおり)、`logger_provider`(ロガー型 `ILoggerProvider` のため)。
  `json_theme_plus` は**採用しなかった**: 取り込み対象は ThemeData 全体ではなく、配色・寸法の少数項目に絞った独自スキーマで足り、
  未知キーまで厳密に検証したいため。
- ロガーは `baton_lib` の `commandLoggerProvider` と同じ方式(`themeLoggerProvider` をアプリが `overrideWithValue`)。
  ログは theme_lib 自身の失敗のみで、先頭が `[theme_lib]`。

## 3. 設計上の判断

- **JSON スキーマ**: `schemaVersion` / `id` / `name` / `fontFamily` / `light` / `dark` / `metrics`。未知キー・範囲外の数値・不正な色は
  `ThemeFormatException(path, reason)` で拒否し、状態は変更しない。`dark` 省略時は `light` のシード色からダーク配色を生成。
- **オンザフライ**: `ThemeData` は `activeThemeProvider`(定義の `==` で変化検知)から生成するため、モード切替だけでは再生成されない。
- **インスタンスの JSON 化**: `ThemeDefinition` / `ThemeState` / `SpaceField` / `BorderField` / 例外に `toJson()`。復元目的では使わない。
- **削除できるテーマ**: 組み込み3種は削除不可(`ThemeProtectedException`)。それ以外は削除でき、適用中なら先頭の組み込みへ戻る。
