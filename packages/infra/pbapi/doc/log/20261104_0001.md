# 20261104_0001 アバター(user_avatars)の追加

指示: `packages/features/issue/20261104_0007.md`(管理者によるユーザー画像の追加)の `pbapi` 側。サーバー側(`tools/docker/pocketbase`)は変更済みで、仕様は `tools/docker/pocketbase/README.md` の「9. ユーザーアバター」。

## Issue との差(サーバーの実装に従った点)
Issue は案A(`users.updateRule` に管理者の例外を足し、`users.avatar` を使う)だったが、サーバーは専用のコレクション `user_avatars` として実装された(`users.avatar` は書き込みを拒否する)。クライアントはサーバーの実装に合わせた。

## 追加・変更
- `AvatarService`(`lib/src/avatar/avatar_service.dart`): `find`・`findMany`(50件ずつ)・`set`(登録または差し替え)・`delete`・`download`(任意でサムネイル `128x128` / `256x256`)。`avatarServiceProvider` を追加。
- `UserAvatar`: 識別情報(レコードID・ユーザーID・画像のファイル名・更新者)。`cacheKey` は画像のファイル名から作る(URL の token は毎回変わるため)。
- `fetchRecordFile`: ファイル項目名(`field`)とサムネイル(`thumb`)を指定できるようにした(共有ファイル・個人ファイルの既定は従来どおり `file`)。
- **破壊的変更**: `AccountService.updateProfile` から `avatarBytes`・`avatarFilename` を削除した(サーバーが `users.avatar` への書き込みを拒否するため)。使用箇所はテストだけで、アプリ・機能には無い。

## 確認
- `flutter analyze`: 既存の info 1件のみ(`personal_file_service.dart` の `prefer_initializing_formals`。今回の変更とは無関係)。
- `flutter test --exclude-tags server`: 56件成功(新規 `test/avatar_test.dart` 8件: 取得・未ログイン・まとめて取得・登録と差し替え・権限なし・削除・画像の取得とサムネイル・不正な引数)。
- 実サーバーに対する通信テストは未実施(サーバーのデータを変更するため)。必要なら、使い捨てのユーザーでの通信テストを `server` タグで追加する。

## 課題・提案
1. `GET /api/app/users/{id}/avatar`(Authorization ヘッダーだけで取得できる302の入口)は使っていない。`Image.network` で直接表示したい画面(担当者一覧)が出たら、`AvatarService` に URL とヘッダーを返すメソッドを足す。
2. `AuthSession` にアバターは持たせていない(`find(session.userId)` で取る)。ログインのたびの追加の問い合わせを避けたいなら、`user_profile` 側で取得結果をキャッシュする。
3. 画像の縮小(EXIF 除去)は、画像を扱う側(`user_profile`)の責務。
