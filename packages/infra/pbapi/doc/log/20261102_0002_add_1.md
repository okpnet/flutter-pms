# 20261102_0002_add_1 実サーバーでの結合テスト

指示: 接続できなかった結合テストを、`http://192.168.9.245:8090/api`で実施する(接続できないときの代替アドレス)。管理者の資格情報は`tools/docker/pocketbase/.env`から実行時に読み、画面・ファイルには出していない。

## 実施
- `pocketbase_server_test.dart`(2件)と`pocketbase_integration_test.dart`(9件)が、実サーバーですべて成功した。後始末(利用者・ファイル・一時コレクション・申請)は`tearDownAll`で行う。
- 追加したテスト: **申請 → 一覧 → 承認(`activate`)→ コード入力 → ログイン → 無効化**。無効化後は既存のセッションが無効になり、新しいログインも通らず、再有効化できることを確認した。
- 既存のテスト(有効化前はログインできない・コードは二度使えない・コード誤りとユーザーIDの誤りが同じ`validation`・パスワード変更・共有/個人ファイル・再設定の依頼)も新仕様で成功した。

## 見つかったこと(修正済み)
**無効・未承認のユーザーが正しいパスワードでログインすると、サーバーは400ではなく403(コレクションの認証条件を満たさない)を返す。** そのままでは`forbidden`になり、「パスワードは合っているが入れない」ことがわかってしまう(「ログインできない理由は区別しない」に反する)。`SessionService.login`で403を`invalidCredentials`に読み替えた(ステータスはそのまま保持)。単体テストを追加。

## 注意
- 全テストを続けて実行すると、ログインのレート制限(同一IPで1分10回)に当たって追加のテストが失敗することがあった(1分あけて単独で実行すると成功)。続けて実行するときは1分以上あける。
