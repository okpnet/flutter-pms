# 20261026_003 出荷・棚ビジターの追加

指示: [issue/20261026_003.md](../../issue/20261026_003.md)

## 結果
- 全量スキーマに `TransShippingOrder` / `TransShippingOrderDetail` / `TransShippingOrderDetailRecord` / `TransVisiter` / `TransConvey` は存在したが、viewsに画面(`~Page`)が無かった(`trans_visiter`は「親に`~Page`が無いビュー」として0055で対象外だった。今回、在庫状態の主画面として`VisiterPage`を追加)。
- 追加した画面(各 read / edit / rfe): `shipping_order_page`、`shipping_order_detail_page`、`shipping_order_detail_record_page`、`visiter_page`、`convey_page`。
  - viewsは `tool/scaffold_view.dart` の出力のまま(列・参照・子のレコード数を含む)。列の過不足・参照先のタグの見直しは、画面を使う段階で行う。
  - `transOrderId`・`transContainerId`・`locationId`・`staffId` などの参照列はIDのまま(選択画面は機能側で用意する)。
- 手順: `gen_view_graphql`(エラー0件)→ `lib/graphql` へ採用 → `prune_schema` → `gen_filter_spec`(39ファイル)→ build_runner(`--build-filter`で5画面)。
- build_runnerの出力は5画面で16ファイル。`--delete-conflicting-outputs` が `--build-filter` の対象外の既存モデル(114ファイル)を削除したため、`git checkout` で復元した。**今後は filter 付きのとき `--delete-conflicting-outputs` を付けない**。
- テスト: `flutter test`(`dart test` は Flutter を読み込めず失敗する) 178件通過。
