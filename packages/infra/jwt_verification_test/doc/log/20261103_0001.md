## 適用した権限: 検証用 DB(PostgreSQL)
適用前の状態(実測)と、適用した SQL。
PostgreSQL `192.168.1.101:5432` の実測:
- `authenticator`(PostGraphile が接続するロール)がメンバーになっているのは `tester_admin` と `pms_anonymous` だけ。**`pms_user` と `pms_admin` には切り替えられない**(`tools/docker/postgresql/scripts/05_init_test.sql` の `GRANT pms_anonymous, tester_admin TO authenticator;`)。
- `pms_user` はスキーマ `tests` の `USAGE` を持たない(`09_grant_test.sql` は `pms_admin, tester_admin` にだけ付与し、旧 `tester` への付与を `pms_user` に引き継いでいない)。

適用した SQL(私の実行は自動モードの判定で拒否されたため、ユーザーが適用した。適用後に全テストが成功):
```sql
GRANT pms_user, pms_admin TO authenticator;
GRANT USAGE ON SCHEMA tests TO pms_user;
```
Docker のファイルへの提案(**変更していない**。指示があるまで行わない):
- `tools/docker/postgresql/scripts/05_init_test.sql`: `GRANT pms_anonymous, pms_user, pms_admin, tester_admin TO authenticator;`
- `tools/docker/postgresql/scripts/09_grant_test.sql`: `GRANT USAGE ON SCHEMA tests TO pms_user;`(あわせて、関数・シーケンスの `pms_user` への権限を確認)
- **要確認**: `pms_user` に付与されているのは `SELECT, UPDATE, DELETE` で `INSERT` が無い。登録(`kind: create`)を一般の利用者に許す設計かを確認する。

適用後に全30件の成功を確認した。

## 実装した変更
1. `pms_graphql`(エラーの分類)
   - `SessionExpiredError`(`ServerError` の一種。`reason`: `expired`/`invalid`/`missing`)、`PermissionDeniedError`、`SessionUnavailableException` を追加。401→`expired`、JWT の失敗と分かる 403→`invalid`、`permission denied…`(HTTP 200/500)→`PermissionDeniedError`。既存の「401/403 は `ServerError`」の期待は、`SessionExpiredError` が `ServerError` の一種のため保たれる(`data_test_harness` のテストも成功)。
   - 理由: 12モデルの結果を型で見分けて、画面が「取り直す」か「ログインへ戻す」かを決められるようにするため。
2. `pbapi`(**不具合の修正**): `SessionService.login` が、取得済みの GraphQL 用 JWT を捨てていなかった。**ログアウトせずに別の利用者でログインし直すと、前の利用者の JWT(担当者のID・ロール)が使い回される**(権限の取り違え)。ログイン時に破棄するようにし、テストを追加。
3. `pms_app`: `graphqlAuthorizationProvider` が、ログインしていない・JWT を取得できないときに、ヘッダーなしで送るのをやめ、`SessionUnavailableException` を投げる(通信しない)。ヘッダーなしで送ると匿名のロールで `permission denied` になり、セッション切れと区別できないため。認証サーバーに接続できないだけなら `transient: true`(`NetworkError`)。`pubspec.yaml` に `pms_graphql` を追加。
4. `packages/infra/jwt_verification_test`(テスト専用): 上の3つのテスト、サポート(JWT の偽造・管理者による使い捨て利用者の作成と削除・要求の計数)。12モデルの読み込みの問い合わせを1つずつ使う(`shared_master_model` は読み込みの問い合わせが無い)。

## 判断
1. **JWT の暗号化は行わない**。JWT は(a)メモリ上だけに置く(`ITokenStore` には保存しない)、(b)15分の短命、(c)同じプロセスの攻撃者は暗号鍵も読めるため、暗号化しても防げない。速度を落とす理由もない。PocketBase 自身のトークン(7日)は永続化されるので、`ITokenStore` を安全な保管庫(`flutter_secure_storage`)で実装する方針は変えない。
2. **匿名は「セッション切れ」にしない**。PostGraphile は、JWT なしと権限不足を区別できない(どちらも `permission denied`)。そこで、アプリが JWT を用意できないときは通信せずに `SessionExpiredError(missing)` にし、匿名で送った結果は `PermissionDeniedError` とした。
3. **モデルは12パッケージの読み込みを1つずつ**検証した。同じ認証の経路(`AuthLink`→PostGraphile)を通るため、1パッケージ1つで十分と判断。全読み込みの網羅が必要なら `model_probes.dart` に足す。
4. 偽造した JWT のテストは、鍵(`PMS_TEST_JWT_SECRET`)が渡されたときだけ行う。渡されなければ、その部分が中止(skip)になる。

## リスクと対応案
| # | リスク | 状態 | 対応案 |
| --- | --- | --- | --- |
| R1 | **`tools/docker/postgraphile/.env` が Git で追跡され、JWT の鍵(64文字)と DB のパスワードが未コミットの変更に入っていた** | **対応済み** | 追跡を外し(`git rm --cached`)、`tools/docker/postgraphile/.gitignore` に `.env` を追加、秘密を空にした `.env.example` を置いた。鍵はどのコミットにも入っていない(確認済み)。万一コミットした場合は鍵を再発行 |
| R2 | **`exp` の無い JWT も検証を通る**(PostGraphile)。PocketBase は常に `exp` を付けるが、鍵が漏れると期限のない JWT を作れる | 既知(`postgraphile_jwt_test` に現状を記録) | PostGraphile 側で期限を必須にする(`jwt.verify` の `maxAge` は `iat` が要るため、PocketBase の発行フック `50_graphql_token.pb.js` に `iat` を足す)。docker-compose の変更は提案のみ |
| R3 | **発行済みの JWT は、利用者を無効化・削除しても、期限(最大15分)まで有効**(ステートレスな JWT の性質)。新しい JWT は得られない(テストで確認) | 設計上 | 重要な操作は TTL を短く(`PB_GRAPHQL_JWT_TTL_SECONDS`)。即時に止める必要があれば、DB 側で `staff_id` の有効性を確認する |
| R4 | 共通鍵(HS256)の漏えい = 任意のロール(`pms_admin` を含む)の JWT を偽造できる。鍵が無ければ、改ざん・ロールの昇格は不可(テストで確認) | 設計上 | 鍵を定期的に再発行。強い値を使う(現在は64文字)。鍵を Git に入れない(R1) |
| R5 | 期限の許容(`PGL_JWT_CLOCK_TOLERANCE=30`)だけ、期限切れの JWT が受理される | 確認済み(許容内は通る) | 必要なければ短くする |
| R6 | 別の利用者でログインし直したとき、前の JWT を使い回す(`pbapi`) | **修正済み** | — |
| R7 | JWT なしのリクエストがエラー(`permission denied`)になる。データは返らない(テストで確認) | 想定どおり | — |
