# 20261103_0001_add_1 書き込み(ミューテーション)を JWT で行うテスト

指示: 20261103_0001 の「未実施」のうち、「書き込みを JWT で行うテスト」(`pms_user` に `INSERT` を追加したので試す)。
対象: PostGraphile `http://192.168.1.100:5000/graphql`(モデルは `access_control_model` の「アクセスパス」`AccessPathPage` の Create / Read / Remove)、PocketBase `http://192.168.1.103:8090/api/`。

## 結論
| ケース | 結果 |
| --- | --- |
| 管理者(`pms_admin`)の JWT: 登録 → 読み込み → 論理削除 → 復元 | **○** |
| 期限切れの JWT: 登録・論理削除とも `SessionExpiredError(expired)`。行は作られず、論理削除もされない | **○** |
| 改ざん(ロールを `pms_admin` に書き換え)・別の鍵の署名: `SessionExpiredError(invalid)`。何も変わらない | **○** |
| 匿名(JWT なし): `PermissionDeniedError`。何も変わらない | **○** |
| セッションを破棄(ログアウト): `SessionExpiredError(missing)`。サーバーへ送らない | **○** |
| 一般(`pms_user`)の JWT: 既存の行を論理削除・復元 | **×** `permission denied for table history_info_access_path` |
| 一般(`pms_user`)の JWT: 登録 | **×** `permission denied for table info_access_path` |

7件中5件が成功、2件が `pms_user` の権限で失敗。**検証用 DB `test_avocado` では、`pms_user` に `INSERT` 権限がまだ付いていない**(読み取りのみで確認):
- `pms_user` に `INSERT` がある `tests` のテーブルは、247 中 **0**。`info_access_path` も `history_info_access_path` も false。
- `pms_user` の `SELECT`・`UPDATE`・`DELETE` と、スキーマの `USAGE` は有効。`pms_admin` は全権限。
- 追加済みとのことだが、この DB(`192.168.1.101:5432` の `test_avocado`、スキーマ `tests`)には反映されていない。別の DB・スキーマ・ロールに付けた可能性がある。

**論理削除(UPDATE)でも `INSERT` が要る**: 行を更新すると履歴テーブル(`history_*`)へ書き込まれる(トリガー)。そのため、`pms_user` には `INSERT` が、本体のテーブルだけでなく `history_*` にも要る。必要な SQL(**未適用。適用していない**):
```sql
GRANT INSERT ON ALL TABLES IN SCHEMA tests TO pms_user;
GRANT USAGE ON ALL SEQUENCES IN SCHEMA tests TO pms_user;
```
適用後、`mutation_session_test.dart` を再実行して、残り2件を確認する(`usage.md`)。

## 実装
- `pms_graphql`: `GraphQLClientProvider.mutate(MutationOptions)` を公開した。ミューテーションの結果を、`query` と同じ分類(`SessionExpiredError`・`PermissionDeniedError` など)で受けるため。単体テストを追加。
- `test/mutation_session_test.dart`: 上の7ケース。登録に要る `info_app_id`(既存のアプリ)と `names`(既存の呼称 `shared_appellations`)は、既存の行から引く(どちらも NOT NULL)。
- `test/support/app_authorization.dart`: アプリの `graphqlAuthorizationProvider` と同じ振る舞いの認証ヘッダー(`model_session_test` と共用)。

## 後始末(要確認)
- テストが作った行は、`usecase_path` が `jwt-test/…` の **12行**。すべて論理削除済み(`remove = true`)。GraphQL に物理削除の口は無く、DB へ直接の削除は行っていない。邪魔なら DB で `DELETE FROM tests.info_access_path WHERE usecase_path LIKE 'jwt-test/%'`(履歴 `history_info_access_path` が参照している場合は先に履歴)。
- PocketBase の使い捨て利用者は削除済み。

## 見つかったこと
- アクセスパスの登録は、`info_app_id`(アプリ)と `names`(呼称)が必須。画面から登録するときも、アプリと呼称の選択が要る。
