# 20261111_0001 サーバーを使うテストに JWT を付ける

指示: `flutter-pms/issue/20261111_0002.md` の実行中に見つけた不具合([issue/D_20261111_0001.md](../../issue/D_20261111_0001.md))。指示元の記録は `flutter-pms/doc/log/20261111_0002.md`。

## 問題
`TestServer` は `Authorization` を付けずに PostGraphile へ要求していた。再構築後の PostgreSQL は匿名ロール(`pms_anonymous`)にスキーマ `tests` の USAGE を与えていないため、サーバーを使うテストが `permission denied for schema tests` で失敗した。

## 対応
1. `TestToken`(新規): アプリと同じ手順で JWT を取る(PocketBase `POST /api/collections/users/auth-with-password` → `GET /api/app/graphql-token`)。資格情報は `--dart-define` または環境変数の `PMS_TEST_USER`・`PMS_TEST_PASSWORD`(接続先は `PMS_TEST_POCKETBASE_URL`、既定 `http://192.168.1.103:8090`)。コード・Git には書かない。取得した JWT は一時フォルダに期限(60秒手前)まで共有し、PocketBase のログイン制限(同一 IP で 1 分 10 回)を避ける。例外にパスワード・トークンを含めない。
1. `TestServer.connect` が、資格情報があれば `Authorization: Bearer` つきの `GraphQLClientProvider` を作る(`authenticated`)。資格情報が無ければ従来どおり匿名。
1. 自前で `HttpLink(server.url)` を作っていたテストを、`server.provider.headers` を付けるように直した(`production_plan` の `graphql_mrp_gateway_test`、`barcode_entry_model` の `scan_client_test`)。
1. `CLAUDE.md` に、使い方(一般ユーザーで実行する・資格情報の渡し方)を追加。

## 確認(PostGraphile 192.168.1.100・PocketBase 192.168.1.103。一般ユーザー `tanaka`、role=user → `pms_user`)
- `*_model` 15 パッケージ(新しい `supply_model`・`plan_change_model`・`return_model` を含む): 全て通過(サーバーの読み取り + 代役サーバー)。
- `production_plan`(MRP の実行 `mrp_execute` を含む。`pms_user` で実行できる)・`purchasing`・`sales`・`organization`・`resource`・`dashboard_container`・`data_test_harness`: 通過。
- `pms_graphql`: 2件失敗(`GraphQLConverterCollection.hasConverter`/`getConverter`)。今回の変更とは無関係(変更を退避しても同じ)。別件。

## 注意
- 資格情報を渡さないと、サーバーを使うテストは匿名で実行され、権限エラーで失敗する(従来どおり。黙って skip にはしない)。
- テスト用の一般ユーザーは `tools/init/test_user_init.bat` で用意する。
