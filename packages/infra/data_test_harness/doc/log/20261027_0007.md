# 20261027_0007 AppとGraphQLのバイパス — 案の選択と実施結果

指示: [issue/20261027_0007.md](../../issue/20261027_0007.md)

## 現状の確認
- 実際の依存は、`pms_graphql`(infra)が`data_strategist`(foundation)に依存する向き。`GraphqlDataRepository`が`IDataRepository`を実装し、GraphQLの実行は`fetch`関数で外から渡す。つまり`foundation`・`features`は、すでにGraphQLの接続を知らずに済む作りになっている。
- 残っている問題は「テスト」だけ。
  - テスト接続先のURLが3か所に重複(`organization_model`のテスト、`pms_graphql/CLAUDE.md`・`dart_test.yaml`、ルート`pubspec.yaml`のスキーマ取得)。
  - `foundation`・`features`の単体テストで、取得元を差し替える道具が無い。

## 案の評価
| 案 | 評価 |
|---|---|
| 1 テスト用の`data_strategy`↔`pms_graphql`を持つプロジェクト | **採用**。テスト専用で、接続先と代役を一か所にできる |
| 2 `foundation`↔`data_strategy`↔`pms_graphql`をまとめるプロジェクト | 不採用。`features`が本番でこれに依存し、接続先が本番に入る(「接続先を残したくない」に反する)。`foundation`がinfraを含むと依存の向き(下の層は上を知らない)にも反する |
| 3 テストだけ`foundation`・`features`が`data_strategy`↔`pms_graphql`を直接参照 | 不採用。接続先・skipの扱いが各パッケージに複製される。`data_strategist`が`pms_graphql`をdev依存にすると循環する |

## 実施
プロジェクト名の提案(採用は1つ目): **`data_test_harness`**(テストの治具。本番に入らないことが名前でわかる)、`pms_testkit`(短いが何のテスト用か曖昧)、`graphql_testbed`(GraphQL以外の代役を含む範囲を表せない)。

1. `packages/infra/data_test_harness`を追加(`packages/*/*`のため、ルートpubspecの編集は不要)。`CLAUDE.md`(issueの規則+固有規則)を追加。
   - `TestServer`: 接続先の候補から先に接続できたものを選び、`GraphQLClientProvider`を作る。
   - `serverTest`: `server`タグ付き。接続できなければ中止(skip)。
   - `RecordingDataRepository<R>`: `IDataRepository<R>`の代役(呼び出しを記録して結果を返す)。
2. 循環の回避: `data_strategist`・`query_builder`のテストはこのライブラリに依存せず、`RecordingDataRepository`を使いたい側(`features`など)が`dev_dependencies`に加える。GraphQLを通した検証は`pms_graphql`・各`*_model`の側で行う。
3. `organization_model`の実接続テストを移行(接続先の重複を解消。`dev_dependencies`に追加、`dart_test.yaml`に`server`タグを宣言)。
4. `pms_graphql/CLAUDE.md`のテスト接続先の記述を、`data_test_harness`が持つ旨に更新。ルート`CLAUDE.md`に反映。

## 確認
- `data_test_harness`のテスト6件成功(記録・結果の優先順位・接続先の選択・接続不能・dev依存のみの検査)。
- `organization_model`の`client_provider_server_test`3件が、実サーバーに接続して成功。
- `dev_dependencies`以外に書かれていないことを、ワークスペース全体の`pubspec.yaml`で検査(上のテスト)。

## 未対応・要判断
- `pms_graphql`自身のテスト(接続先はコメントと`dart_test.yaml`のみ)は、循環を避けるため`data_test_harness`に依存できない。サーバーを使うテストを足す場合は、`pms_graphql/test/`側に置く。
- 各`features`の単体テストを`RecordingDataRepository`へ置き換えるのは、機能ごとのIssueで行う(現状の`organization`は`GraphQLClient`を引数で受けており、すでに差し替え可能)。
