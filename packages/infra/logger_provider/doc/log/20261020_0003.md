# 20261020_0003 共有 `loggerProvider`(Riverpod)の提供

指示: [issue/20261020_002.md](../../issue/20261020_002.md)

## 判断(責務の分離)
候補: (1) 利用側が `ILoggerProvider?` を受け取り null なら何もしない / (2) 利用側が非 null の `ILoggerProvider` を受け取る。

**(2) を採用。** 理由:
- 「ロガーが無いときの振る舞い」はロガー提供側の責務であり、利用側(feature 等)に null 判定を分散させない。
- 利用側は `ref.watch(loggerProvider).info(...)` の単一の書き方で済み、`?.` の付け忘れが起きない。
- 未登録時は何もしない `NoopLoggerProvider`(Null Object)を既定値として返すので、(1) の「null なら何もしない」挙動も保たれる。
- 指示案の `Provider<ILoggerProvider?>` は `Provider<ILoggerProvider>` に変更した。

## 変更
- `lib/src/noop_logger_provider.dart`: `NoopLoggerProvider`(`level` は `Level.off`)。
- `lib/src/shared_logger_provider.dart`: `final loggerProvider = Provider<ILoggerProvider>(...)`。既定値は `NoopLoggerProvider`。
- `lib/src/_src.dart`: 上記2ファイルを export。
- `pubspec.yaml`: `flutter_riverpod: ^3.4.3`(ルート melos 管理の版)を追加。
- `test/shared_logger_provider_test.dart`: 2件追加。
- `doc/contents/usage.md`: Riverpod での使い方を追記。
- `CLAUDE.md`: 共有 Provider の方針を統合。
