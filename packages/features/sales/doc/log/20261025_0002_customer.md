# 20261025_0002 customer: 課題への対応(features/doc/log/20261025_0002.md の実行)

## 対応結果
1. データ取得: `ICustomerRepository`(`data_strategist` の `IDataRepository<List<Customer>>` を拡張)と `customerQueryStateProvider`(`QueryState`)を追加。一覧は `facade.execute(PredicateModel)` 経由。ハンドラ・編集・選択も `customerRepositoryProvider` 経由に変更。
2. ログ: `logger_provider` を dependencies へ移し、`ref.read(loggerProvider)` で直接取得。顧客機能が発生元のエラー(取得・更新失敗)だけ `[customer]` 付きで出し、ハンドラは再スローする。
3. 台帳: `CustomerListPage` を `FlgTable`(`flgtable_lib`)に変更。列は `code/name/mail/phone`、ソート・フィルタ有効、行の操作で編集へ遷移。
4. `customer/doc/log`・`doc/contents`・`issue` を作成。
5. `customer_api` の `CLAUDE.md` は作らない(`customer/CLAUDE.md` に集約)。

## 付随変更
- `apps/pms_app`: `flgtable_lib` が使う `themeLoggerProvider` が未 override だと台帳が例外になるため、`main.dart` で同じロガーを override し、`theme_lib` を依存に追加。
- pubspec(customer): `data_strategist`、`flgtable_lib`、`logger_provider` を追加、`theme_lib`(テスト用)を dev に追加。ルート pubspec の変更は不要だった。

## 確認
`flutter analyze`(customer, pms_app)問題なし。`flutter test` customer 8件・pms_app 2件成功(取得元、skip/take、台帳の列・行の表示を追加)。

## 未対応・提案・課題
1. GraphQL 版リポジトリは未実装。現状の取得元はメモリ上のサンプルで、`graphql_provider_lib` は依存に追加していない(クライアント・認証・言語ID の受け渡しが未決のため)。GraphQL 版の実装時に `customerRepositoryProvider` を差し替え、依存を追加する。
2. 台帳のソート・フィルタはテーブル側(メモリ)で行い、`FilterCondition` → `Expression` の変換は未実装(取得は全件・上限 `customerFetchLimit`=1000)。件数が増えたらサーバー側に切り替える。
3. 列ラベル(コード/名称/メール/電話番号)は仮。`schema.graphql` の `MstrStakeholder` にコメントが無いため。名称は実際には `sharedAppellationByNames` の辞書値で、`Customer` は簡略モデル。
4. `Customer` は `CustomerPage` の簡略版。住所・出荷区分・更新者/更新日は未対応(編集構造で更新者・更新日は編集不可とする)。
5. 台帳・編集の見た目を `tools/open-design` の顧客台帳に合わせる作業と、`doc/contents` への画面イメージは未実施。
6. slang による多言語化は未導入(ラベルは日本語の直書き)。
7. 編集画面の保存は名称のみ。
