# 20261104_0005 ユーザー情報の表示プロジェクト(user_profile)の追加

指示: `issue/20261104_0005.md`(調査 `packages/features/doc/log/20261104_0004.md` の結果、採択された内容)。サーバー・`pbapi` は `packages/infra/pbapi/doc/log/20261104_0001.md`。

## 調査の結果(既存の確認)
ユーザー情報の表示の専用プロジェクトは無く、部品は `app_shell`(`UserContainer`・`AppUser.photo`)、`feature_shared`(`userSummaryProvider`)、`pms_app` の `AppMainFrame`(`photo` を渡していなかった)に分かれていた。そのため、`user_profile`(機能コード `F`)を生成した。

## 実施
- `packages/features/user_profile`(`CLAUDE.md`・`slang`(日本語・English)・テスト・`issue`)。
- 画像の取得: `userAvatarProvider`(`pbapi` の `AvatarService`。サムネイル 256x256)。ログインしていないときは何も取得せず、登録が無い・失敗のときは既定のイメージ。
- 既定のイメージ: 画面案の `avatar.svg` を、`dart:ui` で描き起こす(`DefaultAvatar`)。SVG の描画ライブラリは足していない。
- 変更の可否: `isChangeUserImageProvider`(標準 `false`、`--dart-define=IS_CHANGE_USER_IMAGE=true` で `true`)。裏設定からの上書きは `20261104_0006` で行う。
- 自分のイメージの画面(`/profile/image`): 現在のイメージ・名前・役割、画像ファイルを選ぶ(2MBまで)、初期のイメージに戻す。変更できないときは管理者への案内だけ。
- アップロードの前の縮小: 長辺 512px の PNG に作り直す(`UiImageNormalizer`)。サーバーの README の注意(原寸には EXIF が残る)に対応。
- アプリ(`pms_app`)への組み込み: `featureModules` に `UserProfileModule` を追加。`AppMainFrame` が顔写真を `AppUser.photo` へ渡し、ユーザーメニューに「自分のイメージ」を追加。
- ページ一覧: `tools/entity_gen/access_paths.js`・`apps/pms_app/doc/contents/access_paths.csv` に `/profile/image` を追加。画面コード: `tools/entity_gen/page_codes.js`・`doc/page_code_list.yml` に機能 `F`・画面 `FI` を追加(Node.js が無い環境のため手書き。再生成して差分が無いことを確認する)。

## Issue との差
- 画像の保存先は、Issue の案 A(`users.avatar`)ではなく、サーバーの実装(`user_avatars`)に従った。
- 画面案の「GIF」は、サーバーが受け付けない形式(JPEG/PNG/WebP のみ)だが、選んだ画像を PNG に作り直すため、GIF も選べる(最初のコマ)。

## 確認
- `flutter analyze`(`user_profile`): 指摘なし。`flutter test`: 17件成功(遷移先の登録・標準は変更不可・顔写真の取得(未ログイン/既定/登録あり/失敗/未接続)・画面(変更不可/変更可/初期化/取り消し/失敗の文言)・画像の縮小・既定のイメージ・ファイルの選択)。
- `apps/pms_app`: `flutter test` 25件成功。`flutter analyze` は既存の `avoid_print`(17件)のみ。
- 注意: アプリのテストには、生成モデル(`*.graphql.dart`)が必要(`melos run gql:build`)。このコマンドは追跡済みの `packages/model_providers` の48ファイル(バレルと `*_filter_spec.dart`)を、コミット済みの内容と違う形に書き換えるため、実行後に `git checkout -- packages/model_providers` で戻した(生成器とコミット済みの生成物がずれている。別の課題)。

## 課題・提案
1. 管理者が他のユーザーの画像を変える画面(担当者の画面から)。`AvatarService.set(userId, …)` は対応済み。
2. 顔写真の取得結果は Provider が持つ。担当者の一覧で多人数の写真を出す画面が出たら、`AvatarService.findMany` とキャッシュ(`UserAvatar.cacheKey`)を使う。
3. `example`(ビジュアルテスト)は未作成。
4. `melos run gql:build` が追跡済みファイルを書き換える件(上記)。生成器の出力とコミット済みの内容を合わせるか、生成物を追跡から外すかを決める。
5. 画面案に、標準(ユーザーが変更できない)の表示は無い。画面案へ追加するか確認する。
