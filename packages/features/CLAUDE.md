
#	画面のデザイン
##　このフォルダの目的
このワークスペースで生成するアプリケーションの画面を、機能毎にプロジェクトにまとめ、その中でGoRouterのノードを含めたWidget(ページ）を生成する、ルートプロジェクトです。
様々なライブラリやパッケージを参照するため、全て一度に生成せず、少しずつまとめる必要があります。そこで、希望毎にプロジェクトを生成し、その画面デザインと当該プロジェクトの`CALUDE.md`を生成。そのプロジェクトの`doc/contents`フォルダに画面イメージをHtmlで生成します。そのHtmlを元に当該プロジェクトの`issue`フォルダへ追加、変更をまとめ、完成させる予定です。全てのプロジェクトの`CALUDE.md`は、このファイルを基準として生成します。その中で[規則/仕様](#規則/仕様)は必ず適用します。

##  規則/仕様
1.  ディリクトリ/ファイル
    1.  生成結果のレポートは`doc/log`ディリクトリにファイル名`年月日_4桁ゼロ埋の番号.md`として保存する。
        1.  同じ年月日、同じ番号に対する追加変更は`年月日_4桁ゼロ埋の番号_add_1からの連番.md`として保存する。
    2.  生成したライブラリに関する使い方やヘルプなどの使用にかかわるレポートは`doc/contens`の保存する。
    3.  最終的にこの`CLAUDE.md`へ統合される追加、変更の指示は`issue`ディリクトリに`年月日_4桁ゼロ埋の番号.md`として保存する。
        1.  つまり`生成結果のレポート`と連動する。
        2.  `CLAUDE.md`への統合も指示に含める。統合時、削除指示が無い限り`issue`ディリクトリ`doc/log`ディリクトリの中を削除しない。`CLAUDE.md`には変更や追加、削除であることについて記録しない(生成時に`issue`ディリクトリ`doc/log`ディリクトリを参照するため)。

## 参照するライブラリ
1. テーマライブラリ
	+ theme_lib（テーマ管理）
	+ view_responsiveness（レスポンシブデザイン）
	+ ui_mappter（画面配置のシリアライザ。ユーザーカスタマイズ用）
2. グリッドライブラリ
	+ grid_extenssion（trina_grid拡張）
3. データ問い合わせGraphQLライブラリ
	+ graphql_lib（通信）
	+ graphql_provider_lib（モデル）
4. 認証画面ライブラリ
	+ pms_authenticator ※移植が必要

アプリケーション、ライブラリは日本語をメイン言語とした多言語対応として、`riverpod`からインジェクションする[slang](https://pub.dev/packages/slang) パッケージを使用する。または、これに準ずる自作ライブラリの作成。
表示する全てのラベル、メッセージを対象とするが、機能画面上の列は、データベースのコメントが使用できるため、画面単位で使用する列などの日本語のラベルは、`flutter-pms\packages\infra\graphql_provider_lib\lib\graphql`、`flutter-pms\packages\infra\graphql_provider_lib\lib\postgraphile`を参照した、`schema.graphql`のコメントを使用する。画面で使用する不足しているラベルは適切なものを推論し、推論できないモノは仮で割り当て、後で変更できるようにログに残す。

## 構成
すべての構成はモバイル、タブレット、PC（モバイルより大きいサイズ）のサイズに応じたview_responsivenessを使用する。
色、サイズなどはtheme_libを使用する。
### ライブラリ構成
+ 画面構造
	+ フレーム構造
	+ ツリー構造
	+ テーブル構造
	+ リスト構造
	+ 編集構造

#### 画面構造
すべての画面ライブラリの原点、ルート。実体を持たない抽象化されたインターフェイス。

#### フレーム構造
分割または並べた割合、順序、Zインデックスを持ち、1つまたは複数の抽象化された画面構造を子として持つ。

#### ツリー構造
grid_extenssion使用。親子構造（子のインデント処理）を持ち、ドラッグドロップで親の付け替えができる（Trueのとき）。親は子の有無の情報をもち、子があるときに展開（遅延読み込み）、縮小ができる。

#### テーブル構造
grid_extenssion使用。列（プロパティ/キー）と行をもつリスト構造で、列のソート、フィルタができる（Trueのとき）。列は値を表示/非表示ができる。列キーは`flutter-pms\packages\infra\graphql_provider_lib\source\views`に従う。
列構造は、`flutter-pms\packages\infra\graphql_provider_lib\lib\postgraphile`を参照し、該当するモデルクラスのプロパティ名を適用する。
編集が有効なとき、行のクリックで編集画面へ遷移する。
#### リスト構造
タイルもしくは1つのラベル（アイコンとラベルの組み合わせもありうる）をもつドラッグドロップで順を変えることができる（Trueのとき）リスト構造。1レコード/1タイルをタップ/クリックで編集構造へ遷移できる。[テーブル構造](#テーブル構造)との違いは、列を持たないことである。
編集が有効なとき、行のクリックで編集画面へ遷移する。
#### 編集構造
汎用インプット構造:通常のWidgetを使う。ライブラリとして生成しない。内部にリスト構造を持つ場合がある。
GraphQLから取得したデータのうち、イミュータブルな更新者、更新日は編集できない。

## 共通画面
### タイトルバー
1. アプリケーションのタイトルまたはイメージを表示する
2. モバイル表示のときハンバーガーメニューを表示する。表示する項目と振る舞いは[サイドバー](#サイドバー)と共有する。
	+ ログインしており、画面に対して権限が有効になっている場合のみ（ログイン、ログアウト、一部のエラー画面では表示されない）表示される

### サイドバー
1. モバイルのとき[ハンバーガーメニュー](#ハンバーガーメニュー)として表示するため、非表示にする。
2. タブレットの場合、または設定で有効の場合はアイコンのみの表示にする。
	+ ログインしており、画面に対して権限が有効になっている場合のみ（ログイン、ログアウト、一部のエラー画面では表示されない）表示される
### メインフレーム
[フレーム構造](#フレーム構造)を実装した子を持つ画面。
1. シングルメインフレーム
	+ タイトルバーとメインフレームの子を1つ持つ
2. マルチメインフレーム
	+ タイトルバー、サイドバー、メインフレームの3つの子を持つ
	+ メインフレームは画面によってさらに分割されるときがある

### 選択フレーム
[フレーム構造](#フレーム構造)を実装した子を持つ画面。タイトルバー、サイドバーを持たず、他のフレームと併用する。

## 機能別画面
### 一般
`基本的な情報`とは、名前、略称、読み、住所などの情報をもとに一意に識別できる情報。データの更新者、更新日、削除されているかの情報を含めない。
機能画面の機能単位のプロジェクトは`flutter-pms\packages\features`に保存する。
### 参照するモデル
`flutter-pms\packages\infra\graphql_provider_lib\source\page.md`を画面の参照元とする。
以下の各画面はプロジェクトの単位として、当該情報を`CLAUDE.md`としてまとめ、実装の基準とする。
ログインしていない、画面に対して権限が有効になっていない場合、かつ通信可能でエラーでなければログイン画面に遷移する。

### AppCore

1. ブート画面
	+ シングルメインフレーム
		+ 読み込み中の表示。
2. ログイン画面（遷移）
	+ シングルメインフレーム
	+ Keyclaokを内部ブラウザ表示
		+ 接続できないときはエラー画面へ遷移
		+ 接続でき、ログイン失敗のときは、同画面に失敗の表示
3. ログアウト画面
	+ シングルメインフレーム
	+ 5秒後、ログイン画面へ遷移
	+ ログアウト処理、セッション切れのときの表示
4. エラー画面
	+ シングルメインフレーム
	+ アプリケーションエラーの表示
5. 設定
	+ マルチメインフレーム
	+ バージョン情報
		+ ライブラリではなくアプリケーションのバージョン
	+ 設定
		+ 使用者全体ではなく、使用ユーザーにだけ影響のある設定
		+ テーマの変更、テーマの取得
		+ 使用言語
			+ 原則/初期、アプリケーションの実行環境による（ISO3661/2）
		+ 各画面の列の表示/非表示/標準ソート列
