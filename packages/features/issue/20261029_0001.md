#   デザインの追加変更
1.  `flutter-pms\tools\open-design\index.html`の参考デザインを追加変更した。
資材所要計算（MRP／再MRP）画面を追加する
「生産計画」メニューの子項目として「資材所要計算」を追加する。
画面に「再MRPとして実行する」チェックボックスと「MRPを実行」ボタンを置く。
実行区分は、チェックなしを受注MRP（p_mode = 1）、チェックありを再MRP（p_mode = 2）にする。
実行時は DB 関数 tests.mrp_execute(p_mode, p_staff_id, p_order_detail_ids, p_accept_late) を呼ぶ。
戻り値は trans_mrp_run（実行結果）。提案の一覧は trans_mrp_suggestion から取得する。
実行前に確認ダイアログを出し、「実行する」を押したときだけ実行する。次の警告を必ず表示する。
処理が重く、時間がかかる。
影響が広範囲で、他のユーザーの処理にも影響する。
再MRPのときは、すべての需要を作り直すため影響がさらに大きい。
実行中は操作も中断もできない。
実行中は、画面全体を操作できないようにする。
実行ボタン、再MRPチェックボックス、すべてのメニュー（サイドメニュー・ハンバーガー・下部ナビ）を無効にする。
戻る操作でも画面を離れられないようにする。
「計算中」と分かる表示を出し、処理が止まっていないことを示す（経過時間の表示を含める）。
成功したら、「MRPが成功しました」のお知らせを出し、結果リストをテーブルで表示する。
お知らせには、実行日時、受注MRPか再MRPか、提案件数、要判断件数、遅れ件数を含める。
テーブルの列は、提案種別、品目コード、品目名、数量、在庫引当、必要日、発注日・着手日、納期、遅れ、判断、メッセージ。
判断で絞り込み、並べ替え、検索ができるようにする。
提案種別の値と表示名は次のとおりにする。
PURCHASE_NEW：発注（新規）
PRODUCTION_NEW：生産（新規）
PURCHASE_RESCHEDULE：発注の日程変更
PRODUCTION_RESCHEDULE：生産の日程変更
PURCHASE_CANCEL：発注の取消
PRODUCTION_CANCEL：生産の取消
OUTSOURCE_OPTION：外注への切替
EXC_OVERLOAD：設備の過負荷
判断の値と表示名は、0が要判断、1が採用、2が却下、9が情報にする。
失敗したときは、エラーコードに関わらず、一般の人向けの警告を出す。
文言は「しばらく時間をおいて、もう一度実行してください」とする。
エラーコードは問い合わせ用に小さく添える。
想定するエラーは、DB処理中のタイムアウト（57014）と、引数エラー（MRP00）。
失敗後は、操作を元に戻して再実行できるようにする。
品目に「購入品」チェックボックスを追加する
品目の編集画面に「購入品」のチェックボックスを追加する。
品目の一覧テーブルにも「購入品」の列（はい／いいえ）を追加する。
その品目に仕入先（品目仕入先）が登録されている間は、チェックを外せないようにする。
外そうとしたら、理由を項目の下に表示してエラーにする。
購入品フラグを保存する DB の列を確認する。
mstr_item に該当の列が見当たらず、MRPのSQL（08_mrp.sql）では「購入品フラグ」として参照されている。
購買に「品目仕入先」画面を追加する
購買メニューの「サプライヤー」の次に「品目仕入先」を追加する。
閲覧では、購入品にチェックが入っている品目だけをテーブルにする。
品目テーブルの列は、品目コード、品目名、品目種類、個別単位、サプライヤー数。
並べ替え、検索、列の表示切替ができるようにする。
各品目の行に、サプライヤーのテーブルを入れる（テーブルの中にテーブルを入れる構造）。
行ごとに開閉でき、初期状態はすべて開く。
列は、サプライヤー、デリバリータイム（日）、最小発注ロット、単価（円）、言い値区分。
言い値のときは、単価の欄に「言い値（都度確認）」と表示する。
編集モードを用意する。
品目ごとに「サプライヤーを追加」を置く。
サプライヤーの行を選ぶと、編集画面へ進む。
編集画面の項目は次のとおりにする。
サプライヤー：選択式。サプライヤー台帳から選ぶ。
デリバリータイム（日）：必須、0以上。
最小発注ロット：必須、0より大きい。
単価（円）：言い値でなければ必須、0以上。
言い値区分：トグル。
次の検証と動作を実装する。
同じ品目に、同じサプライヤーを二重に登録できない。
言い値区分をオンにしたら、単価の入力を無効にして、値を空にする。
言い値区分をオフにしたら、単価を必須にする。
削除は確認を出してから行う。
更新者と更新日は表示だけにして、編集できないようにする。
DBのテーブル mstr_item_supplier に対応させる。
サプライヤーは mstr_stakeholder_id。
品目は mstr_item_id。
デリバリータイムは delivery_time（interval）。
最小発注ロットは minimum_lot_size。
単価は cost。
言い値区分は asking_price（boolean）。
DBにある優先順位（priority）、仕入先品番（supplier_item_code）、標準検品時間（quality_inspection_time）は、今回は実装しない。
共通部品として用意する
チェックボックスとトグルの入力項目。
値は真偽値で扱う。
トグルがオンのとき、指定した別の項目を無効にする指定を持たせる。
親のテーブルの行に、子のテーブルを入れて開閉できる表示。
検証ルール：
数値の下限（以上／より大きい）。
親の中での重複禁止。
他の項目がオンでなければ必須にする。
子が存在する間は外せないチェックボックス。
長時間の処理中に、画面全体の操作と戻る操作を無効にする仕組み。
実装方針
リポジトリの CLAUDE.md の構成に従い、機能は xxx_api（契約）と xxx（実装）のペアで作る。
テーブルは flgtable_lib を使い、独自の表を作らない。
項目名は GraphQL の View 定義と DB の列コメントに合わせる。
状態や結果の違いは、色だけでなく文字でも示す。
