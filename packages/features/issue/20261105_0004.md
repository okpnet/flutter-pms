#   ページのコード体系・アクセスパス生成の JS(`tools/entity_gen`)の扱い
`issue/20261105_0003.md` の項目 2(`page_codes.js`・`access_paths.js`)への回答。**削除せず保持する。** 不要ではあるが、使う頻度が不明なため。次のことを記録する。

##  1. 対象の JS(2つ)
Claude が作業を進めるために追加した補助のツール。アプリの実行には使わない。

| JS | 内容 | 出力 |
|---|---|---|
| `tools/entity_gen/page_codes.js` | ページ(画面)をバーコードで読み込んで開く用の、コード体系を作る。機能コード1文字 + 画面コード1文字(大文字英数、36種ずつ)の2文字が画面のコード(例: 品目台帳 `II`)。連想できる文字を優先して割り当て、既に割り当てたコードは変えない。削除した画面は `removed: true` で残す | `packages/features/doc/page_code_list.yml` |
| `tools/entity_gen/access_paths.js` | アクセス管理(`access_control`)の「アクセスパス」を、DB へ初回に一括で登録するための、ページのパスと名前(ja・en)の一覧を作る。実体の定義、手書きのページ(`CUSTOM`)、英語名(`EN`)から作る。`public` はログイン前から使えるページ | `apps/pms_app/doc/contents/access_paths.csv` |

どちらも `node tools/entity_gen/<名前>.js`(リポジトリのルートで実行)。`entity_gen` のほかの JS(`gen.js`・`handwritten.js`・`claude.js`・`examples.js`・`labels_report.js`)は、実体の画面の生成(`gen.js`)に使うもので、この Issue の対象ではない。

##  2. 保持の方針
1.  削除しない。使う頻度が不明なため、保持する。
1.  画面を追加・削除したときは、これまでどおり `page_code_list.yml`・`access_paths.csv` を更新する。Node.js が無い環境では、JS の出力と同じ書式で手で更新する(手書きの更新は、Node.js のある環境で JS を実行して、差分が無いことを確認できる)。
1.  積極的な改修はしない。コード体系や生成の仕様を足す前に、この Issue の「3」を確認する。

##  3. いずれ削除する
1.  この2つの JS は、**いずれ削除する**。削除する時期は、バーコードで画面を開く機能(`symbol` のショートカット。`CLAUDE.md` の「Issue: symbol によるショートカット」)と、アクセスパスの登録の手順が決まったときに決める。
1.  削除するときは、同時に次を直す: `packages/features/CLAUDE.md` の「機能コード・画面コード」(生成の記述)、`apps/pms_app/CLAUDE.md` の「ページのアクセスパス(CSV)」(生成の記述)、`page_code_list.yml`・`access_paths.csv`(生成物から、手で管理するファイルへ)。削除の前に、一覧(`page_code_list.yml`・`access_paths.csv`)は残す。

##  4. コード体系が変わる可能性
1.  バーコードの画面コード(機能1文字 + 画面1文字、36種まで)は、**変更する可能性がある**。上限(機能 36・1機能あたりの画面 36)、機能コードの割り当て(`user_profile`=`F`、`backstage`=`B`〔の予定〕など、連想で決めたもの)、`symbol` との組み合わせ(`機能コード + 画面コード + symbol`)の形式・桁数は、未確定。
1.  「既に割り当てたコードは変えない」という規則は、バーコードを印字して使い始めてから意味を持つ。使い始める前は、体系ごと見直してよい。印字した後で体系を変えるときは、変換表を用意する。
1.  現時点で、バーコードで画面を開く機能は未実装で、画面コードの一覧は、まだ使われていない。
