### DB に無い項目・不明な箇所(schema.bespoke.log.md より)の対応

- 会社: 「代表者の役職」は DB に列がない。所在地は `info_address` の複数列（住所1・住所2・建物・電話・FAX）だが、1 つの欄のまま。=>郵便番号、都道府県、市町村番地、建物、電話、FAXに分割する。
- 事業所/部署: 「種別」「在籍人数」は DB の列ではない（種別は区分の値、人数は集計）。住所は `info_address` の複数列を 1 欄で扱っている。=>郵便番号、都道府県、市町村番地、建物、電話、FAXに分割する。
- 部署区分(`info_department_kind_value`): 区分詳細は未追加。=>追加
- 割当(`info_assign`): 有効・優先順位・事業所・部署は未追加（役職の割当は担当者のみ）。=>追加
- 職員: 「所属事業所」「区分（社員/パート/派遣）」「部署」は `info_staff` にない（割当や別テーブル由来）。=>viewsのstaffに部署、区分が無いか調査。
- 承認範囲(`mstr_approval_scope_pattern`): DB は「アクセスパス承認情報」への参照だけで、段階・役職・対象組織・配下を含むかは DB にない。承認できる人(種別・有効期間)も対応する YAML ページが見つからない。=>view未実装。不要。
- 力量/資格の保持: 力量の「値」は数値、停止の有無は DB にあるが、画面は段階(見習い…)のまま。資格の停止/取り消しは未追加。=>追加
- 点検整備: 「対象部位」「判定基準」、算式の「算式名・単位・基準値」、運用の「周期」、予定の「予定月」「状態」は DB にない。点検実績(`inspRec`)は対応する YAML が無いので触っていない。=>存在しない項目を削除。JOSN化可能な式に変換できるリスト選択項目として次を追加。また、手動入力できるようにする。
    +   {"operator":"=","value":"Valueを入力"}のJSON方式
    +   operatorは=、≠、>、<、>=、<=、この他範囲(between)、二値(Yes,No) 
- 設備: 「設備名」は品目(`mstr_item`)の名称、「設置日」「状態」は DB にない。=>ない項目を削除
- 場所: 「種別」は DB にない。=>削除
- 読み・略称は `names` の pick（name/pronunciation/nickname）に基づく。略称は事業所・部署などでは未追加（読みのみ）。=>追加
- ID 列、更新者、削除フラグは表示しない（更新者・更新日は従来どおり編集不可の欄で表示）。=>削除はライブラリ上の削除ハンドラに対応する

これ以外の、推論で作成したものについてはビジュアルテストしながら調整する(文字数がバランスに影響がある可能性)。現段階としてはクローズ。
