#   棚ビジターの数量一本化(DB 117)・関数(DB 07)に伴う画面の作業
model_providers の issue `20261101_0003`・`20261101_0004` で、モデルと `ScanClient` は対応済み。画面側の作業を残す。

## 作業

1. **異常登録**: 棚のロットを選び、`ScanClient.registerComplaint` で異常を登録し、`ScanClient.moveLot(hold: true)` で隔離棚へ移す。異常数量はロットの今の数量以下。隔離棚はバーコードで読む。
2. **異常の解除**: `trans_complaint_visiter` の `release_at` と許可者を登録する(解除の `kind: edit` を `quality_model` に追加するかは、着手時に決める)。
3. **払出**: 棚を読み、`listVisiters` の取り出せるロットから選んで `issueLot` で払い出す。取り出せない理由(`blockReason`: hold / complaint / empty)を表示する。`ScanClientException.code` が `VIS03`(数量が足りない)・`VIS04`(取り出せない)のときは、理由を表示してやり直せるようにする。
4. **棚卸し**: 数えた数を入力し `adjustLot` を呼ぶ。差が無ければ何も作られない(戻り値 null)ことを表示する。
5. **材料の払出(製造への投入)の自動化**: 作業の開始時に、BOM から材料を求め、ロットを先入れ先出し(`update_at`)で選んで `issueLot`(`workRecordId` に投入先の作業実績)で払い出す。仕様(材料の数量の求め方、足りないときの扱い)を先に決める。
6. **マスタ点検画面**: 新しい点検コード(`VISITER_HOLD_NO_COMPLAINT` / `VISITER_NEGATIVE_BALANCE` / `VISITER_ORPHAN_LINE` / `VISITER_INVALID_PARENT` / `VISITER_CONTAINER_MISMATCH` / `VISITER_ZERO_LINE` / `VISITER_ORIGIN_MISMATCH` / `VISITER_COMPLAINT_MISSING`)を表示する。
7. **在庫の合計**: 出しすぎでマイナスのロットは `v_item_on_hand.onHandQuantity` に入る。合計を出す画面では `VisiterLedgerIssuePage` の件数を併記する。
8. 認証(PocketBase)の導入後、`ENTRY_STAFF_ID` の決め方を差し替える(`staffId` を省略すれば DB が認証の担当者を使う)。
