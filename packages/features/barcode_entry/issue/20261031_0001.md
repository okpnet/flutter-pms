# バーコード実績登録の課題・提案

`issue/20261031_0002.md`(画面追加仕様)の実施で見つかった課題。大きく影響する判断を先に、流れを変えずに対応できるものを後にまとめる。

## A. 判断が必要な課題
1.  **実績登録専用アプリ(Android・スマートフォン)の分離**: 現在は `pms_app`(Windows)のメニューに入っている。専用アプリは `apps/` に別アプリ(例 `apps/entry_app`)を作り、`BarcodeEntryModule` だけを載せるのが素直(`example` の `FeatureHost` と同じ配線)。権限・ログイン方式(PocketBase)も専用アプリで決める。→ 別アプリを作るか決めてほしい。
2.  **カメラ読み取り**: プロトタイプは `BarcodeDetector` のカメラ読み取りを持つが、本実装は未対応(リーダーのキーボード入力と手入力のみ)。スマートフォンで使うなら `mobile_scanner` などの導入が必要で、カメラ権限と Android/iOS の設定が増える。→ 導入するか決めてほしい。
3.  **GraphQL 取得元**: `IScanGateway` の GraphQL 版が必要。symbol の照会は、作業指示・棚・発注明細・品目・設備の `symbol` 列を種類ごとに引く(`CLAUDE.md` の symbol ショートカットと共通)。登録は、棚出庫・入庫(在庫の更新)・受入・作業実績・点検結果にあたるミューテーションが DB 側に要る。現在の検証用サーバーは読み取り専用のため、登録の通信テストは書けない。→ 登録に使うテーブル・関数(`tests` スキーマの関数を含む)を指定してほしい。
4.  **symbol の種類の判定**: 同じ `symbol` が複数の種類にあり得る(ルートの `CLAUDE.md` の未確定事項)。区切りと桁数の形式が決まるまで、取得元が全種類から引く方式にしている。

## B. 流れを変えずに対応できる提案
1.  委託品(`outsourced`)は、開始時に出庫ではなく「委託先への払い出し」になる可能性がある。現在は製造品と同じ流れ。
2.  不合格の入庫先は、不良品棚(`SH-X-…`)に限定すると誤入庫を防げる(現在は任意の棚)。
3.  同じ作業指示の同時登録(複数端末)は、登録時の数量の再確認(楽観ロック)が要る。GraphQL 版で対応。
4.  履歴は画面の中だけ(最新20件、保存しない)。端末を替えても確認したいなら、サーバー側の実績の一覧から引く。
5.  数量入力は整数のみ。小数の単位(kg など)の品目があれば、単位ごとの桁を取得元から渡す。
6.  英語など他の言語ファイル(`en.i18n.yaml`)は未作成。日本語のみ。
