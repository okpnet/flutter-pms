# 20261031_0002 バーコード実績登録の新規プロジェクト

指示: `issue/20261031_0002.md`。

## 実施内容
- 新しい機能プロジェクト `packages/features/barcode_entry` を作成した(プロジェクト名はバーコードで実績を登録する役割から)。
- 画面は `tools/open-design` の「作業実績 › バーコード」に合わせた。リーディングトップ(バーコード読込/テキスト入力、モードで種類を絞る)から、作業実績・受入検品・棚移動・設備点検をフロー図の段階で進める。
- ビジネスロジックは別パッケージにせず、このプロジェクト内で分離した(`lib/src/logic`)。取得元は `IScanGateway`(Strategy)で受け、暫定はメモリ上のサンプル(`InMemoryScanGateway`)。画面は状態の表示だけ。
- アプリ(`pms_app`)へ組み込み、メニュー「作業実績 › バーコード」を追加した。`doc/page_code_list.yml` を再生成した(機能コード `E`、リーディングトップ `ET`)。
- テスト: 流れ 13 件(`test/barcode_entry_test.dart`)、example の起動と読み込み 1 件。`pms_app` の配線テストも通過。

## フローの解釈(フロー図から読み取ったこと)
- 作業指示の「開始の選択」で「いいえ」は、開始せずリーディングトップへ戻す(図の `Q -- いいえ --> H` は循環のため、プロトタイプ(open-design)の動きに合わせた)。
- 作業指示の「開始中 → 数量入力」の評価で合格・不合格のどちらも、最後は棚移動リーディング(入庫処理)を通る。不合格は理由を決めてから入庫する。
- 委託品(`outsourced`)は、現時点で製造品と同じ流れ。区別は Issue に提案した。
