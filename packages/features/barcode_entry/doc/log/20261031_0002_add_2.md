# 20261031_0002_add_2 モデルを使った取得元(GraphQL)の実装

指示: `issue/20261031_0002.md` の回答(`packages/model_providers/issue/20261031_0001.md` に統合して実施。報告は `packages/model_providers/doc/log/20261031_0001.md`)。

## 実施内容
- `GraphqlScanGateway`(`lib/src/logic/graphql_scan_gateway.dart`): `IScanGateway` の GraphQL 版(Adapter)。`barcode_entry_model` の `ScanClient` だけを使う。照会した対象の id を持ち、登録のときに引き直さない。
- 登録の方針: 作業実績・ビジター・入庫の組み合わせをクライアントで順に呼ぶ(作業の入庫 = 作業実績 + ビジター + 入庫 + 結び付け、購入品 = 受入 + ビジター + 入庫 + 結び付け、棚移動 = ビジター + 入庫、開始 = 作業実績)。
- `apps/entry_app`: `--dart-define=ENTRY_GRAPHQL_URL`・`ENTRY_LANGUAGE_CODE_ID`(・`ENTRY_STAFF_ID`)があれば GraphQL、なければメモリ上のサンプル。
- テスト: `test/graphql_scan_gateway_test.dart`(変換と登録の呼び出し)。実サーバーでの登録は行わない(読み取り専用)。

## 判断した点(Issue `issue/20261031_0003.md` で確認)
- ビジター(`trans_visiter`)に品目の列が無いため、棚出庫(払出)は行わず、作業の開始は作業実績の登録だけにした。
- 不合格は、異常(`trans_complaint`)を登録せず、作業実績・受入・ビジターの備考に理由を残す。
- 単位は取得元から取れないため空。設備点検の記録は未対応(`UnsupportedError`。画面は「登録できませんでした」を出す)。
