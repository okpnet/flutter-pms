# 20261102_0001_add_1 認証画面を画面案(tools/open-design)に合わせて作り直し

## きっかけ
画面案は `tools/open-design/index.html#/login`・`#/register`・`#/forgot`・`#/forgot/code`・`#/forgot/reset` にあった(実装は `app.js` の「account: register / forgot password」)。最初の生成では見落とし、独自の画面にしていた。

## 変更
- ログイン前の画面を画面案の構成に合わせた: カード中央配置・エンブレム・見出し・「必須」の印・項目ごとのエラー(フォーカスが外れたときと送信時)・案内の帯(赤=失敗、アクセント色=完了)。
- 画面とパスを画面案に対応させた(`/auth/login`・`/auth/register`・`/auth/forgot`・`/auth/forgot/code`・`/auth/forgot/reset`)。「新しいパスワード」(`NewPasswordDestination`)を追加し、コード入力と分けた。
- 入力の検証(`form_rules.dart`)は画面案の `RULES`(ユーザーID 4〜32文字、メール、ふりがな、パスワード8文字以上と一致)に合わせ、コードは12文字に変更した。
- 新規登録は画面案の4項目(ユーザーID・メール・名前・ふりがな)。ふりがなは申請の `profile.ruby` に入れる。
- 画面コード一覧の画面を差し替えた: `register`(US)・`forgot`(UR)・`code`(UC)・`newpassword`(UP、新規)。`signup`・`reset` は同じコードのまま改名しただけ(この一覧は未コミットのため、バーコードへの影響は無い)。
- 文言は画面案どおり(「生産管理にサインイン」「パスワードを忘れた」「認証コードの入力」「新しいパスワード」など)。

## 画面案と違えた点(サーバーの仕様に従う)
1.  画面案は「6桁のコードをメールで送り、すぐ登録完了」。サーバー(README)は管理者の承認制で、コードは12文字(承認後に渡される)。そのため新規登録は「申請を受け付けました」で終わり、認証コードの入力へ進める。
2.  画面案はユーザーIDの重複を画面で示すが、サーバーの応答はいつも同じで重複を教えない。重複の検証はしない。
3.  画面案は認証サーバーの内部ブラウザ(URL バー)を模すが、PocketBase は自前の画面なので出さない。
4.  画面案のコード入力と新しいパスワードは2画面だが、サーバーはコードとパスワードを1回の呼び出しで受ける。コードは `accountFlowProvider` に預かり、「新しいパスワード」で一緒に送る。コードの誤りはその画面で帯に出る。
5.  画面案のコードの再送・入力回数の制限は、サーバー(`PB_CODE_MAX_ATTEMPTS`)が行うため、画面には持たない。
6.  「認証コードをお持ちの方」のリンクは、画面案に無い(承認後に管理者からコードを受け取る流れのために追加)。

1.  画面案に、共有ファイルと管理者の2画面(新規登録の管理・再設定依頼の管理)は無い。画面案へ追加するか確認する。
2.  画面案に「承認後のコード受け取り→入力」の流れを足す案(新規登録の完了画面から認証コードの入力へ)。
3.  `app_core` の `login`(AL)の扱い(`_0001` の課題2のとおり)。
