# 20261102_0001 認証・ファイル共有プロジェクト(auth_files)の追加

## 対応した issue
`issue/20261102_0001.md`(Authentication プロジェクトの追加)。

## 判断
- 名前は `auth_files`(認証 auth + 共有ファイル files の両方の意図)。機能コードは `U`。
- 認証は `packages/infra/pbapi` を使う。画面の遷移は `tools/docker/pocketbase/README.md` の流れ(申請 → 承認 → コード → ログイン、再設定 → コード → ログイン)に従う。
- 管理者の承認は `app_user_id` を受け取るだけにし、担当者の登録(App DB)は organization の担当者の画面の責務とした。
- ファイルの選択・保存は、パッケージを足さずに差し込み口(`IFilePickerGateway`・`IFileSaverGateway`)にした。未差し込みは「この環境では使えません」の文言。
- ログイン前の画面は枠の外、共有ファイルと管理者の画面は枠の中を想定。

## 課題・提案(後で解決)
1. この環境に Node.js が無く、`node tools/entity_gen/page_codes.js` を実行できなかった。`page_code_list.yml` は生成と同じ書式で手で追記した。node のある環境で再生成して差分が無いことを確認する。
2. `app_core` に、認証の導入後に追加する予定の `login`(コード `AL`)が残っている。ログインは `auth_files`(`UL`)に置いたので、`app_core` の `login` を削除するか(削除すると `removed: true` で残る)、役割を決める。
3. `example`(ビジュアルテスト)とアプリへの組み込みは未実施。
4. Html 画面案(`tools/open-design`)に該当する画面が無い。画面案を足すか、この画面を基準にするか決める。
5. 承認の画面は担当者の ID(`app_user_id`)の手入力。organization の担当者を選んで渡す形(`EntityPickerDestination`)にできる。
6. ログインユーザーの役割(`role`)は `AuthSession` に無いため、表示用の `UserSummary.role` は空にしている。
7. ファイルの選択・保存の実装(例: `file_picker`)はアプリで決める。
