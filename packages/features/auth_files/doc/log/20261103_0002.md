# 20261103_0002 ログアウト・ファイルの選択と保存・ログイン情報の安全な保管庫

指示: [issue/20261103_0002.md](../../issue/20261103_0002.md)(`doc/log/20261103_0001.md` の「未対応」1〜3)。4(実機の目視)は実装後に行う。

## 調査(Issue の有無)
- ログアウト・ファイルの選択と保存・保管庫は、`auth_files` の Issue(`20261102_0001`・`20261103_0001`)にも `app_core` の Issue にも無かった。そのため Issue を追加した。

## 実施
1. **ログアウト**
   - `app_core`: `signOutProvider`(ログアウトの実体を差し込む口。既定は何もしない)と `signInDestinationProvider`(ログアウト後のボタンの遷移先。既定は null = 仮のログイン)を追加。ログアウト画面は、開いたとき**1回だけ**実体を実行し、失敗しても表示する(失敗は `[app_core]` でログ)。遷移先があるとき、ボタンの文言は「ログイン画面へ」。
   - `auth_files`: `authFilesSignOut` — PocketBase のセッション(メモリ上のトークン・GraphQL 用の JWT)、保管庫のログイン情報、ログインユーザーの表示、画面をまたぐ入力(コード・ユーザーID)を破棄する。一部が失敗しても残りを続け、例外にしない(失敗は `[auth_files]` でログ)。
   - `pms_app`: `POCKETBASE_URL` を指定したとき、`signOutProvider` を `authFilesSignOut`、`signInDestinationProvider` を `LoginDestination` にする。指定しないときは、これまでの仮の動き。
1. **ファイルの選択・保存**: `file_picker`(13.3.2)で `PlatformFilePicker`・`PlatformFileSaver` を実装し、`filePickerGatewayProvider`・`fileSaverGatewayProvider` の既定にした。選択は、サーバーの上限(100MB)を超えるファイルを**メモリへ読む前に**断る(`FileTooLargeException`、画面は「ファイルが大きすぎます」)。取り消しは null/false。
1. **ログイン情報の保管庫**: `flutter_secure_storage`(10.3.4)で `SecureTokenStore`(`ITokenStore`)を実装し、`tokenStoreProvider`(Riverpod)の既定にした。`pms_app` の `pocketbaseOverrides` は、既定でこれを `PbConnection.open` に渡し、同じものを `tokenStoreProvider` にも差し込む(ログアウトで確実に消す)。保管庫が使えなくても止めない(読めなければ未ログイン、書けなくてもメモリ上で続ける。失敗は値を含めずログ)。

## 判断
1. **ファイルの選択に `file_picker` を採用**。Windows・Android の両方で、選択と「名前を付けて保存」(`saveFile`)ができるため(`flutter.dev` の `file_selector` は Android で保存できない)。13 系は `PlatformFile` が `abstract base class` のため、テストで差し替えられるよう、小さな型(`PickedSource`)を挟んだ。
1. **保管庫は `flutter_secure_storage`**。`pms_authenticator` が使っている版(`^10`)と同じで、Windows(資格情報の保護)・Android(Keystore)・macOS/iOS(Keychain)に対応する。
1. **ログアウトはセッションと保管庫の両方を消す**。`SessionService.logout` が `AsyncAuthStore` を通して保管庫も消すが、保管庫の失敗が握りつぶされるため、`tokenStoreProvider` からも明示的に消す(冪等)。PocketBase のトークンはサーバーで失効させられないので、端末のログイン情報を消すことがログアウト。
1. **ログアウト画面で実行する**(メニューのクリックではなく、画面を開いたとき)。遷移と実行を別々に持たず、メニュー以外から `/logout` を開いても(期限切れの案内など)同じ後始末になる。再描画では実行しない(テスト)。
1. **ボタンの遷移先を Provider にした**。`app_core` は認証の実装(`auth_files`)に依存できないため。

## 実機の目視(`flutter run -d windows`)
**実施できなかった。**
- ビルドは、次のとおり通る。プラグイン `connectivity_plus`(既存)の C++ ソースが日本語の Windows のコードページ(932)で警告 C4819 になり、警告をエラーとして扱うため、**環境変数 `CL=/utf-8` が要る**(`$env:CL = '/utf-8'; flutter build windows --debug --dart-define=POCKETBASE_URL=http://192.168.1.103:8090/api --dart-define=GRAPHQL_URL=http://192.168.1.100:5000/graphql`)。この問題は今回の変更とは無関係で、プロジェクトのファイルは変更していない。恒久策は `apps/pms_app/windows/CMakeLists.txt` に `add_compile_options(/utf-8)` を足すこと(未実施。ファイルの変更になるため、指示があってから)。
- 生成した `pms_app.exe` の起動が、OS から「アクセスが拒否されました」で拒否された(この作業環境の制約とみられる)。回避は行っていない。
- 手元での確認手順: 上のビルド後に `build\windows\x64\runner\Debug\pms_app.exe` を起動 → ログイン画面 → 利用者でログイン → ユーザーメニューの「ログアウト」→「ログアウトしました。」→「ログイン画面へ」→ ログイン画面。次の起動でログインが続くこと(保管庫)、共有ファイルでファイルの選択・保存のダイアログが開くことを確認する。
