# ログアウト・ファイルの選択と保存・ログイン情報の安全な保管庫

`doc/log/20261103_0001.md` の「未対応」3点を、この機能(`auth_files`)を通して実装する。実機(`flutter run -d windows`)での目視の確認は、実装の後に行う。

## 調査
1. **ログアウト**: `app_core` のログアウト画面(`LogoutDestination` → `/logout`、ユーザーメニューの「ログアウト」で開く)は、仮のボタンで標準のユーザーに戻すだけで、PocketBase のセッションを破棄しない。`auth_files` の Issue(`20261102_0001`・`20261103_0001`)にログアウトの項目は無かった。
1. **ファイルの選択・保存**: `auth_files` に差し込み口(`IFilePickerGateway`・`IFileSaverGateway`)はあるが、実体は無く、既定は「この環境では使えません」だった。Issue にも実装の項目は無かった。
1. **安全な保管庫**: `pbapi` の `ITokenStore` の既定はメモリで、実体は無い(`pbapi/CLAUDE.md` は「本番は `flutter_secure_storage` で実装する」とだけ書いている)。トークンを保存するのは `auth_files` の責務(ログイン・ログアウトの画面を持つ)とする。

## 追加・変更すること
1. **ログアウト**
   - `app_core`: ログアウトの実体を差し込む口(`signOutProvider`、既定は何もしない)と、ログアウト後のボタンの遷移先(`signInDestinationProvider`、既定は null = 仮のログイン)を、Riverpod の Provider で持つ。ログアウト画面は、開いたとき1回だけ実体を実行し、失敗しても表示する。
   - `auth_files`: `authFilesSignOut` を提供する。PocketBase のセッション(メモリ上のトークンと GraphQL 用の JWT)・保管庫のログイン情報・ログインユーザーの表示・画面をまたぐ入力(コード・ユーザーID)を破棄する。一部が失敗しても残りを続け、例外にしない。
   - `pms_app`: `POCKETBASE_URL` を指定したとき、`signOutProvider` を `authFilesSignOut`、`signInDestinationProvider` を `LoginDestination` にする。
1. **ファイルの選択・保存**: `file_picker`(OS のダイアログ)で `PlatformFilePicker`・`PlatformFileSaver` を実装し、既定にする。選択は、サーバーの上限(100MB)を超えるファイルを、メモリへ読む前に断る(`FileTooLargeException`、画面は「大きすぎます」)。取り消しは null/false。
1. **ログイン情報の保管庫**: `flutter_secure_storage` で `SecureTokenStore`(`ITokenStore`)を実装し、`tokenStoreProvider`(Riverpod)の既定にする。`pms_app` の `PbConnection.open` に同じものを渡し、ログイン情報が次の起動でも続くようにする。保管庫が使えなくても、アプリを止めない(読めなければ未ログイン、書けなくてもメモリ上で続ける)。

## 規則
1. トークン・保存する値・コードをログに出さない。失敗は `[auth_files]` 付きで残す。
1. 他の機能が使うのは `app_core_api.dart` の Provider と `auth_files.dart` の関数だけ。
1. 画面の文字列は slang(`ja`・`en`)。
