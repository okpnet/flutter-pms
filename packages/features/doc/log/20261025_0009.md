### 1. 利害関係者の共有化
- `shared_master` に利害関係者(`stakeholder`)と担当者(`contact`、子の台帳)を置いた。画面の定義は画面案の顧客・外部供給者(同じ項目の組)から作り、`tools/entity_gen/gen.js` で生成する(顧客3件・外部供給者の行を1つの取得元にまとめ、サンプルのフラグは役割に合わせて置き直した)。
- 顧客台帳・外部供給者台帳は、同じ台帳の画面を `is_customer` / `is_supplier` で絞り込んで開く。`feature_shared` の `EntityListDestination` に `filter`、`EntityEditDestination` に `initialValues`(台帳から「新規」を押すと役割のフラグがオンで始まる)を足した。見出しは `EntityFeatureModule.listTitle` で絞り込みごとに変える。営業のメニューに「顧客台帳」、購買のメニューに「外部供給者台帳」を出す。
- ほかの実体が顧客(`customer`)・外部供給者(`supplier`)を参照するときの選択肢は、利害関係者を役割で絞って登録簿へ登録する(`registerLookup` に `backing` を足し、参照されている利害関係者は削除できないようにした)。
- 配送区分の選択は、利害関係者の項目(`mstr_shipping_kind_id`)で同じプロジェクトの配送区分を選ぶ。0005 の課題 5 はこれで解決。
- `sales` の顧客の専用の画面(`lib/src/customer`)・`sales_api.dart`・`FindCustomerNameCommand`・顧客の選択画面は不要になり削除した。`sales` は実体の画面(受注)だけを持つ。`purchasing` の `supplier`・`suppcontact`(生成)も、利害関係者に統合したため生成の対象から外した。
- 契約は `shared_master_api.dart` の `customerLedgerDestination`・`supplierLedgerDestination`・`stakeholderEditDestination`。

### 2. 画面の見出し
- `app_shell` に `ScreenScaffold` / `ScreenTitle` を追加した(見出し + 本体。戻れるときは左に戻るボタン、右に操作ボタン)。`app_core`・`sales`(旧顧客)・`shared_master`・`entity_screens` の画面を `AppBar` から置き換えた。アプリの枠のタイトルバー(`AppTitleBar`)だけが `AppBar` になり、二重にならない。
- `FeatureHost` の起点の一覧(example 用)は `AppBar` のまま。

### 3. ログインユーザーの設定値
- `userSummaryProvider` を `UserSummaryNotifier` にした。アプリが差し込む固定の利用者(鈴木 一郎/生産管理部)を標準値とし、`set`(設定値)・`reset`(標準値へ)・`logout` を持つ。
- 設定画面に「ログインユーザー」の欄(ユーザー名・役割、「設定する」「標準に戻す」)を足した。保存はしない。

### 4. ログアウト
- ユーザーメニューに「ログアウト」を置いた。押すとユーザーなしになり(メニューとユーザーが消える)、ログアウト画面(`LogoutDestination` → `/logout`)へ遷移する。
- 認証(Keycloak)が無いため、ログアウト画面には仮の「ログインする(仮)」ボタンを置き、標準のユーザーに戻す。CLAUDE.md の仕様(5秒後にログイン画面へ遷移)とログイン画面は、認証の導入後に実装する。

### 5. メニューの遷移
- 本番アプリのメニューの項目は、`TopLevelDestination`(`feature_shared`)で包んで CommandBus に通す。ナビゲータが積まずに枠の中の画面を入れ替える。ダッシュボードの項目だけは、アプリ自身が持つルートのため `go` で開く(機能の遷移先ではない)。

## 確認
