## A. 設定の保存(settings_keeper)
- `feature_shared` に `UserSettingsOriginator`(`settings_keeper` の持ち主)を置いた。保存する値は、使用言語(実行環境に従うか・言語)、サイドバーをアイコンだけにする設定、ユーザー名と役割。ログアウト中はユーザーを保存しない。
- `userSettingsAutoSaveProvider` が変更のたびに保存する。保存先(`SettingsStorage`)は知らず、アプリが `settingsStorageProvider` を Riverpod で差し込む。`pms_app` の `main.dart` は `%APPDATA%\pms_app` の `FileSettingsStorage` を差し込み、起動時に復元してから保存を始める。保存・復元の失敗は `settings_keeper` がログに残し、標準の設定で起動する。
- 設定画面の使用言語の選択は、`localeFollowsSystemProvider` と `localeProvider` から求める(復元後も合う)。
- テスト: `feature_shared` に保存→復元、保存なし、ログアウトの3件。

## B. 親の付け替え(ハンドラ)
- `EntityListPage.onReparent` と `EntityFeatureModule.reparentHandler(ref, entityKey)` を追加した。ハンドラがある実体のツリー台帳だけ、ドラッグ&ドロップを有効にする。更新と検証(循環・権限)は利用者がハンドラで実装する。ハンドラの完了(失敗を含む)後に台帳を再読み込みし、実際のデータに合わせる。
- どの機能も、現時点ではハンドラを実装していない(部署・場所は従来どおり付け替え不可)。実装が決まった機能から、`reparentHandler` を override する。

**条件(新しい項目の種類)**: 演算子(`=`・`≠`・`>`・`<`・`>=`・`<=`・範囲(`between`)・二値(`yesno`))をリストから選び、値を手で入力する。値は JSON の文字列(`{"operator":">=","value":"10"}`、範囲は値が2つ、二値は真偽)。台帳では `>= 10`・`1 〜 5`・`Yes` と表示する。取得元は、読めない値を検証エラー(`invalidCondition`)にする。テスト: `entity_screens` に `condition_test.dart`。
