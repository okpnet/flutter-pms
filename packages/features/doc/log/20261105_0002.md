# 20261105_0002 ログイン/ログアウトの集約、`20261105_0001` の提案への対応

指示: `issue/20261105_0002.md`。

## 1. ログイン/ログアウトの画面: 調査・評価・集約

### 調査(変更前)
| 場所 | 画面 | 役割 |
|---|---|---|
| `auth_files` | ログイン(`/auth/login`) | PocketBase の認証。画面案の構成 |
| `pms_app`(旧 mock_up) | ログイン(`/login`、`Login`・`LoginRouter`) | PocketBase に接続しないときの最初の画面(モック。資格情報をモックの認証サービスで確認) |
| `app_core` | ログアウト(`/logout`、`LogoutPage`) | ログアウトの実体は `signOutProvider`(アプリが `auth_files` の関数に上書き)と、ログイン先 `signInDestinationProvider` を介して、`auth_files` を呼ぶ遠回しな作り |
| `app_core` | ログイン(画面コード `AL`) | 「認証の導入後に追加する」とされたまま未実装の枠 |
| `pms_authenticator` | Keycloak | 着手しない(ルート CLAUDE.md) |

問題点: ログインとログアウトは、セッションの開始と終了という同じ機能なのに、画面が3か所(うち2つは重複するログイン)に分かれ、見た目(画面案の構成)・文字列・処理がそろっていなかった。`app_core` は `auth_files` に依存できないため、ログアウトの実体を差し込む2つの Provider が必要になっていた。

### 評価
別々にする理由はない。**ログイン・ログアウトは `auth_files` に集める**(認証=セッションの開始と終了、共有する枠・文字列・セッション処理が `auth_files` にあるため)。`app_core` は、ブート・ダッシュボード・エラー・設定だけにする。

### 実施
- **ログアウトを `auth_files` へ移した**: `LogoutDestination(sessionExpired)`・`/auth/logout`(セッション切れは `?expired=1`)・`LogoutPage`。画面案(`#/logout`)の構成で、確認(キャンセルでダッシュボード)→ ログアウト中 → 完了(5秒のカウントダウンのあとログイン画面。「今すぐログイン画面へ」でもすぐ進む)。セッション切れ・すでにログアウトしているときは、確認を出さずにログアウトして完了を案内する。失敗してもログに残して完了を表示する。
- **ログアウトの実体**: `auth_files` の `signOutProvider`(既定は `authFilesSignOut`)。`app_core` の `signOutProvider` は廃止。
- **ログインの一本化**: `pms_app` の旧ログイン画面・ルート(`/login`)・`LoginConstant`・関連ファイル(`contents/authorization`)を削除。最初の画面は常に `/auth/login`。PocketBase に接続しない(`POCKETBASE_URL` なし)ときは、`AuthMode.provisional`(`authModeProvider`)で、ログイン画面が資格情報を求めず、標準のユーザーでログインする開発用にした(これまでの「ログインする(仮)」の置き換え)。`AuthMode.provisional` のログアウトは、ユーザー表示を消すだけ。
- **app_core**: `LogoutPage`・`LogoutDestination`・`signOutProvider`・パス・文字列を削除。`signInDestinationProvider`(他の機能が `auth_files` に依存せずログインへ向かうための窓口。`backstage` が使う)だけを残した(`sign_in.dart`)。
- **画面の部品**: ブート・エラー・ログアウトの「中央のカード」を、`app_shell` の `StatusCard`・`StatusIcon` に共通化した。

### 関連する機能の調査と修正
- `pms_app`: `AppMainFrame` のログアウトは `auth_files` の `LogoutDestination`。`sessionOverrides` から `signOutProvider` の上書きを外し、`authModeProvider` を上書き、`signInDestinationProvider` は常に `LoginDestination`。`root_router` の最初の画面と `authRedirect` の `openPaths`(ログアウト〔完了の表示〕を追加。ログインしていない状態で開けるようにするため)。`mock_core_service` のログインへの遷移先を `AuthFilesPaths.login` に変更。`contents_control_router`(型付きルート)から `LoginRouter` を除き、`build_runner` で再生成。
- `backstage`: `signInDestinationProvider`(app_core)を引き続き使う。変更なし。
- `app_core` の example・テスト: ログアウトとその状態切り替えを削除。`auth_files` の example に、ログアウト(確認から・セッション切れ)を追加。
- ページ一覧: `access_paths`(`.js`・`.csv`)から `/logout`(app_core)・`/login`(pms_app)を外し、`/auth/logout`(auth_files、ログイン前から開ける)を追加。画面コード(`page_codes.js`・`page_code_list.yml`): app_core の `logout`(AO)・`login`(AL)は `removed: true` で残し、`auth_files` に `logout`(UO)を追加。
- 仕様: `auth_files/CLAUDE.md`・`app_core/CLAUDE.md`・`features/CLAUDE.md`(AppCore の画面、ユーザーメニュー、機能の表)・`pms_app/CLAUDE.md` を更新。

## 2. `20261105_0001` の提案への対応

| 提案 | 採択 | 対応 |
|---|---|---|
| 1. `--focus`・`--seg-1`・文字の大きさ | あわせる | `theme_lib` に `AppColors`(`ThemeExtension`: surface2・muted・line・accentSoft・seg1/2/3・focus)を追加。`ColorScheme` から作り、focus だけ色の個別指定 `focus` で変えられる。`focusColor` も設定。文字の大きさ(28/20/16/14/12・太さ・行高 1.6)を全テーマに適用 |
| 2. ログアウト・ブートを画面案の構成に | あわせる | ブート(進行中・見出し・説明・進行バー)とログアウト(上記)を、画面案の中央のカードに。エラーと同じ部品 |
| 3. `ocean`・`forest` を完成させる | 採択 | 既定と同じ全項目(色の個別上書きの全項目、ライト・ダークの両方、数値、focus)を指定し、画面案と同じ構造にした。コントラスト(文字 4.5:1・枠 3:1)をテストで確認 |
| 4. 設定画面にテーマ変更。`ocean`・`forest` は外部ファイルでテーマライブラリから取り込む。テーマ内の設定は別のアプリ | 採択 | `ocean`・`forest` を `theme_lib/themes/*.json`(アセット)に移し、組み込みは既定の1つだけにした。`ThemeManager.importAssets`(`ThemeAssets.all`)で取り込む(失敗は返して起動を止めない)。設定画面(`app_core`)に、表示モード(システム/ライト/ダーク)と配色のテーマの選択を追加し、`UserSettingsModel` の `themeId`・`themeMode` として保存・復元。`pms_app` は起動時にテーマを取り込んでから設定を復元する。テーマの中身の編集は実装しない |
| 5. フォントは標準/システム、同封するならメイリオ | 採択 | OS のフォントだけを使う(Hiragino Sans → Yu Gothic UI → Meiryo)。Noto Sans JP を外し、同梱しない。仕様に「同梱が必要になったときはメイリオ」を記載 |

## 4. 互換性・注意
- **破壊的変更**: `app_core` の `LogoutDestination`・`signOutProvider`・パス `/logout` を削除し、`auth_files` へ移した(使っていたのは `pms_app` と example・テストだけ)。`themeManagerProvider` を `app_core` が読むため、アプリ・テストは `themeLoggerProvider` を上書きする。
- `ocean`・`forest` は組み込みではなくなった(`themes/*.json` を取り込むまで選べない)。`ThemeManager` の初期状態は既定の1つ。
- 開発用(`AuthMode.provisional`)は資格情報を確認しない。本番のビルドでは `POCKETBASE_URL` を指定すること。裏設定の入口(ID とパスワード)は開発用では使えない。

## 5. 課題・提案
1. `pms_app` に、使われなくなったモックの認証(`mockAutorizeService`・`MockAuthState`・`AuthenticatorPageSession`・`pms_authenticator` への依存、`lib/i18n` のログイン用の文字列)が残っている。`pms_authenticator`(Keycloak)に着手しない方針のため触っていない。整理は別の Issue で。
2. `page_codes.js`・`access_paths.js` は、この環境に Node.js が無く実行できていない(`page_code_list.yml`・`access_paths.csv` は手書き)。再生成して差分が無いことを確認する。
3. 画面案のブート・ログアウトの文言(アプリ名入りの見出し)は、アプリ名を引数にせず固定の文言にしている。アプリ名を入れる場合は slang の引数にする。
4. `theme_lib` の `AppColors` の seg1/2/3 は primary/secondary/tertiary と同じ。画面案の従業員区分のような別の色が必要になったら、色の個別上書きに足す。
5. 日本語フォントの同梱が必要になった場合は、メイリオを同梱する。ライセンスを確認すること。
