## 1. 承認できる人
- **views の Yaml に存在する**(`company/approval.yaml`)。`ApprovalReadFields` / `ApprovalEditFields`(`mstr_approval`)が「承認者明細 / 承認権限情報」で、列は部署(`info_department_id`)・役職(`info_position_id`)・優先順位(`priority`)・名称(読み・略称)・記号・備考。承認パターン(`mstr_approval_pattern`)は、明細(`mstr_approval_pattern_detail`)を通してこの承認を持つ。前回「Yaml が見つからない」としたのは誤りだった。
- 承認パターンの子の台帳として「承認できる人」(`approver`)を戻した。項目は名称・読み・略称・部署・役職・優先順位・備考(DB の列だけ。前回の有効期間・種別・担当者は DB に無いので持たない)。画面案のサンプルの承認範囲(段階・役職・組織)から作った。
- 承認範囲(`ApprovalScopePage`)は、`mstr_approval_scope_pattern` がアクセスパス承認(`info_access_path_approval_id`)への参照だけを持つ。段階・役職・対象組織は DB に無く、アクセスパス承認の画面も無いため、画面は作らない(0011 の指示「不要」のまま)。
- 明細(`mstr_approval_pattern_detail`)と承認(`mstr_approval`)は 1 対 1 で編集するため、画面では 1 つの子の台帳(承認できる人)にまとめた。

## 2. 設備の品目を、品目の画面で選んで戻る(コマンド)
- 設備(`mstr_equipment`)は品目(`mstr_item_id`)を持ち、設備名は品目の名称。設備の項目を「品目(設備名)」の参照にして、品目の台帳で選んで戻る方式にした。
- 項目の定義に `picker`(選択方式の参照)を追加した。編集画面は、選んだ 1 件の表示名と「選択」「解除」のボタンを出す。
- 選択は CommandBus の `EntityPickerDestination(entityKey)`(結果は選んだ行の id または null)。`EntityFeatureModule` が `/e/<キー>/pick` のルートを用意するため、すべての実体で使える。機能同士はコンパイル時に依存しない(設備は `item` のキーを渡すだけ)。
- 選択画面は新規登録のボタンが無い台帳で、行の操作(ダブルクリック・長押し)で選んで戻る。
- 生成元は `tools/entity_gen/handwritten.js`(`picker: true`)。再生成済み。
- 表示: 名称(`name`)を持たず、選択方式の参照で名称を借りる実体は、他の実体から選ぶときの表示を「コード + 参照先の表示」にした(例: 設備は「E-001 I-1000 ユニットA」)。編集画面の削除の確認も同じ表示。登録簿の `labelOf` が参照先をたどって求める。
- テスト: `entity_screens`(選択方式の編集、選択画面、借りた名称の表示)、`pms_app`(設備の編集から品目の台帳を開き、選んで戻る)。
