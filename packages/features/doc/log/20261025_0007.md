# 20261025_0007 残りのプロジェクトの画面の生成

## 内容
Html のトップメニューに対応する、画面が空だった11プロジェクトに、台帳(テーブル構造/ツリー構造)と編集(編集構造)の画面を生成した。
対象: `resource`・`system`・`item`・`production_process`・`purchasing`・`production_plan`・`work_record`・`quality_common`・`quality_document`・`quality`・`organization`。`sales` は受注(受注・受注明細)を足した(顧客台帳は専用の画面のまま)。`shared_master` は専用の画面のまま。

## 方針(判断したこと)
- 実体が101あり、1つずつ手書きすると差と誤りが増えるため、**実体の定義から画面を作る方式**にした。Html の画面定義(`tools/open-design`)も同じ「共通エンジン」で作られているので、見た目と振る舞いを合わせやすい。
- 専用の画面(顧客・配送区分)は、これまでどおり手書き。表(`flgtable_lib`)・多言語(slang の Yaml)・データ取得(`data_strategist`)・Riverpod の注入・String の id・削除の参照チェックは、手書きの画面と同じ規則を守る。

## 追加したもの
1. **`packages/ui/entity_screens`**(新規): 実体と項目の定義(文字・複数行・数値・日付・選択・参照)、取得元(`IEntityRepository` と `InMemoryEntityRepository`。必須・数値・日付・選択肢・ツリーの循環の検証)、登録簿(`EntityCatalog`。参照の選択肢、使用中・配下がある場合の削除不可、所有する子の連動削除)、画面(台帳=`EntityListPage`、編集=`EntityEditPage`。ツリーは`TreeTable`、子の台帳は編集の下に表示)、共通の文字列(slang、日本語・英語)。
2. **`feature_shared`**: `EntityFeatureModule`(Template Method。定義・サンプル・表示名を渡すだけでルート・遷移先・登録が済む)、`EntityListDestination`・`EntityEditDestination`、`entityScreenStringsProvider`。
3. **生成ツール `tools/entity_gen`**: `gen.js`(本体)、`handwritten.js`(会社情報・資源の定義。`tools/open-design/data.js` の値から作る)、`examples.js`(example)、`menu.js`(アプリのメニュー)、`claude.js`(CLAUDE.md の一覧)。再生成はリポジトリのルートで `node tools/entity_gen/gen.js`。
4. **各プロジェクト**: `lib/src/entities`(定義・サンプル・表示名)、`lib/src/i18n`(slang の Yaml。実体名・項目名)、`slang.yaml`、モジュール、`test/<名前>_entities_test.dart`、CLAUDE.md の実体の一覧、example の遷移先。
5. **アプリ(`pms_app`)**: 全モジュールを `featureModules` に追加。ホームに、トップメニューのグループごとの業務メニュー(暫定)を追加した。`sales`・`shared_master` は参照先の選択肢(顧客・配送区分)を登録簿へ登録する。

## 提案・課題
1. **サンプルの補完**: Html のサンプルで必須の参照が空だった `preventiondetail.info_department_id` は、部署の先頭で補った(生成時の警告に出る)。
2. **顧客の担当者・サプライヤーの担当者**: Html の `custcontact`・`suppcontact` は、顧客が専用の画面のため未対応(`suppcontact` は生成済み)。顧客の編集を拡張するときに、担当者の子の台帳を足す。
3. **力量・資格の保持者**: 資源の画面の「保持者」は、作業者側の台帳(作業者の力量・資格)から逆引きする表示が未対応。
4. **GraphQL 版**: 取得元はすべてメモリ上のサンプル。`IEntityRepository` を GraphQL で実装して差し替える。画面定義(`graphql_provider_lib`)が無い実体は、先に定義の追加と生成が必要(0006 の課題)。サーバー側のフィルタ・ソート・ページングへの変換も未対応。
5. **項目名**: 手書きの定義(会社情報・資源)の項目名と、Html の画面定義の項目名は、DB のコメント(`schema.graphql`)が無いため仮。英語の項目名は未用意(日本語を使う)。
6. **重複チェック**: Html にあるコード等の重複不可は、実体の定義に持たせていない(必須・形式・選択肢・参照・循環のみ)。DB の一意制約が分かるものから足す。
7. **メニュー**: アプリのホームの業務メニューは暫定。`app_shell` とメニュー項目の提供(0006 の提案)を決めたら置き換える。
8. 実体の画面の見た目は、Html とは細部が異なる(検索・列の表示切り替え・ドラッグドロップによる親の付け替えは未接続。親の付け替えは編集の「親」で行える)。
