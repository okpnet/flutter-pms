# 20261025_0005 shared_master の実装(配送区分)と organization の契約方針

## 実施
1. **organization の方針変更**: `organization_api` パッケージは作らない(他のプロジェクトに合わせる)。契約は必要になった時点で `lib/organization_api.dart` に公開する。`organization/issue/20261025_0001.md` を追加し、`organization/CLAUDE.md` に統合した。`20261021_0001.md` は削除せず残した(新しい issue が項目2を置き換える)。
2. **shared_master の実装**(配送区分):
   - 台帳: `FlgTable`(`flgtable_lib`)。列は `code/name/pronunciation/nickname/remarks`、ソート・フィルタ有効。行の操作で編集へ、「新規」ボタンで登録へ。
   - 編集: 配送区分コード*・配送区分名称*・読み・略称・備考。コード・名称は必須、コード重複不可。削除は確認ダイアログ。
   - 選択: `ShippingKindPickerDestination`(id を返す)。名称取得: `FindShippingKindNameCommand`。
   - データ: `IShippingKindRepository`(`data_strategist` の `IDataRepository` を拡張)。現状はメモリ上のサンプル実装で、`shippingKindRepositoryProvider` を差し替える設計。
   - ログ: `loggerProvider` を直接取得し、`[shared_master]` 付きでこの機能が発生元のエラーだけを出す。入力検証エラーは画面表示のみ。
   - 契約は `lib/shared_master_api.dart`、実装の入口は `lib/shared_master.dart`(`SharedMasterModule` は Composite で配送区分のモジュールを束ねる)。
3. **アプリへの組み込み**: `featureModules` に `SharedMasterModule` を追加。ホームに「配送区分台帳を開く」を追加し、遷移を確認するテストを足した。

## 確認
`flutter analyze` 問題なし。`flutter test`: shared_master 11件(モジュールの遷移先、リポジトリの取得・登録・更新・検証・削除、provider 経由の取得、台帳の表示、編集の表示・必須エラー、未存在 id)、pms_app 3件が成功。

## 提案・課題
1. GraphQL 版リポジトリは未実装。名称・読み・略称は名称辞書(`labels`)の値で、更新者・更新日は未対応(編集構造では編集不可にする)。`id` は GraphQL では UUID のため、GraphQL 版では型の見直しが必要(サンプルは int)。
2. 台帳のソート・フィルタはテーブル側(メモリ)。取得は上限1000件。
3. 列ラベル(配送区分コード/配送区分名称/読み/略称/備考)は仮。`schema.graphql` にコメントが無いため。
4. 削除時に、その配送区分を使っている顧客・受注・サプライヤーがある場合の扱いは未実装(参照チェックが必要)。サンプルは無条件に削除する。
5. `sales` の顧客台帳が持つ配送区分の選択(`ShippingKindPickerDestination` の利用)は未接続。顧客の編集画面を拡張するときに、`shared_master_api.dart` の型で接続する。
6. 営業・購買のメニューから配送区分を開く経路(メニューの配置)は未決定。現状はホームのボタンのみ。
7. slang による多言語化は未導入。
