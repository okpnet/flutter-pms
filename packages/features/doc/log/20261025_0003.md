# 20261025_0003 Html のトップメニューに従った機能プロジェクトの作成

## 内容
`tools/open-design`(`app.js` の `NAV`、`domains.base.js` の `groups`)のトップメニューに従い、次の11プロジェクトを `packages/features` に作成した。
`resource`(資源)、`system`、`item`、`production_process`(工程)、`sales`、`purchasing`、`production_plan`、`work_record`、`quality_common`、`quality_document`、`quality`。
ダッシュボードは AppCore(アプリ側)、会社情報は既存の `organization` が担当するため作成していない。

各プロジェクトの構成: `pubspec.yaml`、`analysis_options.yaml`、`lib/<name>.dart`(バレル、公開は `XxxModule` のみ)、`lib/src/<name>_module.dart`(`FeatureModule` の空実装)、`test/`(モジュール生成のテスト)、`CLAUDE.md`、`doc/log`、`doc/contents`、`issue`。
`CLAUDE.md` には、画面(Html のメニュー)、参照する `graphql_provider_lib/source/views` の yaml、実装の指針、規則/仕様を記載した。
`packages/features/CLAUDE.md` に、メニューとプロジェクトの対応表を追加した。

## 判断したこと
1. 契約用の `xxx_api` は作っていない。他の機能から遷移先・命令が必要になった時点で追加する(空のパッケージを増やさないため)。
2. `process` は pub パッケージの `process`(melos の依存)と名前が衝突して `pub get` が失敗したため、`production_process` にした。
3. アプリ(`apps/pms_app`)の `featureModules` にはまだ追加していない(画面が無く、ルートも空のため)。

## 提案・課題
1. `sales` と既存の `customer` の関係。顧客台帳を `customer` のまま残すか、`sales` に統合するかを決める(統合する場合 `customer_api` の扱いも)。
2. `purchasing` と `sales` に「配送区分」が重複している(Html も同様)。どちらかの画面に寄せるか、共有の置き場を決める。
3. 品質共通・品質管理の参照 yaml(`quality/*.yaml`)の割り当ては、ファイル名からの推定。画面実装時に確認する。
4. `work_record` の購入受入は `purchase` 側のビューも参照する可能性がある。
5. `organization/lib/company/comapny_module.dart` が壊れたまま(0001 の課題 3)。
6. 各プロジェクトは画面が空。実装の優先順位を決める。
