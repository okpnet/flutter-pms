# 20261106_0001 裏設定の入口の暗号化と、設定ファイルの外部置き換え

指示: `issue/20261106_0001.md`(`toold` は `tools` の誤記として扱った)。

## 確認の結果
| 確認 | 結果 |
|---|---|
| 入口のパスワードも暗号化して保存するのか | **暗号化ではなく、一方向のハッシュ**(PBKDF2-HMAC-SHA256、ソルト付き、100000 回)。ID とパスワードをつないだ値からハッシュを作り、アセットには `salt`・`iterations`・`hash` だけを置く。元の値は取り出せない |
| 一度決めたら変更できないか | **変更できる**。ツールで作り直した `entry` を `apps/pms_app/assets/backstage.json` に貼り替え、アプリを再ビルド・再起動する(アプリの実行中に変える手段は無い) |
| 暗号化ツールの情報が `features/CLAUDE.md` に無かった理由 | ツール(`backstage/bin/make_entry_hash.dart`)は在ったが、記載はルートの `CLAUDE.md`・`backstage/CLAUDE.md`・README だけだった。今回 `features/CLAUDE.md` と `auth_files/CLAUDE.md` に追加 |
| 外部から裏設定ファイルを置き換えできるか | **できなかった**。アセットはビルドに含まれ、実行時の値は OS の保管庫にあるだけで、ファイルの取り込みは無い |
| 設定ファイルの暗号化ツール | **無かった**ので新規作成 |

## 実施
1.  `tools/config_user_generator`: `backstage/bin/make_entry_hash.dart` を**移動**(単独の Dart パッケージにし、PBKDF2 を同梱。`--help`・`--out`・反復回数)。`doc/usage.md`。テストはアプリの `EntryHash` と同じ固定値を確認(アプリ側 `backstage_test.dart` にも同じ値のテスト)。
1.  `tools/config_generator`(新規): AES-256-GCM + PBKDF2。入力・出力を省略すると同じフォルダの `backstage_config.json` → `backstage_config.enc.json`。`--decrypt`・`--passphrase-file`・`--iterations`・`--help`。`doc/usage.md`。平文・暗号化ファイルは `.gitignore`。テスト4件。
1.  文書: `features/CLAUDE.md`(裏設定の手作業)、`auth_files/CLAUDE.md`、`backstage/CLAUDE.md`・README、ルート `CLAUDE.md`・`WORKSPACE.md` のコマンドをツールの新しい場所へ。

## 追加(提案に対する追加)の対応
指示: 設定ファイルを取り込むのではなく、入口のパスワードをパスフレーズにする。復号できないときは標準(通知しない)。共有のリスクは提案する。
1.  `config_generator` のパスフレーズ = 入口のパスワード(ヘルプ・`doc/usage.md` を更新)。平文は裏設定の項目そのもの。
1.  アプリ: `backstage` に `encrypted_config.dart`(復号。`pointycastle` を依存に追加)、`BackstageEntryGate.afterMatch`、`BackstageController.applyEncryptedConfig`、`BackstageBoot.encryptedConfig`。`pms_app` が exe と同じフォルダの `backstage_config.enc.json` を読む。復号の失敗・検証の失敗は何もせず標準のまま(通知もログも出さない)。保管庫に値があれば上書きしない。
1.  テスト: ツールで作った見本の復号、パスワード違い・形式違いは null、保管庫が空なら保存・違えば変えない・値があれば上書きしない。

## 提案: パスワードを共有するリスク
入口のパスワードが「ログインの入口」と「設定ファイルの鍵」を兼ねるため、共有の影響が大きい。
| リスク | 内容 | 提案 |
|---|---|---|
| 共有した全員が設定を作れる・適用できる | パスワードを知る人は誰でも設定を暗号化でき、入口も通れる | 共有は制作者の最小限に。人が代わるときはパスワード(ハッシュ)を作り直し、設定も暗号化し直す |
| 漏れたとき両方が破られる | 入口と設定ファイルの鍵が同時に漏れる | 長いパスフレーズ(16文字以上)にする。漏れたら入口のハッシュと暗号化ファイルを作り直して配り直す |
| 総当たり | ハッシュはアセット、暗号化ファイルは exe の隣にあり、取得されるとオフラインで試される | 反復回数を上げる(入口 200000 以上、設定 既定 200000)。強いパスワードにする |
| 失効できない | 旧パスワードで作った暗号化ファイルは、旧パスワードを知る人なら今後も復号できる | 設定を変えるたびにパスワードも変える。旧ファイルは配らない・回収する |
| 平文の残り | 作業用の `backstage_config.json`・`--passphrase-file` のファイルが残る | 作業後に削除(`.gitignore` 済み)。パスフレーズをファイルに置かない |
| 適用は保管庫が空のときだけ | 設定を更新しても、既に値がある端末は変わらない | 更新するときは「保存した値を消す」を案内する(必要なら、暗号化ファイルの世代番号で再適用する案を別途検討) |

## 確認
- `tools/config_generator` `dart test` 4件、`tools/config_user_generator` `dart test` 2件、解析は問題なし。
- `backstage` `flutter test` 全件成功(暗号化した設定の適用を追加)。`pms_app` の解析は新規の問題なし。
