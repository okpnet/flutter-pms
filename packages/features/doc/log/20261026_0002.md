## 1. ページ用の拡張(page_mediator)
- **データ取得**: `IPageDataMediator.fetch<R>(IQueryState<R>)`。ジェネリックにした(結果が一覧・件数・1件などページごとに違い、`Object` では呼び出し側の変換が増えるため)。失敗は `[page_mediator]` 付きでログに残して再送出する。
- **設定の保存**: `IPageSettingsMediator`(`restore`・`save`・`clear`)。`SettingsKeeper` へ委譲する。保存先はアプリが `settingsStorageProvider` で決める。
- **セッション確認**: `IPageSessionMediator`(`check`・`refresh`)と `PageSessionStatus`(有効・期限切れ・ログアウト・メンテナンス・不明)。既定は何もしない実装(`NoopPageSessionMediator`)で、**テストでは差し込まない**(指示 3-1)。
- **pms_pkce_lib について**: `pms_pkce_lib` は `legacy` にあり、ワークスペースには `packages/features/pms_authenticator`(移設済みの Keycloak 認証)がある。セッション確認は、その `AuthController`(`checkAndApplyExpiration`・`refreshToken`)を使う想定。core が features に依存できないため、**この実装はアプリが差し込む**(下記の「未実施」)。
- **形**: `mixin PageMediatorMixin`(with。`ConsumerStatefulWidget` 向け。`enterPage()` で表示・更新のタイミングにセッションを更新して確認し、使えなければ `onSessionUnusable`)と、`extension PageMediatorRef on WidgetRef`(`ref.pageData` など)。どちらもインターフェイス経由。

## 2. メンテナンスページ(maintenance)
- メンテナンスページ(`/maintenance`)は、文面・実施時間・「再確認」だけを持ち、枠・戻る・リンクを持たない(メンテナンス中は戻る操作も無効)。ルートは `ShellRoute` の外に置く。
- **他のページへリンクできない**: ルーターの `redirect` に `maintenanceRedirect(status, location)` を使うと、メンテナンス中はどのページもメンテナンスページへ向く。終わっていればメンテナンスページから戻す。
- **ログイン中でも切り替わる**: `MaintenanceAwarePageSession`(`page_mediator` のセッション確認の Decorator)が、ページの切り替え・更新(`refresh`)で、認証の確認より先にメンテナンスを確認する。メンテナンスなら `PageSessionStatus.maintenance`。
- **サーバーの応答**: `HttpMaintenanceChecker` は HTTP 503 をメンテナンス中とする(`tools/open-design/maintenance.html` の「HTTP 503 + Retry-After を推奨」に合わせた)。本文が JSON なら `message`・`startAt`・`endAt` を読む。通信できないときは利用可能として扱う(メンテナンスと断定できないため)。通常の通信(GraphQL)の応答が 503 のときは `MaintenanceStatusNotifier.report` で知らせる。

## 3. カスタムコンテナ(dashboard_container)
- コンテナは Full・1/2・1/4。表示できる件数の項目は、3つ・2つ・1つ(並べた項目の先頭から)。領域(`DashboardContainerArea`)は幅に応じて並べる(全幅・1/2・1/4。狭い画面は全幅)。
- 項目1つにフィルタグループ(区分、利害関係者(顧客・外部)など)を1つ対にして、選んだ項目の件数を表示する。選択は設定として保存する。
- **設定に保存・表示時に読込**: 配置は `DashboardContainerSettings`(JSON)で、`page_mediator` の設定の窓口(`settings_keeper`)に保存する。領域の表示時に復元する。
- **件数の元**: `ICountSource` を機能・アプリが `countSourcesProvider` へ差し込む。`RepositoryCountSource` は、件数を返す取得元(`IDataRepository<int>`)から `page_mediator` のデータ取得で数える。DB の元(当日出荷・進捗遅延の件数)は `graphql_provider_lib` の 20261026_0004(`ShippingTodayPage`・`WorkPlanDelayPage`、`totalCount`)にある。
