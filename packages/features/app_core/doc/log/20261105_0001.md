## 実施内容
1. `example/`(Windows 向けのビジュアルテスト用アプリ)を追加。`flutter run -d windows`(`example` で実行)。
   - 本番と同じ配線の `FeatureHost` に `AppCoreModule` を載せる。
   - 一覧: ブート / ダッシュボード / エラー(内容なし・あり) / 設定 / ログアウト / 状態の切り替え。
   - 「状態の切り替え」(example だけのモジュール `ConditionsModule`)で次を切り替え、画面を目視で確認できる。
     - ログアウトの実行が失敗する(失敗しても画面は表示される)
     - ログイン画面の遷移先がある(ボタンが「ログイン画面へ」/「ログインする(仮)」)
     - ダッシュボードの件数の元がある/ない
   - 依存関係上必要なもの(`feature_shared`・`dashboard_container`・`settings_keeper`・`theme_lib`・`logger_provider`)のみ参照。件数の元・保存先・ユーザーはこのプロジェクト内の代役。
2. `BootDestination`(`/boot`)を契約に追加。ブート画面にルートはあったが遷移先が無く、example(CommandBus 経由)から開けなかったため。見本の登録漏れ検出にも追加。
3. `example/test/widget_test.dart`: 5画面の起動・状態切り替えを確認(5件)。

## 提案・課題
1. ブート画面は読み込み中のスピナーが止まらないため、テストは `pumpAndSettle` でなく `pump` を使う。
2. ログイン画面は認証導入後に追加予定(未実装)。追加時に example の一覧と状態の切り替えにも足す。
3. 設定画面の保存・復元(`UserSettingsOriginator`)の状態は example では確認していない。必要なら保存先の切り替えを追加する。
4. ログアウト画面の「失敗」はログにだけ残る(画面に出ない)。利用者への通知が必要か検討。
5. 「ブート」はルートが `/boot` のみで、アプリ側の実際の利用箇所が見当たらない。利用予定がなければ整理を検討。
