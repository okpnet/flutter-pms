# 20261027_0002 DB変更への追随(生成結果レポート)

対応する指示: [issue/20261027_0002.md](../../issue/20261027_0002.md)

## DB変更

1. `trans_purchase_detail` に `cost`(単価、`BigFloat!`、NOT NULL)を追加
2. `v_purchase_amount` が単価を使うようになり、`purchase_amount` と `received_amount` の列が増えた
3. `info_address` の `iso3166_2` 列を `country_code_2` に改名(履歴テーブルも変更。履歴は YAML で参照していないため影響なし)

指示書の `iso3661` は、YAML 上の実際の列名 `iso3166_2` のことと解釈した。

## 変更したファイル

| ファイル | 内容 |
| --- | --- |
| `gql_shared/gql/all_common.yaml` | `AddressReadFields` と `AddressEditFields` の `iso3166_2` を `country_code_2` に変更 |
| `purchasing_model/gql/purchase.yaml` | `PurchaseDetailPage` と `PurchaseDetailPageEdit` に `cost` を追加 |
| `purchasing_model/gql/purchase_amount.yaml` | `purchase_amount` と `received_amount` を追加 |
| `organization_model/lib/src/contents/company_page_keyname.dart`、`office_page_keyname.dart` | 手書きの `address_iso31662` / `'address||iso31662'` を `address_countryCode2` / `'address||countryCode2'` に変更 |

上記以外(`lib/src/graphql/` の `.graphql` と `schema.graphql`、`*.graphql.dart`、`*_filter_spec.dart`、バレル)は生成物。

## 実行した手順

`melos` が未導入だったため、`pubspec.yaml` の melos スクリプトと同じ内容を直接実行した。

1. `gql:schema` … `fetch_schema.dart` で本家スキーマを再取得(`.schema/schema.graphql`、Git 管理外)
2. `flutter pub get`(ルート。tools のパッケージを解決するため)
3. `gql:yaml` → `gql:prune` → `gql:filter` → `gql:build:runner`(各モデルパッケージ) → `gql:barrel`

`gql:prune` の検証は通った。生成物に差分が出たのは item / organization / purchasing / quality / resource / sales / work_record。差分が無かったのは production_plan / quality_document / system。
