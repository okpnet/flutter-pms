# 20261101_0004 棚ビジターの関数(DB 07)の取り込みと ScanClient の更新

issue `20261101_0004.md`(`20261101_0003` ログへの対応)を実行した。

## 実施

1. 本家スキーマを再取得。`visiterIssue` / `visiterMove` / `visiterAdjust` と、`v_visiter_issuable.symbol` が入った。
2. 生成ツールに `kind: function`(`~PageCall`)を追加した(`tools/gql_yaml2graphql/lib/src/function_generator.dart`)。DB の関数のミューテーションを、入力の名前のまま変数にして作る。YAML は `work_record_model/gql/visiter_ledger.yaml` の `VisiterIssuePageCall`・`VisiterMovePageCall`・`VisiterAdjustPageCall`。`page.md` に追加。変換器のテストを2件追加。
3. `ScanClient`:
   - `issueLot` / `moveLot` / `adjustLot` は関数を1回呼ぶだけにした(行と受払実績はDBがまとめて作る)。引数はロットの id、移動先の棚の id、数えた数(棚卸しは差ではなく数えた数)。`ScanVisiter` を受け取らなくなった。
   - `ScanClientException.code` に errcode(`VIS03` など)を持たせた。
   - `listVisiters` は `v_visiter_issuable` の1回の読み込みにした(`symbol` 列を使う)。
4. `model_providers/CLAUDE.md` に「DB の関数の呼び出し」を統合。`barcode_entry_model/CLAUDE.md` を更新。

## 判断

- 出しすぎの検査はクライアントに置かない(DB の関数とトリガーが VIS03 で止める)。
- `extensions` の errcode は PostGraphile の `extendedErrors` の設定で位置が変わるため、`extensions.errcode` と `extensions.exception.errcode` の両方を見る。実サーバーでの確認はしていない(関数はデータを変えるため通信テストを書かない方針)。**PostGraphile の `extendedErrors` に `errcode` が入っているか確認してほしい。**
- 仮止め・異常の判定(VIS04)は DB の関数だけで行う。棚ビジターを直接登録して出庫の行を作ると、この判定を通らない(`createVisiter` の `parentVisiterId` は入庫の分割用に残している)。呼び出し側は出庫に `issueLot` を使う。
