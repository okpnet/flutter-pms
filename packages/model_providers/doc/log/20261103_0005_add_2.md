# 20261103_0005 追加2: symbol の撤回

指摘: `symbol` は DB のトリガーによる自動生成。

## 撤回したこと
1. 「`info_access_path.symbol` は一意制約で、空の symbol は 2 件目から衝突する」という判断(`20261103_0005.md` の 2.)。トリガー `trg_gen_symbol_seq`(`info_access_path` は `trg_04_symbol_info_access_path`)は、symbol が空のときに連番(33進数4桁)を付ける。空で登録すれば衝突しない。
1. 旧 pms_app の 4 ページへの `LG-` の symbol の付与。
1. `tools/docker/postgresql/issue/20261103_0002.md` の、symbol に関する記述と関数案の `p_symbol` 引数。

## 変更
1. CSV(`apps/pms_app/doc/contents/access_paths.csv`)から `symbol` の列を外した(列: usecase_path,name_ja,name_en,feature,public)。`tools/entity_gen/access_paths.js` の symbol・画面コードの処理と検査も外した。
1. 登録の mutation(`AccessPathPageCreate`・`DepartmentAccessPathPageCreate`・`StaffAccessPermissionPageCreate`)から `symbol` の列を外した。`AccessControlClient.createAccessPath`・`AccessPathSeed` は symbol を持たない(読み取りは残す)。
1. 画面(`access_control` の「ページアクセス」)から symbol の項目を外した。
1. CSV の位置づけ: 頻繁に使うものではなく、**初回の一括登録の元、または参考の一覧**。`apps/pms_app/CLAUDE.md` とスクリプトの説明に追記した。

## 登録済みのデータ(要判断)
先に登録した 79 件は、こちらが渡した画面コード(例: `YU`・`II`)が symbol になっている。トリガーは「空のときだけ」付けるため、自動の連番ではない。動作に問題は無い。自動の連番にそろえたい場合は、論理削除して登録し直す(テストサーバーのデータ)。
