## 結果

- `dart analyze packages/model_providers`: 指摘なし
- モデルのテスト(往復変換・RFE⇔Edit・検索条件の対応表): 全パッケージ通過
- 通信テスト(`server_read_test.dart`): organization / purchasing / quality / quality_document / resource / sales / system は通過。**item(1件)、work_record(1件)、production_plan(9件)が失敗**

## 失敗の原因(DB の権限)

失敗はすべて `permission denied for table|view ...` で、対象は次の10個。クエリはスキーマの検証を通っており、モデルの不具合ではない。

- テーブル: `trans_mrp_run`、`trans_mrp_suggestion`、`trans_mrp_suggestion_task`、`trans_mrp_pegging`、`trans_mrp_load`
- ビュー: `v_mrp_pending_suggestion`、`v_mrp_purchase_plan`、`v_mrp_master_issue`、`v_resource_plan_coverage`、`v_item_on_hand`、`v_mrp_visiter_item`

`tools/docker/postgresql/scripts/07_grant_test.sql` は `GRANT ... ON ALL TABLES` を一度だけ実行する。`08_mrp.sql` は、その後に作ったテーブルとビューへの権限を付けていない。`08_mrp.sql` の後に同じ GRANT を再実行する(または `08_mrp.sql` の末尾に追加する)と直る見込み。再実行したあと、各パッケージの `flutter test test/server_read_test.dart` で確認する。

## 未対応

- `mstr_equipment_available` / `mstr_outsource_available`(`delivery_interval` など)の読み込みと書き込みは、もともとモデルが無い。追加する場合は別の指示で。
- `mstr_item_task_cost` は工程場所との関係なので、品目の編集画面へ組み込む際は工程場所の選択肢を ID で引く。
