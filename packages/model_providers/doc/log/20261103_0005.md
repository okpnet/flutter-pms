# 20261103_0005 ログ 20261103_0004 への対応(issue 20261103_0005)

## 1. 「実行環境の自動判定で拒否された」の調査
**結論: アプリ側(あなたの設定)で許可すれば実行できる見込みが高い。こちらからは変えられない(自分で自分の権限を広げることになるため)。** 実行は未実施。
1. 拒否したのは、Claude Code のプロジェクトの権限ルールではなく、実行モードの自動判定(auto mode の分類器)。理由は「共有資源の変更(Modify Shared Resources)」。サーバー(PostGraphile `http://192.168.1.100:5000/graphql`)のデータを変更する操作が対象で、Issue の「テストサーバーなので続行してよい」の記述だけでは通らなかった。
1. 確認した設定: `.claude/settings.json`・`.claude/settings.local.json`(プロジェクト)は存在せず、`~/.claude/settings.json` に権限ルールは無い(`model` と `autoUpdatesChannel` だけ)。許可ルール(`permissions.allow`)が1つも無いので、すべて自動判定に任されている。
1. 拒否のメッセージが示す方法: 「`Bash` の許可ルールをユーザーの設定に追加する」。許可ルールは自動判定より先に評価されるため、ルールに合う操作は判定されずに実行できる見込み(実際の挙動はルールを足して試すまで未確認)。
1. 提案する許可ルール(狭く、プロジェクトの `.claude/settings.local.json` へ):
   ```json
   { "permissions": { "allow": [
     "Bash(flutter test --run-skipped --tags server_write*)"
   ] } }
   ```
   書き込みを実行するコマンドを固定した形にする(広すぎるルールは避ける)。ほかに、書き込み用のコマンドを決まったスクリプトにして、そのスクリプトだけを許可する方法もある。
1. 一時的なテスト(`test/server_register_access_paths_test.dart`、`server_write` タグ)は削除した。許可が済んだら、実行の直前に作って実行し、すぐ削除する(リポジトリには残さない)。
1. `git stash drop` も同じ分類器に拒否された(「不可逆な削除」)。後述の stash が残っている。

## 2. 登録の途中失敗の調査
`tools/docker/postgresql/issue/20261103_0002.md` に調査結果と関数の案(`access_path_create`)を書いた。要点:
1. 関数にできる(棚ビジターと同じ方式。1回の呼び出し = 1トランザクションで孤児が残らない)。1件の登録が 11 往復から 1 往復になる。
1. 要確認: 自動 CRUD の登録・更新で、監査列(`update_user_id` など)が埋まるか。関数は `visiter_staff()` で明示できる。
1. `info_access_path.symbol` は一意制約。空の symbol は 2 件目から衝突する。CSV の旧 pms_app の 4 ページは symbol が空だったので、`LG-` で始まる symbol を付けた(`tools/entity_gen/access_paths.js` が、公開でないページの symbol が空・重複のときに失敗する)。
1. `usecase_path` の一意制約は DB に無い(クライアントが調べてから登録)。
採否はあとで決める(現状のままでも運用できる)。

## 5. アプリの GraphQL 接続と JWT
1. `apps/pms_app/lib/services/graphql/graphql_overrides.dart`: `--dart-define=GRAPHQL_URL=...` を指定したときだけ `GraphQLClient`(`AuthLink` で `Authorization: Bearer <JWT>`)を作り、取得元を GraphQL 版にする。未指定はサンプルのまま。
1. JWT は `graphqlTokenProvider`(Riverpod)に保存する。通信のたびに読むので、更新すれば次の通信から反映される。
1. **未実装**: ログイン後に PocketBase の `GET /api/app/graphql-token` を呼んで `graphqlTokenProvider` に保存し、期限(既定15分)の前に取り直す処理。アプリに PocketBase のセッション(`pbapi`)がまだ無いため。ページ遷移時の権限確認(`IPageSessionMediator`)も同じ前提。
1. 部署・担当者の参照先の選択肢は、`organization` の取得元が GraphQL 版になるまで、サンプルの値のまま(id が合わない)。
