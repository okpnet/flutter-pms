# 20261103_0006 アプリの GraphQL 接続と JWT: pbapi の調査(issue 20261103_0005)

指示: PocketBase から JWT を取得するライブラリは `pbapi`。これが参照でき、組み入れ出来るか、及び必要かを調査する。

## 結論
1. **参照できる**: `pbapi` は workspace のパッケージ(`packages/infra/pbapi`)で、`pms_app` の pubspec に `path` で足すだけで解決できる(`flutter pub get` で衝突なし。`auth_files` も同じ方法で使っている)。
1. **組み入れ出来る**: 組み込んだ。必要な部品はすべて `pbapi` にある。
1. **必要である**: JWT の取得・期限管理・ログイン状態の確認は `pbapi` の `SessionService` が持つ。自前で作らない。ただし、いまの `pms_app` はログイン画面(`auth_files`)を組み込んでおらず、**ログインする手段がまだ無い**ため、実際に JWT を得て使うところまでは動かせない。

## `pbapi` の使えるところ
| 用途 | API |
| --- | --- |
| 接続 | `PbConnection.open(url, logger, tokenStore)` → `pbConnectionProvider` を上書き |
| GraphQL 用 JWT | `SessionService.graphqlToken()` — `GET /api/app/graphql-token`。期限の 60 秒前まで使い回し、切れたら取り直す。未ログインは `PbException`(`unauthorized`)、サーバーが無設定なら `notFound` |
| セッション確認 | `SessionService.ensureSession()`(auth-refresh)、`watch()`(5 分ごと) |
| ログイン | `SessionService.login(ユーザーID, パスワード)` → `AuthSession`(`appUserId` を含む) |
| トークンの保存 | `ITokenStore`(既定はメモリ。本番は安全な保管庫) |

## 組み込んだ内容(`apps/pms_app`)
1. `pubspec.yaml` に `pbapi` を追加。
1. `lib/services/pocketbase/pocketbase_overrides.dart`: `--dart-define=POCKETBASE_URL=...` を指定したときだけ `PbConnection.open` し、`pbConnectionProvider` を上書きする(`main()` に組み込み)。トークンの保存先はメモリ(アプリを閉じるとログアウト)。
1. `lib/services/graphql/graphql_overrides.dart`: `graphqlAuthorizationProvider` — PocketBase を使うとき `SessionService.graphqlToken()` の JWT を `Authorization: Bearer` にする(通信のたびに呼ぶ。キャッシュと更新は `pbapi` が行う)。ログインしていない・取得できないときはヘッダーを付けない。前回の `graphqlTokenProvider`(手動の指定)は、PocketBase を使わないときのために残した。
1. テスト(`pms_app/test/graphql_overrides_test.dart`): 未ログインはヘッダーなし(通信しない)、PocketBase を使わないときは手動のトークンが Bearer になる。`pms_app` 11 件が通る。
1. 実サーバーの確認: PocketBase `http://192.168.1.103:8090` に、`pbapi` の読み取りだけの接続テスト(存在しないユーザーのログイン、未ログインの共有ファイル)が通る。ログインの成功は、サーバーのデータを増やすため試していない。

## 見つかった問題
1. **PostGraphile `http://192.168.1.100:5000/graphql` は JWT を検証していない**。起動オプションに `--jwt-secret` が無く、不正な JWT でも 200 で通る。アプリが JWT を送っても無視され、DB の関数が読む `jwt.claims.staff_id` は設定されない。また、JWT の `role`(`app_user` / `app_admin`)に当たる DB のロールが無い。対応案を `tools/docker/postgresql/issue/20261103_0003.md` に書いた。**PocketBase 側(JWT の発行)と PostGraphile 側(検証)の両方がそろって初めて、JWT が効く。**
1. ログイン画面が無い: `pms_app` の `featureModules` に `AuthFilesModule` が無い。組み込めば `pbConnectionProvider` を使う(今回の上書きで足りる)。画面の遷移とセッション確認(`IPageSessionMediator` の実装)の置き換えは、別の Issue(`pbapi` の CLAUDE.md)。
1. トークンの保存先: 既定のメモリのままでは、再起動のたびにログインが必要。本番は `flutter_secure_storage`(`pms_authenticator` が使っている版 `^10.0.0`)で `ITokenStore` を実装する。

## 次の手順(提案)
1. PostGraphile の JWT の検証と DB ロールの対応(上記 Issue)。
1. `auth_files` を `pms_app` に組み込み、ログインしたら `ensureSession` / `watch` で確認する。
1. `ITokenStore` の安全な保管庫の実装。
1. ログイン後の権限の取得(`AccessControlClient.listEffectiveAccessPaths(staffId: AuthSession.appUserId)`)と、ページ切り替え時の確認。
