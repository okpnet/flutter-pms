# 20261031_0001 バーコード実績登録のモデル

指示: `issue/20261031_0001.md`。

## 実施内容
1.  `tools/gql_yaml2graphql`: `kind: create`(`~PageCreate`)を追加した(`lib/src/create_generator.dart`)。`createXxx(input: {xxx: {...}})` と、主キーと指定した列を返す。列が入力型に無い・入れ子はエラー。テスト 2 件を追加。
2.  本家スキーマを取り込み直し(`.schema/schema.graphql`。`trans_complaint_work`・`trans_complaint_purchase_rec` を含む)、全パッケージの `schema.graphql` を再抽出した。
3.  登録を追加: `work_record_model`(`WorkRecordPageCreate`・`WorkRecordVisiterPageCreate`・`VisiterPageCreate`・`ConveyPageCreate`・`ComplaintWorkPageCreate`)、`purchasing_model`(`PurchaseRecPageCreate`・`PurchaseRecVisiterPageCreate`・`ComplaintPurchaseRecPageCreate`)。モデルを生成した。
4.  `barcode_entry_model` を新設した。読み込み 8 件(`gql/scan.yaml`)と窓口 `lib/scan_client.dart`(`ScanClient`)。生成モデルは窓口の中に隠し、平らな型(`ScanFound`)で返す。登録は上の 3 のモデルを使う。
5.  `ScanClient` の登録の組み合わせ: 作業の開始(作業実績)、作業の入庫(作業実績 + ビジター + 入庫 + 結び付け)、購入品の入庫(受入 + ビジター + 入庫 + 結び付け)、棚移動(ビジター + 入庫)。順に呼び、途中で失敗すると例外にして以降は呼ばない(そこまでの登録は残る)。
6.  テスト: `barcode_entry_model/test/scan_client_test.dart`(検証用サーバーでの symbol の照会、代役の通信路での登録の順序と値)。

## 検証の結果
- 検証用サーバーでの照会で、発注明細・設備の読み込みに使わない `languageCodeId` が宣言されていてサーバーに拒否された。名称を持たない読み込みから `requiredWhere: languageCode` を外して直した。
- 検証用サーバーに作業指示の symbol のテストデータが無く、作業指示の照会は「登録の無い symbol は null」(クエリの検証)までの確認。

## 残る課題(`packages/features/barcode_entry/issue/20261031_0003.md`)
- 棚出庫(払出)・単位・設備点検・異常の登録は、DB の構成から決められず未対応。
- `tools/gql_yaml2graphql` の `page_views_consistency_test` の「viewsのトップノードは、すべてpage.mdから参照されている」は、今回より前から失敗している(`MrpXxx` などが page.md に無い)。
