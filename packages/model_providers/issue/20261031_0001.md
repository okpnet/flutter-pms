# バーコード実績登録のモデル(登録 `kind: create`・barcode_entry_model・異常テーブル)

`packages/features/barcode_entry/issue/20261031_0002.md` の「モデルへの Issue」を統合したもの。実施内容は `doc/log/20261031_0001.md`。

1.  **登録(`kind: create`)を YAML から生成する**(`tools/gql_yaml2graphql`)。ノード名は `~PageCreate`、出力は `<dir>/<dir>_create.graphql`(操作名 `~PageCreate`)。列は列名だけ(入れ子は対象外)。更新(`~PageEdit`)と同じ列の並びで書く。
2.  **各モデルパッケージの登録を追加する**。
    1.  `work_record_model`: 作業実績 `trans_work_record`、作業実績ビジター `trans_work_record_visiter`、棚ビジター `trans_visiter`、入庫/払出 `trans_convey`、作業異常 `trans_complaint_work`。
    2.  `purchasing_model`: 購入品受入 `trans_purchase_rec`、受入ビジター `trans_purchase_rec_visiter`、受入異常 `trans_complaint_purchase_rec`。
    3.  `resource_model`(設備点検 `trans_inspect_record`): 点検予定の明細(`trans_inspect_sch_detail`)との結び付けが未定のため、今回は追加しない。
3.  **`barcode_entry_model` を新設する**。symbol で対象を引く読み込み(`Scan~Page`。作業指示・作業実績・棚・棚のビジター・発注明細・受入実績・品目・設備)を持つ。子のレコード数を読まない軽い読み込みのため `lightRead: true` を付ける(要件0056の検査の対象外)。登録は 2 の各モデルを使い、保守のため重複して持たない。
4.  **異常テーブル**(DB に追加済み): `trans_complaint_purchase_rec`(受入異常)、`trans_complaint_work`(作業異常)。本家スキーマを取り込み直し(`melos run gql:schema`)、2 の YAML・生成を行う。異常の本体 `trans_complaint` の登録は、表題・詳細(`titles`・`details` の文書)が必要なため、このIssueでは扱わない。
5.  **複数テーブルにまたがる登録は、クライアントで順に呼ぶ**(DB の関数にしない)。作業実績だけ・ビジターだけ・すべてを組み合わせる場合に対応できるよう、1テーブルずつの部品と組み合わせを `barcode_entry_model` の `ScanClient` に持たせる。
6.  登録の通信テストは書かない(検証用サーバーは読み取り専用)。symbol の照会と、登録の呼び出しの順序・値(代役の通信路)をテストする。
