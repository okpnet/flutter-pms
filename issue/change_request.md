### 0-3. 設計の共通ルール（守ること）

1. **状態・区分をコード値（smallint や文字列の定数）で持たない、判定しない。** はい／いいえで決まるものは boolean 列、利用者が増やせる分類はサロゲートキーのマスタにする。マスタにも boolean を持たせ、アプリやビューは **boolean で判定する**（マスタの `code` で分岐しない）。
2. 「キャンセル」「停止」などの**表示用の文字は、ビューで1か所だけ定義する**。アプリごとに解釈を持たない。
3. 記録（計画変更・支給・返品・精算）は**追記のみ**。取り扱いが変わったら1件追加する。元の行は書き換えない。
4. trans からマスタを参照するときは、**履歴ID＋IDの組**で `history_mstr_*` を参照する（既存と同じ）。
5. 棚ビジターの数量は、棚ビジターの行（＋・−）と受払実績が持つ。中間テーブル（返品ビジター・支給ビジター）は数量を持たない。
6. ビューには `symbol` 列を含める。

## 1. 決定事項

| # | 決定 |
|---|---|
| 1 | 受注・発注のキャンセルは**数量の累計**（`cancel_quantity`）で持つ。一部も全部も同じ列。「全部キャンセル済み」は列に持たず、ビューの `cancel_closed` で判定する |
| 2 | 停止は boolean（`stop`）。延期は納期の変更として計画変更記録に残す |
| 3 | 変更・処置の履歴は**計画変更記録**（`trans_plan_change`）に残す。種別の列は持たず、どの列に値が入っているかで何をしたかが分かる |
| 4 | 再MRP は MRP 実行（`trans_mrp_run`）として残っている。計画変更は、反映した MRP 実行（`reflected_trans_mrp_run_id`）でつなぐ |
| 5 | 完了まで続ける生産は**受注明細のまま**進める（非計上明細へ付け替えない）。顧客と合意した途中の請求は**受注明細精算**で持つ。値引きとは分ける |
| 6 | 精算1件 = 請求書1行 |
| 7 | 押さえる品・外注先へ渡す材料は、**ユーザーが選んだコンテナへ引当して移す**。外注先専用のコンテナは作らない |
| 8 | 顧客支給は0円発注ではなく**支給**（`trans_supply`）で受ける。**顧客支給の品目は発注を提案しない**。足りなければ MRP は要判断の `SUPPLY_REQUEST`（支給依頼）を出す |
| 9 | 支給品も検品する。異常は支給異常（`trans_complaint_supply`）に登録する |
| 10 | 顧客支給で作った物は顧客の所有。キャンセル時に顧客が「返却不要」と言えば、自社の所有に変えて在庫として使える |
| 11 | 発注先への無償支給は自社の所有のまま。有償支給は販売。発注先の責任による再生産で、無償から有償に切り替わることがある |
| 12 | 製品が顧客の所有かどうかは受注明細に明示する（`customer_property`）。購入品＋顧客の製品で作る販売品目（Assy）があるため |
| 13 | 有効な所有者は別テーブル（`trans_visiter_owner`）に切り出し、トリガーで保つ。読むときに最新の支給をたどらない |
| 14 | 支給予定は受注のときに登録する（最初の契約）。支給の取り決めが変わったら、その受注明細を指定して再MRP する |
| 15 | 譲渡で自社の物になった材料の評価額は0円。購入品＋支給品で作った品目は、購入品＋生産コスト（支給品は0円）。顧客の所有物は評価しない |
| 16 | 有償支給の請求は支給明細1件 = 請求書1行。有償か無償か（`paid_supply`）、切り替えか（`paid_by_switch`）が分かればよい |
| 17 | `info_provision` 系のマスタは「会社が顧客へ何を提供するか」（ISO 9001 4項）で、支給とは関係ない |
| 18 | 受注1件に明細を複数登録できる（`trans_order_detail_IX1` の一意は廃止済み） |
| 19 | **一般ユーザー（`APP_USER_ID`）にも INSERT を付ける**（05・09）。ただし `trans_visiter_owner` は一般ユーザー・管理者とも読み取りだけ（13 で REVOKE） |
| 20 | **組立品の部品ごとに、支給・自社製造・購入が混ざってよい**（例: A = 顧客支給、B = 自社製造、C = 購入）。顧客支給として扱うのは、その受注に支給明細がある品目だけ。同じ品目の数量の一部だけを自社で手配する運用は無い |

### 2-4. 支給の場面ごとの値

| 場面 | receive | counterpart_owns | company_owns | つなぐロット |
|---|---|---|---|---|
| 顧客から支給を受ける | true | true | false | 受け入れた＋の行（仮止め → 検品後に解除） |
| 顧客へ返す | false | false | false | `visiter_issue` の−の行 |
| 返却不要（譲渡） | false | false | true | 今あるロット |
| 発注先へ無償で渡す | false | false | false | 選んだコンテナへ移した＋の行 |
| 発注先から戻る | true | false | false | 自社の棚へ戻した＋の行 |
| 発注先へ有償で渡す | false | true | false | 移した＋の行（単価は明細） |
| 無償 → 有償の切り替え | false | true | false | 発注先にあるロット（起因の異常を入れる） |

### 2-5. 有効な所有者の決め方（13 のトリガー）

上から順に、最初に当てはまったもの。

1. そのロットに直接つながる支給のうち、所有を変える支給の最新（`supply_at` の新しい順）
2. 分割元のロットの所有者（移動・分割は元を引き継ぐ）
3. 作業実績で作られたロット: いちばん上の受注明細が `customer_property = true` なら、その受注の顧客
4. どれも無ければ自社（行を消す）

受注明細の `customer_property` や受注の顧客を後から変えたときは、`visiter_owner_rebuild()`（管理者だけが実行できる）で全件を決め直す。

## 3. 運用仕様

### 3-1. キャンセル・停止

| 対象 | 操作 | DB の更新 | 計画変更 |
|---|---|---|---|
| 受注明細・発注明細 | 一部・全部キャンセル | `cancel_quantity` を増やす | `cancel_quantity` |
| 〃 | 停止 / 再開 | `stop` | `old_stop` → `new_stop` |
| 〃 | 納期の変更（延期・前倒し） | 納期 | `old_date` → `new_date` |
| 〃 | 数量の変更 | 数量 | `old_quantity` → `new_quantity` |
| 生産計画 | 停止 / 再開 | `stop` | `new_stop` |
| 〃 | 打ち切り | `discontinue = true` | `discontinue` |
| 〃 | 完了まで続ける | 変更なし（受注明細に残す。差額は精算） | なし（または備考） |
| 引当予約 | 解除 | 予約・引当を取り消す | `release` |
| 〃 | 保管 | 引当してユーザーが選んだコンテナへ仮止めで移す | `hold` ＋ `trans_container_id` |

起点の変更（例: 受注キャンセル）と、その下の処置は `parent_trans_plan_change_id` でつなぐ。

### 3-2. キャンセル後の品物（棚ビジターが対象の計画変更）

| 処置 | 計画変更 | やること | MRP |
|---|---|---|---|
| 在庫にする | `release` | 引当予約を解除 | 空き在庫として使う |
| 押さえる（交渉中） | `hold` ＋ コンテナ | `visiter_move(p_hold: true)` で移す | 仮止めなので使わない |
| 顧客へ引き渡す | `deliver` ＋ 精算 | 精算を登録し `visiter_issue` で払い出す | 在庫から消える |
| 廃棄 | `scrap` | `visiter_issue` で払い出す | 在庫から消える |
| 材料に戻す（仕掛品） | `release` | 払い出して材料品目で入庫し直す | 材料の在庫になる |

押さえたままの品は、未処置一覧に出し続ける。

### 3-3. 返品（売買の取り消しだけ）

- 顧客からの返品: 返品区分 `receive = true`。明細に受注明細・出荷明細実績。入庫の＋の行を返品ビジターでつなぐ。
- 仕入先・外注先への返品: `receive = false`。明細に発注明細・受入実績。`visiter_issue` の−の行をつなぐ。
- 代品あり（`replacement = true`）は、受注残・発注残に戻す。
- 支給材の返却・戻りは返品ではなく支給で扱う。

### 3-4. 顧客支給

1. 受注のときに支給予定を登録する（支給 `receive = true, counterpart_owns = true` ＋ 支給明細。充てる資材計画を指定する）。
2. 受け入れ: 仮止めで＋の行を作り、支給ビジターでつなぐ（所有者 = 顧客）。
3. 検品: 異常は支給異常へ。合格したら仮止めを外す。
4. 使う: 充てた資材計画に払い出す（今の引当・払出のまま）。
5. キャンセル: 未使用分は返す。返却不要なら、残っているロットに `company_owns` の支給を付ける。
6. 組立品では、部品ごとに手配が決まる。支給明細がある品目（A）だけが顧客支給で、ほかの品目（B: 自社製造、C: 購入）は通常どおり生産・発注を提案する。同じ品目でも、支給明細の無い別の受注では通常どおり手配する。
7. 支給明細のある品目が足りないときは `SUPPLY_REQUEST`（支給依頼）。その品目を自社で手配に切り替えるなら、支給明細を取り消して（`remove`）再MRP する（同じ品目の一部だけを自社で手配する運用は無い）。
8. 支給明細に資材計画を指定しないとき（受注の時点では資材計画がまだ無い）は、その受注の木の中の同じ品目の需要すべてに充てる。

### 3-5. 発注先への支給

1. 渡す: 外注工程の材料の資材計画に引当し、ユーザーが選んだコンテナへ移す。移した＋の行を支給でつなぐ（所有は変えない）。
2. 発注先にある量: `v_supply_detail_balance.current_quantity`。
3. 戻る: 自社の棚へ移し、支給（`receive = true`）でつなぐ。キャンセルなら引当予約も解除（`release`）。
4. 有償で渡す: `counterpart_owns = true`、明細に単価。
5. 無償 → 有償: 発注先にあるロットに支給を1件追加（`counterpart_owns = true`、単価、起因の異常）。

### 3-6. 評価額

| ロット | 評価額 |
|---|---|
| 顧客の所有物 | 評価しない |
| 譲渡で自社の物になった材料 | 0円 |
| 購入品＋支給品で作った品目 | 購入品の額 ＋ 生産コスト（支給品は0円） |
| 発注先へ無償で渡している材料 | 元の評価額（自社の資産） |
| 有償で渡した材料 | 発注先の物（`paid_amount` を請求） |

## 4. MRP（08_mrp.sql）の仕様（実装済み）

| 箇所 | 仕様 |
|---|---|
| 受注の需要 | `v_order_detail_balance` を使う。全部キャンセルは需要なし。`stop = true` は凍結（下の生産計画・従属需要も凍結） |
| 発注残 | `v_purchase_detail_balance` の残。`stop = true` は紐づく需要にだけ使う |
| 生産残 | `stop = true` は凍結（負荷にも積まない）。`discontinue = true` は生産残 0 |
| 顧客支給 | 顧客の物の在庫と支給予定（供給区分 6）を、その受注明細・資材計画の需要にだけ使う。不足は `SUPPLY_REQUEST`（要判断）。発注・生産は提案しない。判定は「品目 × 受注明細（または資材計画）」なので、組立品のほかの部品・支給明細の無い受注には影響しない |
| 確定: 発注の取消 | 数量を書き換えず、残りを `cancel_quantity` にする。計画変更を記録（MRP 提案付き） |
| 確定: 生産の取消 | 着手済みは打ち切り、未着手は削除。計画変更を記録 |
| 確定: 反映 | 未反映の計画変更に `reflected_trans_mrp_run_id` を入れる |
| ペギング | `trans_mrp_pegging.trans_supply_detail_id` を追加 |
| 補助関数 | `mrp_root_order_detail`、`mrp_op_frozen`、`mrp_cancel_purchase_detail` |
| MRP 未反映の判定 | 支給明細の `update_at` が最後に確定した MRP 実行より新しい受注明細 |
