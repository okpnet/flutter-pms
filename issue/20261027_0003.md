## 1. 背景
- ダッシュボード用ビュー(従業員数・売り上げ実績・発注金額合計・出荷予定受注実績状況・出荷納期遵守状況・発注納期遵守状況・点検整備実施状況・棚在庫状況・生産計画納期遵守状況)の集計は、サーバー側で行う。
- 問い合わせの組み立てと、フィルタ(`Expression` / `PredicateModel`)の GraphQL 用への変換には `packages/foundation/query_builder` を使う。
- このライブラリは初期の TrinaGrid で使う想定で作られたが、現在まで使われていない。ワークスペースの現状(`data_strategist`・`pms_graphql`・各 `xxx_model`)との整合が未確認。

## 2. 影響範囲(想定)
- `query_builder`: 現状(`lib/src` に constants・predicates・sorts・debugs)で GraphQL への変換が足りているか。README は未記入(TODO のまま)。
- `data_strategist`: 取得元が `PredicateModel` をどう扱っているか(`dashboard_container` は `PredicateModel(take: 0, skip: 0, predicate: ...)` を渡している)。
- `pms_graphql` / 各 `xxx_model`: フィルタ(`condition`・`filter`)と集計(`totalCount`・集計関数)の GraphQL への変換。スカラーの扱い。
- `dashboard_container` と、集計値の元を提供する機能(`organization`・`sales`・`purchasing`・`resource`・`work_record`・`production_plan`)。
