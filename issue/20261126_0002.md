# 20261126_0002 海外取引(通貨・為替)のテーブル設計

`202611.md` の「元: 20261125_0004.md」(将来の Issue)を、着手する。**この文書はテーブル設計の提案(PERO に入れる前)**。確認・決定のあと、PERO → `06_cteate_test.sql` → `07_dummy.sql` → SQL テスト → モデル → 画面の順に進める。

## 決定済み(2026-11-26。利用者)
1.  外貨になる取引: 受注・発注の**両方**。
1.  請求・支払の通貨: **設定から決める**(通貨は限られた数で、設定で足りる)。
1.  為替の差損益: **扱う**。
1.  為替レートは、**手動**と**自動**から選べる。自動は、画面の「自動取得」ボタンで Web から取得する。
1.  **利害関係者が取引の通貨を持つ**。新規登録では標準の通貨を入れる。DB の既定値では入れず(アプリが入れる)、**NULL は許さない**。マスタと**履歴の両方**に列を足す。

## 2. 新規の表

### 2-1. `mstr_currency`(通貨マスタ。履歴は持たない。`shared_unit` と同じ形)
| 列 | 型 | 内容 |
|---|---|---|
| `mstr_currency_id` | uuid PK | 通貨 ID |
| `code` | varchar(3) NOT NULL | ISO 4217 のコード(`JPY`・`USD`)。有効な行(`remove = false`)で一意(部分一意索引 `mstr_currency_ix_code_active`) |
| `names` | uuid NOT NULL | 名称(呼称。共通関数 `shared_appellation_save` で作る) |
| `currency_symbol` | varchar(8) NOT NULL | 表示の記号(`円`・`$`)。言語ごとの違い(JPY を日本語は「円」・英語は「¥」)は、設定 `info_app.settings` の `currency` の上書きで持つ(現行どおり) |
| `minor_unit` | smallint NOT NULL | 小数の桁数(JPY=0・USD=2)。CHECK `0 ≤ minor_unit ≤ 4`。丸めと表示に使う |
| `rate_auto` | boolean NOT NULL DEFAULT false | **自動取得の対象か**(true = 「自動取得」ボタンで Web から取得する。false = 手入力)。boolean で判定する(コード値にしない) |
| 共通列 | | `revision`・`symbol`・`remarks`・`update_at`・`update_user_id`・`update_user_history_id`・`remove` |
- 基準通貨は、この表に boolean を持たない(**1 か所に集める**ため、`info_app` の列にする。下の 3)。基準通貨のレートは常に 1(表に行を持たない)。
- 通貨の数は限られるため、標準の通貨(`JPY`・`USD`・`EUR`・`CNY` ほか)を `07_dummy.sql` に入れる。追加はマスタ画面。

### 2-2. `trans_exchange_rate`(為替レート。追記のみ)
| 列 | 型 | 内容 |
|---|---|---|
| `trans_exchange_rate_id` | uuid PK | |
| `mstr_currency_id` | uuid NOT NULL FK | 通貨(基準通貨以外) |
| `applied_at` | date NOT NULL | 適用日(この日以降に使う。取引日 ≥ 適用日の最新の行を使う) |
| `rate` | numeric(18,8) NOT NULL | **1 単位の通貨 = 基準通貨いくら**(例 USD → JPY = 150.12)。CHECK `rate > 0` |
| `auto_fetched` | boolean NOT NULL DEFAULT false | 自動取得か(false = 手入力)。表示用の文字は持たない |
| `source` | varchar(255) | 自動取得の取得元(サービス名・URL。手入力は NULL) |
| 共通列 | | `symbol`・`remarks`・`update_at`・`update_user_id`・`update_user_history_id`・`remove`(取り消し)ほか |
- **追記のみ**(CLAUDE.md の R3)。直すときは新しい適用日の行を足す。取り消しは `remove = true`。同じ通貨・適用日の有効な行は 1 つ(部分一意索引 `trans_exchange_rate_ix_active`。手入力と自動が同じ日にあれば、あとから登録したほうが有効になるよう、前の行を `remove` する運用)。
- 登録は**ミューテーション**(`create`。1 行ずつで、同時実行・金額の影響が限定的なため。CLAUDE.md の「登録・更新の方式」)。自動取得は、取得した通貨ごとに 1 行ずつ登録する。

### 2-3. DB 関数(参照用。読み取り)
- `exchange_rate_at(p_currency_id uuid, p_at timestamp)` → numeric: 基準通貨なら 1、そうでなければ適用日 ≤ `p_at` の最新の有効な行。無ければ errcode `EXC01`(レートが無い)。STABLE(query になる)。
- `currency_round(p_currency_id uuid, p_amount numeric)` → numeric: `minor_unit` で丸める(丸めは **四捨五入** を既定の案)。
- 登録時にレートを自動で入れるトリガー: 見出し・計上の記録の `exchange_rate` が NULL なら `exchange_rate_at` で入れる(手で入れた値はそのまま使える)。

## 3. 既存の表への列の追加

### 3-1. 基準通貨(標準の通貨): `info_app`・`history_info_app`
- `mstr_currency_id uuid NOT NULL`(FK → `mstr_currency`)。コメント「標準の通貨(基準通貨)」。利害関係者の新規登録の既定値と、基準通貨の金額の換算先(帳簿の通貨)を決める。
- **基準通貨の変更は、取引が 1 件でもあれば禁止**(トリガー errcode `CUR01`。取引のレートが基準通貨に対する値のため、あとから変えると過去の金額の意味が変わる)。変更したいときは、決算・移行の手順を別に設計する。
- 履歴のトリガー(`trg_02_history_info_app`)の 3 か所(比較・INSERT の列・VALUES)を直す(CLAUDE.md「履歴の表を持つ表に列を足すとき」)。`info_app` の書き込みは管理者だけ(既存のトリガー `trg_00_admin_only_column` の対象に列を足す)。

### 3-2. 利害関係者: `mstr_stakeholder`・`history_mstr_stakeholder`
- `mstr_currency_id uuid NOT NULL`(FK → `mstr_currency`)。コメント「取引の通貨」。
- **DB の既定値は付けない**(NULL も許さない)。新規登録は、アプリが `info_app.mstr_currency_id`(標準の通貨)を入れる(`organization` の利害関係者の登録画面。選択で変更できる)。`07_dummy.sql` の利害関係者・テスト用の登録(Dart のテスト・`tools/init`)にも通貨を入れる。
- 履歴のトリガー(`trg_02_history_mstr_stakeholder`)の 3 か所を直す。変更は履歴に残り、**過去の取引は履歴 ID + ID で参照するため、そのときの通貨が残る**。
- 顧客・仕入先・外注先・配送サービサーすべてに同じ列(区分で分けない)。

### 3-3. 取引の見出し(取引の通貨と取引時のレートを固定して残す)
対象と、金額を持つ明細の対応:
| 見出し(列を足す) | 明細(見出しの通貨を使う。列は足さない) |
|---|---|
| `trans_order`(受注) | `trans_order_detail`(`unit_price`・`price_adjustment`・`fixed_price`)・`trans_order_detail_settlement`(`amount`) |
| `trans_purchase`(発注) | `trans_purchase_detail`(同上) |
| `trans_unrecognized`(非計上) | `trans_unrecognized_detail` |
| `trans_supply`(支給。有償の `unit_price`) | `trans_supply_detail` |
追加する列(上の 4 表):
- `mstr_currency_id uuid NOT NULL`: 取引の通貨。登録時にアプリが相手先の通貨(`mstr_stakeholder.mstr_currency_id`)を入れ、変えられる(相手先の通貨と違う取引も可)。
- `exchange_rate numeric(18,8) NOT NULL`: **取引時のレート**(基準通貨に対する。基準通貨なら 1)。NULL のとき、トリガーが `exchange_rate_at` で入れる。登録後は変えない(再計算しない)。
- 精算(`trans_order_detail_settlement`)は、受注の通貨で入れ、レートは受注のものを使う(列は足さない)。
- 履歴の表を持つ表ではないため、履歴の変更は無い(trans)。

### 3-4. 計上の記録(差損益用。計上時のレート)
- `trans_shipping_order_detail_record`(出荷実績。売上の計上)・`trans_purchase_rec`(受入実績。仕入の計上)に `exchange_rate numeric(18,8) NOT NULL`(計上時のレート。NULL のときトリガーが `exchange_rate_at(通貨, 計上日)` で入れる)。通貨は見出しのものを使う(列は足さない)。
- **差損益 = 外貨の金額 ×(計上時のレート − 取引時のレート)**(売上は + が差益、仕入は + が差損)。計上の時点の差だけを扱う。
- **入金・支払の時点の差損益は、この設計では扱わない**: DB に入金・支払の表(請求・入金・支払)が無いため。必要になったら、入金・支払の表と、その時点のレートを足す(下の「決めてほしい点」2)。

### 3-5. 原価・標準価格(通貨の列を持たない表)
- `mstr_item_supplier.cost`・`history_mstr_item_supplier`(仕入先ごとの標準単価): **仕入先の通貨**(`mstr_stakeholder.mstr_currency_id`)。列は足さない。原価計算では、最新のレート(`exchange_rate_at(通貨, now())`)で基準通貨に換算する(標準原価は「いまの値」)。
- `mstr_item_task_cost.cost`(工程の原価)・`trans_work_record`の費用: 自社の費用で、基準通貨。
- `trans_mrp_suggestion.cost`・`trans_mrp_suggestion_task.cost`: 提案の元の仕入先の通貨。基準通貨に換算した列を、ビューで持つ(画面に合計を出すなら)。
- 実績の原価(`v_work_record_cost`)の材料の評価額は、材料のロットが購入品のとき、**受入実績の計上時のレート**で換算した値(`trans_purchase_rec.exchange_rate`)を使う案。標準原価のまま(決定済み)なら、最新のレート。→ 決めてほしい点 3。

## 5. 為替レートの自動取得(アプリの機能)
- 通貨の台帳(または「為替レート」の画面)に **「自動取得」ボタン**。`rate_auto = true` の通貨について、Web のサービスから最新のレートを取得し、`trans_exchange_rate` に `auto_fetched = true`・`source` つきで登録する。失敗した通貨は登録せず、失敗の一覧を出す(手入力で補える)。
- 取得は**クライアント(アプリ)から**行う(サーバーにジョブを置かない。PDF の出力と同じ方針)。送るのは通貨コードだけで、利用者・会社の情報は送らない。取得元の URL・サービスは設定(`info_app.settings` の `exchange`: `{ "provider": "…", "url": "…" }`)に持つ。接続は `https` だけ。
- 取得元の候補: 無料で認証が要らず、公的なレートを出すもの(例: 欧州中央銀行(ECB)のレートを返すサービス)。対応していない通貨は `rate_auto = false` にして手入力にする。サービスの条件(利用の制限・対応する通貨)は、実装の前に確認する。
- 手動: 通貨・適用日・レートを入力して登録する。
- 画面の権限: 為替レートの登録・自動取得はアクセスパスで制御する(`/exchange-rate`。一般ユーザーも可か、管理者だけか → 決めてほしい点 4)。

## 決めてほしい点(既定の案つき)
1.  **取引の通貨を見出しに持つか、利害関係者の履歴から引くか**: 案(既定): 見出しに持つ(相手先の通貨と違う取引を許し、ビューが単純になる)。履歴から引く案は、列が増えない代わりに、取引ごとに通貨を変えられない。
1.  **入金・支払の時点の差損益**: 案(既定): 今回は計上時(出荷・受入)の差だけ。入金・支払の表が無いため。入金・支払の管理を作る時期に追加する。
1.  **実績の原価の材料の評価額のレート**: 案(既定): 標準原価のまま(最新のレート。決定済みの「材料の評価額は標準原価」に合わせる)。受入時のレートを使う案は、実際の仕入の原価に近いが、棚ビジターの履歴の追跡が増える。
1.  **為替レートの登録・自動取得の権限**: 案(既定): 管理者だけ(金額に直結するため)。
1.  **丸め**: 案(既定): 四捨五入。基準通貨の小数桁で、見出しの合計に 1 回。
1.  **自動取得の取得元**: 候補を調べて提案する(上の 5)。
1.  **標準の通貨(基準通貨)を `info_app` の列にしてよいか**(`mstr_currency` に base を持たない。上の 2-1・3-1)。

## 8. 追加の指摘: 締め日・決済日がない(2026-11-26)と、変更の量の調査

### 8-1. 指摘
1.  レートが変わっても、**いつの時点のレートを適用するか**が決まっていない。
1.  レートを決める日は、相手先(利害関係者)の決める日のほかに、**自社の決める日**もある。

### 8-2. 調査の結果(現状)
1.  **締め日・支払日・入金日・支払の条件は、DB に無い**(利害関係者・会社・受注・発注のどれにも、列も表も無い。請求・入金・支払の表も無い)。`06` の「決済」は、**受注明細の精算**(`mstr_settlement_kind`・`trans_order_detail_settlement.settle_at`。キャンセル・値引きの請求書 1 行)のことで、支払・入金の決済とは別。新しい列の名前に「決済」を使うと混同するため、「支払日(自社が払う)」「入金日(相手が払う)」「締め日」を使う。
1.  利害関係者の列は、コード・名称・メール・住所・配送区分だけ(`mstr_stakeholder`)。会社(`info_company`)・設定(`info_app`)にも、年度・締め・支払の列は無い。
1.  `20261126_0002` の 3-3・3-4(取引時と計上時のレートを**登録時の値として固定**する案)は、**この指摘で成り立たない**: 登録時にレートの決まる日が来ていない取引(例: 月末締め・翌月末払いで、支払日のレートを使う取引)がある。

### 8-3. 見直しの案(レートを「決める日」で引く)
**決める日は、取引の条件(締め日・支払の月数・日)と、為替の決める基準から計算する。** レートは、決める日のレートをビューで引く。取引に値を固定して持たない。
1.  **利害関係者(`mstr_stakeholder`・`history_mstr_stakeholder`)に取引の条件**: `closing_day`(締め日。1〜31。月の日数を超えたら月末)・`payment_month_offset`(締めの何か月後。0〜12)・`payment_day`(支払日または入金日。1〜31)。顧客なら入金日、仕入先なら支払日。標準値は会社の設定。
1.  **為替レートを決める基準**(マスタ `mstr_rate_basis`。R1 のとおりコード値で分岐せず、**boolean を持つ**): `at_order`(取引日)・`at_recognition`(計上日 = 出荷・受入の日)・`at_closing`(締め日)・`at_payment`(支払日・入金日)。標準は、会社の設定。
1.  **誰の日で決めるか**: `rate_own_calendar`(boolean。true = **自社の締め日・支払日**で決める。false = **相手先の条件**で決める)。利害関係者ごと(取引ごとに変える場合は見出しの列)。
1.  **自社の条件**(`info_app`・履歴に列): `closing_day`・`payment_month_offset`・`payment_day`・標準の `mstr_rate_basis_id`・標準の `rate_own_calendar`。標準の通貨と同じ場所(管理者だけが変更)。
1.  **取引の見出し**(受注・発注・非計上・支給): 通貨のほか、**`rate_fix_date`(レートを決める日)** を、登録時に計算して固定する(計算した結果の日。あとから条件が変わっても、その取引の決める日は変わらない)。`exchange_rate` の固定値の列は持たない。
1.  **計上の記録**(出荷実績・受入実績): 固定の列を足さない。**計上日のレート**はビューで引く。
1.  **レートの引き方**(関数 `exchange_rate_at(通貨, 日)`): 適用日 ≤ その日の最新の有効な行。**決める日が未来、またはレートがまだ無いとき**は、最新のレートで仮にして、ビューの列 `rate_provisional`(boolean)を true にする(画面は「仮のレート」と表示。確定は、決める日のレートが登録されたとき)。
1.  **差損益** = 外貨の金額 ×(**決める日のレート** − **計上日のレート**)。ビュー `v_exchange_gain_loss`。入金・支払の実績の表が無くても、**決める日 = 約束の日**として計算できる(実際の入金・支払の日のずれは扱わない)。
1.  為替レートの表(`trans_exchange_rate`)は、前の案のまま(追記のみ)。通貨マスタも同じ。

### 8-6. 決めてほしい点(既定の案つき)
