# 20261126_0002 海外取引(通貨・為替)のテーブル設計

`202611.md` の「元: 20261125_0004.md」(将来の Issue)に着手する。生産管理に必要なのは、**通貨の違う金額を、集計で基準通貨に換算すること**だけ。決済・請求・差損益などの会計処理は、生産管理の対象外(会計側)。

## 決定(2026-11-26。利用者)
1.  **外貨になる取引**: 受注・発注の両方。金額は**相手先の通貨のまま保存**し、基準通貨への換算は**集計のビュー**で行う(画面・Dart で換算しない)。
1.  **基準通貨(内部の通貨)**: 設定(`info_app`)で決める。
1.  **利害関係者**: 取引の通貨と**検収日**だけを持つ(締め日・支払日・支払条件・差損益は持たない)。新規登録は、標準の通貨(基準通貨)を入れる。DB の既定値では入れず(アプリが入れる)、NULL は許さない。**マスタと履歴の両方**に列を足す。
1.  **為替レート**: **月ごと**の概算レート。手動と自動(「自動取得」ボタンで Web から取得)の両方。レートは追記のみ。
1.  **レートが影響する範囲**:
    1.  **出荷実績・受入実績の金額**: 相手先の**検収日のある月**のレートで換算する。検収日までに出荷・受入したものは当月、検収日より後は翌月。検収日が月の日数より大きいときは月末として扱う。検収日が NULL は月末(常に当月)。
    1.  **受注・発注の金額・外注の工程単価(`mstr_item_supplier.cost`)・標準原価**: 目安。**最新の月のレート**で換算する(固定しない)。
    1.  **自社の工程の時間単価**: 自社の費用で、基準通貨のまま。換算しない。
1.  **取引の表には列を足さない**: 通貨は、受注・発注が参照する相手先の履歴(履歴 ID + ID)から引く(取引時の通貨が残る)。
1.  **月のレートが無いとき**: その月以前で最新のレートを使う。その月が登録されていなければ「仮」(`provisional = true`)。
1.  **基準通貨の変更は、為替レートが 1 件でもあれば禁止**(レートは基準通貨に対する値のため)。errcode `CUR01`。

## 設計

### 新しい表
| 表 | 内容 |
|---|---|
| `mstr_currency`・`history_mstr_currency`(マスタ+履歴。`shared_unit` と同じ形) | 通貨。`code`(ISO 4217。有効な行で一意)・`names`(呼称 = `shared_appellations`)・`currency_symbol`(記号。言語ごとの違いは `info_app.settings` の `currency`)・`minor_unit`(小数の桁数 0〜4)・`rate_auto`(boolean。true = 「自動取得」の対象) |
| `trans_exchange_rate`(trans。追記のみ) | 為替レート。`mstr_currency_id`・`rate_month`(月の初日)・`rate`(1 単位 = 基準通貨いくら。`numeric(18,8)`、> 0)・`auto_fetched`(boolean)・`source`(自動取得の取得元)。直すときは新しい行を足す(同じ通貨・月は、あとから登録した有効な行を使う)。取り消しは `remove` |

### 列の追加
| 表 | 列 |
|---|---|
| `mstr_stakeholder`・`history_mstr_stakeholder` | `mstr_currency_id uuid NOT NULL`(取引の通貨)・`acceptance_day smallint`(検収日。1〜31。NULL = 月末) |
| `info_app`・`history_info_app` | `mstr_currency_id uuid NOT NULL`(基準通貨) |
- 履歴のトリガー(`trg_02_history_mstr_stakeholder`・`trg_02_history_info_app`)の 3 か所(比較・INSERT の列・VALUES)を直す。

### 関数・トリガー・ビュー
| 名前 | 内容 |
|---|---|
| `currency_rate_at(通貨, 日付)` | その月以前で最新のレート。基準通貨は 1。無ければ NULL。`@omit`(補助) |
| `currency_rate_provisional(通貨, 日付)` | その月のレートが無い(別の月で代用)なら true。基準通貨は false。`@omit` |
| `acceptance_month(検収日, 日付)` | 検収日を考慮した換算の月(月の初日)。`@omit` |
| `currency_to_base(金額, 通貨, 月)` | 基準通貨の金額(基準通貨の `minor_unit` で四捨五入)。レートが無ければ NULL。`@omit` |
| `trg_currency_base_guard`(`info_app`) | 基準通貨の変更をレートが 1 件でもあれば止める(`CUR01`) |
| `v_currency_rate_latest`(ビュー) | 通貨ごとの最新のレート(月・レート・自動か) |
| 金額のビュー(別の段階) | 出荷・受入の金額、受注・発注の目安、標準原価、外注の工程単価、実績の原価に、通貨・基準通貨の金額・`provisional` を足す(約 6〜8 本) |

### 為替レートの自動取得
- 通貨の画面の「自動取得」ボタンで、`rate_auto = true` の通貨のレートを Web から取得し、`trans_exchange_rate` に `auto_fetched = true`・`source` つきで 1 行ずつ登録する(ミューテーション)。失敗した通貨は登録せず、失敗の一覧を出す(手入力で補える)。
- 取得はクライアントから行い、送るのは通貨コードだけ(`https`)。取得元は設定(`info_app.settings` の `exchange`)に持つ。無料で認証が要らないサービスの条件(対応する通貨・利用の制限)は、実装の前に確認する。
