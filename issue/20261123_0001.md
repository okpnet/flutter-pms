## E. 監査の計画の登録(着手)
画面 `/quality/audit-plan`(メニュー「監査計画の登録」。品質管理のグループ)。1 つの画面で、監査と、チーム・監査員・実施(予定日時)の行を登録する。
1.  入力: 監査の題名(ラベル)・詳細(文章)・監査標準(選択)・責任者(既定はログイン中の担当者)・対象の部署と利害関係者(任意)。行(1 行以上): チーム名・監査員(担当者を複数選択)・予定日時・終了予定日時。1 行 = チーム 1 つ + 監査員 + 監査実施詳細 1 件(名称は題名 + チーム名)。
1.  DB: **関数 `audit_plan_register`(提案)**。1 回の呼び出し = 1 トランザクション(監査・チーム・監査員・監査実施詳細・ラベル・文章の登録は、複数の表にまたがるため。方針)。引数: 題名・詳細(言語別の JSON)・監査標準 ID・責任者・部署・利害関係者・行の配列(`jsonb`: チーム名・監査員の担当者 ID の配列・予定日時・終了予定日時)。戻り値は監査。errcode: `OPR00` 担当者が無い / `AUD02` 監査標準が無い / `AUD08` 行が無い・監査員が無い / `AUD09` 予定日時の前後が逆。監査標準の履歴 ID・担当者の履歴 ID は関数が引く。管理者または品質の権限だけが登録できる(権限の決め方は未決。いまは一般ユーザーも可)。
1.  画面の取得元は `IAuditPlanGateway`(メモリ上 + GraphQL 版)。GraphQL 版の登録は、関数の導入後に実装する(それまで `UnsupportedError`)。選択肢(監査標準・担当者)の読み込みは、いま実装する。
