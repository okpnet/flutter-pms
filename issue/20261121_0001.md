### 確認が要る点(DB 設計の解釈)
1. 「リレーションシップ先の承認結果の適用がすべて true」=文書 → `trans_approval_pattern` → `trans_preapproval`(承認ごと) → `trans_approved.approved` と読んだ。**承認前の行ごとに、承認結果の行があり、すべて `approved = true`** のとき公開。承認結果の行がまだ無い承認前の行があれば、未承認(公開しない)。
1. 却下・差し戻しは `approved = false` と `status`(jsonb)で表すが、`status` の中身の決まりが無い。判定は `approved` の boolean だけにし(コード値で判定しない。R1)、却下かどうかの表示文は、ビューの 1 か所で定義する。
1. 「承認パターンマスタの該当者」=`mstr_approval` の(部署 + 役職)に、担当者(`info_staff`)が当てはまる人。担当者と部署・役職の対応(`info_staff` の列か、割当の表)を、実装時に確認する。

## 3. 提案

### 3-1. 公開の判定と閲覧の範囲(DB のビュー。判定は 1 か所)
1. ビュー `v_document_publication`(文書 1 行): `mstr_document_id`・`trans_approval_pattern_id`・`total_count`(承認前の件数)・`approved_count`・`published`(**すべて承認適用済み**。件数 0 は未公開=承認なしの文書は公開するかを決める(下の判断 D1))・`pending`(承認待ちがある)・`approved_at`(最後の承認の日時)・`approved_staff_id` ほか。画面・PDF・アプリごとに判定を持たない。
1. ビュー `v_document_approval_stamp`(承認ごとに 1 行): 文書・段(`mstr_approval` の名称・順位・部署・役職)・`approved`・承認者(氏名・履歴 ID)・`approved_at`・期限・備考。スタンプの表示項目は、この**ビューの列**(DB 列)から選ぶ。
1. 閲覧の範囲は、DB の権限(PostGraphile の JWT のロール + RLS または関数)で守る。クライアントで隠さない。
    1. 公開(`published = true`): 全員が中身を読める。
    1. 非公開: 該当者(`mstr_approval` に当てはまる担当者)と、管理者だけが中身を読める。それ以外には、行はあっても中身(`mstr_document_content.contents`・ファイル)を返さない。**画面で隠すだけにしない**(API で読めてしまうため)。
    1. 該当者・管理者が非公開の文書を開くと、「承認待ち」の表示(帯 + スタンプ「承認待ち」)を必ず出す。
1. 承認の操作は DB 関数 `document_approve`(引数: 承認前の ID・適用・備考。担当者は JWT の `staff_id`)。追記のみ(記録を書き換えない)。承認できるのは該当者だけ(`OPR` 系の errcode)。1 回の呼び出し = 1 トランザクション(`~PageCall`)。

### 3-2. スタンプ(画面と PDF の共通の部品)
1. **ルートだけ**: 承認結果(スタンプ)は、文書のルート(最上位の文書・または文書の最初のページ)にだけ出す。子の文書・ページには出さない(各ページの隅に「承認済み」の小さな文字だけ出す案は D3)。
1. 「承認(Approval)」のスタンプ: 承認適用済み = 「承認 / Approval」、承認待ち = 「承認待ち / Pending」(ビューで 1 か所の定義。R2)。承認が複数段なら、段ごとに並べるか、最終承認のスタンプ 1 つにまとめるかを設定で選べる。
1. 設定(`StampStyle`。JSON で保存・読み込み。バージョン付き):
    | 項目 | 内容 |
    |---|---|
    | 位置 | 基準(右上・右下・左上・左下・中央)+ オフセット(mm)・ページ(先頭だけ・全ページ) |
    | すかし(透明度) | 0〜1。文字・枠・塗りの色は別に持つ |
    | 形・大きさ | 丸・角丸の四角・二重の枠・横長の日付印。幅・高さ(mm)・回転(度) |
    | 表示項目 | ビューの列名の並び(承認ラベル・段の名称・承認者の氏名・承認日時・版コード・管理番号 …)。項目ごとの行の位置・文字の大きさ |
    | 文字列の書式 | 日時の書式(例 `yyyy/MM/dd`・`yyyy年M月d日 HH:mm`・和暦)、ラベルの言語、氏名の書式(姓名・略称)、テンプレート(例 `{approved_at:yyyy/MM/dd}\n{staff_name}`) |
    | 段の扱い | 段ごとに並べる / 最終承認のみ / 承認待ちのときの見た目(破線・灰色) |
1. 設定の保存先: 当面は設定(`StampStyle` の JSON)を `info_` 系の設定、またはアプリの設定(`settings_keeper`)に置く。複数の様式(会社の標準・文書の階層ごと)が要るなら、DB のマスタ `mstr_approval_stamp`(承認パターンにひも付く。JSON 1 列 + 名称。履歴付き)にする(判断 D2)。変更できる人は管理者だけ。
1. 部品の作り: 1 つの描画の定義から、画面(Flutter の `CustomPainter`)と PDF(`pdf` パッケージの `PdfGraphics`)の両方を描く(同じ見た目にするため、図形・文字の配置の計算は純 Dart にして共有する)。設定の画面は、プレビュー(文書の見本の上に重ねる)付きで、位置のドラッグ・透明度のスライダー・項目の並べ替え・書式の入力。

### 6-1. スタンプの設定の置き場所(確認)
1. 承認パターンの `status` は実行の側(文書ごと)にあるため、様式を入れると文書ごとの複製になり、様式を直しても既存の文書に反映されない。実行の状態(`status`)と様式は別にする。
1. 提案: マスタ `mstr_approval_pattern` に JSONB 列(例 `stamp_style`)を足す(追加のみ・既定 NULL。破壊的ではない)。承認パターンごとの様式。NULL のときは 6-2 の既定を使う。

### 6-2. アプリの設定(裏設定を含む)を DB に置く案: `info_app` の JSONB 列
`info_app`(アプリ情報。アクセス制御は固定の 1 件を名前で引く)に `settings jsonb` を足す案は妥当。置き場として次の理由で採る。
1. `info_app` は既にアプリの識別の単位で、`AccessControlClient` が名前で引く経路がある。履歴・更新者・`remove`・`revision` の仕組みに乗る。
1. 追加列(NULL 許容)なので、既存の読み書きは壊れない(破壊的ではない。PERO・06 の再出力と、`access_control_model` の再生成だけ)。
制約と運用:
1. **接続先・ログイン入口・秘密情報は DB に置けない**(接続する前に要る。裏設定 `backstage` に残す)。DB の設定は「接続したあとで効く設定」(スタンプの既定・表示の既定・機能の有効/無効など)だけ。
1. 読み取りは一般ユーザー、書き込みは管理者だけ(DB の権限か、設定を書く関数)。
1. 優先順位: `backstage` の `defaults` < DB(`info_app.settings`) < 端末のローカル設定(`settings_keeper`)。端末が優先するのは表示の好みだけ(様式のような全体の設定は DB が優先)。
1. 形は `{ "version": 1, "stamp": {...}, ... }` の名前空間つき(機能ごとのキー)。読むときは未知のキーを無視し、不正なら既定に戻してログに残す。
1. 取得は起動後・ログイン後(JWT が要る)。取れないとき(メンテナンス・未ログイン)は既定で動く。
1. 保存先の候補だった PocketBase は、ログイン前に読めるが、DB の担当者・履歴と別管理になる。ログイン前に要る設定がある場合だけ別途検討する(今回は無し)。

## 9. 追加の指示: PDF(Markdown → PDF)のテーマ・ヘッダ・フッタの設定(2026-11-21)
指示: PDF にするときのテーマ(文字の大きさ・色)の JSON も `info_app.settings` に足す。テーマには変数が要る(例: ページ)。固定の文字と変数を混ぜたヘッダ・フッタを設定できるようにする。

### 実施(PERO・06。列は増やさず、`info_app.settings` の標準値(列の既定値)に `pdf` を足した)
`settings.pdf` の構成(`version` は設定全体で 1):
| キー | 内容 |
|---|---|
| `page` | 用紙 `size`(A4 など)・向き `orientation`・余白 `marginMm`(上右下左) |
| `theme.vars` | テーマの変数(`accent`・`muted`・`line`)。色は `"#RRGGBB"` か `"$変数名"` で書く。変数を 1 か所直すと全体の色が変わる |
| `theme.font` | `family`・`monoFamily`(等幅)・`baseSize`・`lineHeight` |
| `theme.colors` | 本文・見出し・リンク・引用・コードの背景・表の罫線・表の見出しの背景・未作成リンク |
| `theme.headings` | `h1`〜`h3` ごとに文字の大きさ・太字・色(null は見出しの色)・前後の余白(mm)・`pageBreakBefore`(h1 は章ごとに改ページ) |
| `theme.paragraph`・`code`・`table` | 段落の余白・コードの大きさ・表の罫線の太さ・セルの余白・見出し行の太字 |
| `header`・`footer` | `enabled`・`heightMm`・`size`・`color`・`border`(線)・`firstPage`(`same` / `none`)・`left`・`center`・`right`(固定の文字と変数を混ぜた書式) |
| `custom` | 利用者が足す変数(`{var.名前}` で使う。例 `company`) |

**書式の文法**(ヘッダ・フッタの `left`・`center`・`right`): 固定の文字の中に `{変数}` または `{変数:書式}` を書く。波括弧そのものは `{{`・`}}`。未知の変数は空にして、ログに残す(PDF の出力は失敗させない)。
| 変数 | 内容 |
|---|---|
| `page`・`pages` | 今のページ・全ページ数 |
| `title`・`chapter` | 文書(ページ)の名前・今の章(最後に出た h1) |
| `controlNumber`・`versionCode`・`revision` | 文書の管理番号・版コード・改訂(`v_document_publication`・文書の列) |
| `statusLabel` | 承認・承認待ち(`v_document_publication.stamp_label_ja/en`。文字は DB のビューで 1 か所) |
| `approvedAt:書式`・`approvedBy` | 最後の承認の日時・承認者(`v_document_publication`) |
| `printedAt:書式`・`printedBy` | 出力した日時・出力した人 |
| `var.名前` | `custom` の値 |
日時の書式は `yyyy/MM/dd`・`yyyy年M月d日 HH:mm` など(スタンプの書式と同じ部品を使う。`approval_stamp` の書式)。
